# 回忆录技术探索方案评估 5.0：复核与修订

## 一、评估范围

本报告复核以下内容：

- `回忆录技术探索/00-README.md` 至 `15-业务Agent接入规范.md`，共 16 份文档。
- `OpenMAIC项目技术栈/PROJECT_ANALYSIS.md` 中与契约分层、Stage/Scene/Action、生成调度、provider 路由、Agent Runtime、持久化、健康检查和安全边界相关的设计。
- 上一轮评估提出的 `dispatch_state` 实体归属、held 超时默认值和工具签名请求头问题。

评估区分三类结论：已验证正确、问题成立但建议需修正、证据不足的概括性判断。

## 二、原评估结论核验

| 原评估意见 | 核验结果 | 说明 |
|---|---|---|
| `dispatch_state` 已从 AgentDefinition 移到 AgentRun | 正确 | [09-公共AgentRuntime架构](../回忆录技术探索/09-公共AgentRuntime架构.md) 将字段放在 AgentRun；[14-AgentRuntime运行机制](../回忆录技术探索/14-AgentRuntime运行机制.md) 定义 held/queued/claimed/finished、lease 回收和 retry 转换规则。 |

| 建议新增 `held_run_timeout_seconds` | 不采用该命名 | 新增第二个名称会造成配置漂移。统一使用 AgentPackage 已采用的 `held_ttl_seconds`。 |

| 新机制没有引入任何矛盾 | 方向正确，原证据不足 | 原报告只说明抽查 06/09/13/14，不能据此代表全部 16 份文档。本次改为全目录契约矩阵、术语扫描和结构验证。 |

原报告中的“其余两项”只列出一项，属于表述错误，本版已删除该说法。

## 三、本次修订

### 3.1 运行时间参数统一

[13-观测评测与运行治理](../回忆录技术探索/13-观测评测与运行治理.md) 的默认参数表已与 15 号 `agent.yaml` 对齐：

| 参数 | 默认值 | 语义 |
|---|---:|---|
| `max_run_seconds` | 300 | planning/running/evaluating 的活跃执行预算 |
| `held_ttl_seconds` | 600 | held run 等待 start 的最长时间 |
| `queue_ttl_seconds` | 900 | queued 等待调度的最长时间 |
| `approval_ttl_seconds` | 86400 | waiting_human 默认等待时间 |
| `max_wall_clock_seconds` | 172800 | run 从创建到终止的最终存续上限 |

本次同时修正了原报告未指出的两点：

- 13 号文档原来的 `queue_timeout_seconds/approval_timeout_seconds` 与 15 号文档 `queue_ttl_seconds/approval_ttl_seconds` 命名不一致。
- 13 号文档缺少已经在 09/14/15 中定义的最终 wall-clock deadline 默认值。

### 3.2 工具签名请求头统一

[15-业务Agent接入规范](../回忆录技术探索/15-业务Agent接入规范.md) 的工具请求头清单已补充 `X-Agent-Key-Id`，与 [10-Agent工具协议与MCP适配](../回忆录技术探索/10-Agent工具协议与MCP适配.md) 一致。

第一版固定使用 HMAC-SHA256，不新增未定义的签名版本 header。未来增加签名算法时，需要同时冻结 header、canonical payload、允许算法注册表和降级策略，不能让调用方自由声明算法。

## 四、全量复核结论

当前方案已经覆盖：

- OpenMAIC 的契约层与业务层分离、两阶段生成、Scene/Action 播放、媒体降级和模型输出后处理思想。
- 回忆录的 snapshot、baseline revision 0、完整作品原子发布、`published_revision` 和 `generation_epoch` 业务 fencing。
- 公共 AgentRuntime 的 package 生命周期、run/dispatch 状态机、lease/fencing、幂等、checkpoint、outbox/dead letter、背压和对账恢复。
- `privacy_version` 删除写屏障、`authorization_version` 运行中复核，以及 trusted instructions/untrusted content 隔离。
- 小程序状态轮询基线、可选 SSE、健康检查、能力发现、共享持久化和 serverless 部署边界。
- MemoirAgent 首期闭环，以及客服、订单 Agent 的后续复用边界。

本次未发现新的 P0/P1 架构缺口。上述时间值属于第一版默认配置，不代表生产 SLA；实现阶段仍需通过压测和 provider 延迟数据调整，但不需要继续修改总体架构。

## 五、最终判断

原评估对 `dispatch_state` 修复和两个文档遗漏的判断基本正确，但 held 参数命名建议会引入别名，且全量结论的证据范围不足。本次已修正技术文档和评估表述。

修订后的技术探索方案可以进入 Runtime Contract、数据库迁移、OpenAPI 和实施计划阶段。
