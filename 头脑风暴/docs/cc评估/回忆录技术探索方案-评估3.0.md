## 2. P1 级逻辑决策点（开发启动前必须拍板）

针对“重试”与“乱序保护”的边界冲突，需明确 `event_seq` 的处理策略：

*   **问题核心：** 若重试后 `event_seq` 重置为 1，将导致业务侧的乱序保护（对比 `last_event_seq`）将重试后的新状态误判为旧数据并丢弃。
*   **决策建议（任选其一，建议优先方案A）：**
    *   **方案 A（推荐）：** `event_seq` 在 `run_id` 的全生命周期内全局单调递增，重试后从当前最大值继续累加。**优点：** 现有业务侧逻辑无需修改，逻辑最简。
    *   **方案 B：** 引入 `(attempt_no, event_seq)` 复合版本号。**优点：** 记录更严谨，能区分不同重试轮次。**缺点：** 需同步更新业务侧数据库结构与比对逻辑。
*   **落地要求：** 请在文档中显式声明所选方案，并保持 `AgentRun` 与 `MemoryAgentRunRef` 的表结构定义一致。
