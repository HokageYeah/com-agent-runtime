# AI Agent 架构评估报告：实施前置清单

## 1. 总体评价
**结论：** 分层设计合理、方向正确，文档体系完整。
*   **架构边界：** 三层边界（业务系统 / 公共 Runtime / 业务 Agent）划分清晰。
*   **经验沉淀：** OpenMAIC 的经验映射扎实。
*   **路线规划：** 第一版/二期/三期的取舍克制，避免了过早平台化。
*   **现状：** 文档已具备“评审”成熟度，但若直接进入开发，下述缺口需在实施前补齐，否则将导致阻塞或后期返工。

## 2. 核心问题清单（优先级排序）

### P0：实施关键阻碍（必须补齐）
1.  **Callback 乱序与状态竞态**
    *   **问题：** 指数退避重试可能导致乱序，造成状态倒退（如 `run_succeeded` 被 `step_changed(running)` 覆盖）。
    *   **建议：** 引入 `event_seq` 或 `updated_at` 版本号机制，业务后端更新前需进行版本比对。
2.  **幂等键生命周期**
    *   **问题：** 缺乏幂等键的存储者、TTL 和冲突处理逻辑定义。
    *   **建议：** 明确 `Idempotency-Key` 的存储位置、过期策略及重复插入时的响应行为（返回缓存结果或报错）。
3.  **跨库一致性/补偿机制**
    *   **问题：** Runtime 库与业务库的异步操作缺乏事务对账。
    *   **建议：** 实施调用后的业务侧写库重试补偿，或采用“先落库为 Pending -> 后异步绑定 RunID”的模式。
4.  **签名机制细节**
    *   **问题：** `X-Agent-Signature` 仅有定义，缺乏算法实现（HMAC-SHA256）、密钥分发方式及时间戳容忍度。

### P1：执行效率与风险控制
5.  **PolicyEngine 默认硬限制**
    *   **问题：** 硬限制字段缺失默认值。
    *   **建议：** 定义 `max_step=15`、`max_model_calls=8`、`max_tool_calls=20` 等通用默认值，避免配置发散。
6.  **Model Policy 映射表**
    *   **问题：** 策略名（如 `reasoning`, `balanced` 等）与实际 Provider/Model 的绑定关系未定义。
    *   **建议：** 补充一份最小化的模型映射配置文件。
7.  **双重脱敏边界划分**
    *   **问题：** 业务侧脱敏与 `sanitize_materials` 职责交叉。
    *   **建议：** 业务侧负责强规则（手机号/OpenID），Agent侧负责身份代称/文本截断。
8.  **SSE 实现路径**
    *   **问题：** 两种可选实现方案未定案。
    *   **建议：** 确定第一版采用“方案A”（读本地状态推送）。
9.  **重试与越权校验**
    *   **问题：** Retry 接口未校验 Owner 权限，且缺少调用上限。

### P2：架构关注项（跟踪即可）
*   **抽象验证风险：** 第一版仅接入一个 Agent，建议增加“破坏性重构窗口”声明。
*   **技术栈异构成本：** 针对 TS (Runtime) 与 Python (Business) 的双栈维护、CI/CD 整合进行风险评估。
*   **隐私边界：** 需明确列表页的“昵称/头像/摘要”是否在解锁前即展示，评估隐私风险。
