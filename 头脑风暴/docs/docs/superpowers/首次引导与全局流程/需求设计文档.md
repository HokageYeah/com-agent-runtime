# 首次引导与全局流程需求设计文档

> **模块定位：** 负责定义用户首次进入产品时的引导链路，以及未绑定态、已绑定态之间的全局状态切换。
> **上级入口：** [情侣日记总文档](../../2026-06-11-情侣日记小程序-需求设计总文档.md)

---

## 一、模块目标与边界

### 1.1 模块目标

- 明确用户从打开小程序到进入核心功能的全路径
- 定义不同全局状态下应该看到什么页面
- 让跨模块跳转和页面门禁保持一致

### 1.2 模块边界

- 本模块只描述全局流程和页面门禁
- 单模块业务规则仍以各子模块文档为准

---

## 二、角色与前置条件

### 2.1 参与角色

- 新用户：首次进入产品的人
- 老用户：已有账号、可能已绑定或已解绑的人
- 系统：判断当前用户所处状态并决定路由

### 2.2 前置条件

- 用户已打开小程序
- 系统可以判断其登录、绑定、回忆录等状态

---

## 三、页面与入口

| 页面 | 触发条件 | 作用 |
|---|---|---|
| 登录页 | 未登录 | 建立身份 |
| 角色选择页 | 已登录未选角色 | 补足情侣空间角色信息 |
| 等待绑定页 | 已登录已选角色但未绑定 | 发起或接受绑定 |
| 日记首页 | 已绑定 | 进入核心使用态 |
| 我的页 | 任意有效用户态 | 查看个人信息和入口汇总 |

---

## 四、核心流程

### 4.1 首次使用流程

```text
打开小程序
  -> 微信登录
  -> 选择角色标签
  -> 进入等待绑定页
  -> 发起邀请或输入绑定码
  -> 绑定成功
  -> 进入日记首页
```

### 4.2 已绑定用户全局流程

```text
进入小程序
  -> 直接进入日记首页
  -> 可在日记 / 赌局 / 我的之间切换
  -> 从我的进入回忆录、设置、解绑、通知等页面
```

### 4.3 解绑后流程

```text
解除情侣关系
  -> 当前共享功能关闭
  -> 用户回到未绑定态或个人态
  -> 可进入回忆录查看归档
  -> 冷却结束后可重新绑定
```

---

## 五、状态流转

### 5.1 全局用户状态

```text
未登录
  -> 已登录未选角色
  -> 已登录未绑定
  -> 已绑定
  -> 已解绑
  -> 拉黑冷却中
  -> 可重新绑定
```

### 5.2 页面门禁原则

| 状态 | 可进入页面 | 禁止进入页面 |
|---|---|---|
| 已登录未绑定 | 登录、绑定、我的 | 日记、赌局主功能 |
| 已绑定 | 全部核心页面 | 无 |
| 已解绑 | 我的、回忆录、重新绑定入口 | 原情侣空间业务详情 |
| 拉黑冷却中 | 我的、回忆录 | 重新绑定相关入口 |

---

## 六、字段与约束

- 全局状态判断必须优先于页面渲染
- 页面跳转必须基于当前状态做门禁控制
- 任意入口跳转到业务详情时，都需要校验当前用户是否仍有访问权限

---

## 七、异常与边界场景

- 登录态失效时，任意页面都应回退到登录流程
- 绑定关系在当前会话中被解除时，应及时退出原业务空间
- 通知跳转到已失效页面时，应提供兜底提示与返回入口

---

## 八、与其他模块的数据关系

- 登录和绑定状态定义来自 [登录与绑定](../登录与绑定/需求设计文档.md)
- 日记首页和赌局首页入口分别指向 [日记](../日记/需求设计文档.md) 与 [打赌系统](../打赌系统/需求设计文档.md)
- 解绑后的回退和归档入口依赖 [回忆录](../回忆录/需求设计文档.md)
