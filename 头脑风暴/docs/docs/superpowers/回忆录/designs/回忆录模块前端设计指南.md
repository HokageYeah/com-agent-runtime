## 二、模块角色与设计目标

### 2.1 模块角色

回忆录模块是情侣关系解除后的历史归档空间。

它在产品中的角色有三层：

- **隐私门禁**：进入模块前需要通过独立密码保护历史内容
- **多段归档**：用列表承载用户过往多段恋情回忆
- **仪式回看**：用闪回轮播承载系统整理后的美好片段

### 2.2 设计目标

- 让用户明确感受到“这是私密、安全、需要被温柔对待的历史空间”
- 让多段回忆可以被清晰浏览、置顶和删除
- 让详情页像年度账单一样有节奏地回看关键片段
- 让 LLM 在生成页面时，能够清晰分辨：
  - 密码门禁和列表页的边界
  - 列表管理动作与详情浏览动作的边界
  - 回忆闪回与普通日记/赌局详情的边界

## 三、与整体设计的关联关系

### 3.1 必须继承的全局规则

回忆录模块必须严格继承全局设计规范中的以下内容：

- 主背景使用 `#fff8f7` 或同色系柔和渐变
- 主文本使用 `#4a3a3b` 或参考代码中的 `#22191a`
- 品牌强调色使用 `#ff8fa3` / `#9b4053`
- 卡片使用大圆角，普通卡片为 `24px`，闪回主卡可使用 `32px`
- 阴影保持轻量粉调，不使用重黑阴影
- 顶部导航沿用统一 `TopAppBar` 的轻玻璃质感
- 动效以轻浮动、轻呼吸、平滑位移为主，避免强烈刺激

### 3.2 回忆录模块的局部特化

相较于“我的”页面，回忆录模块更强调私密、归档和仪式感。

它的特化重点是：

- 密码入口要有安全感，但不能做成冷硬的账户安全页
- 列表页要像“档案馆”，强调多段关系的归档与整理
- 详情页要像“年度账单 / 记忆胶片”，强调沉浸回看而非管理操作
- 删除与置顶是列表管理动作，不应抢占回忆卡片本身的情绪表达

## 四、模块页面信息架构

### 4.1 回忆录入口页结构

回忆录入口页用于承接首次设置密码和后续输入密码解锁。

页面结构建议为：

1. TopAppBar
2. 私密空间 Hero 卡片
3. 密码输入区
4. 主按钮：进入回忆录 / 设置密码
5. 低权重说明：密码用于保护历史回忆
6. 错误提示或冷却提示

### 4.2 回忆录列表页结构

回忆录列表页用于展示多段恋情回忆和列表管理动作。

页面结构固定为：

1. TopAppBar
2. 搜索输入区
3. 回忆卡片列表
4. 置顶回忆高亮卡片
5. 普通回忆卡片
6. 空状态
7. 操作菜单或底部弹层

### 4.3 回忆录详情页结构

回忆录详情页用于展示单段关系的闪回轮播。

页面结构固定为：

1. 沉浸式背景
2. 顶部进度条
3. 标题与关闭按钮
4. 横向闪回卡片容器
5. 左右切换能力
6. 底部滑动提示
7. 总结卡片与收尾动作

### 4.4 页面链路关系

```text
我的页
  -> 回忆录入口页
      -> 未设置密码：设置密码并确认
      -> 已设置密码：输入密码并校验
      -> 校验成功：进入回忆录列表页
          -> 点击某段回忆：进入回忆录详情页
          -> 点击更多：置顶 / 删除
          -> 删除确认：从当前用户列表移除
      -> 校验失败：停留入口页并提示重试
```

## 五、密码门禁设计指南

### 5.1 页面目标

密码门禁不是普通登录页，而是进入私密历史空间前的轻量确认。

它要完成三件事：

- 告诉用户“这里是受保护的回忆空间”
- 支持首次设置 4-6 位数字密码
- 支持后续输入密码后进入列表

### 5.2 视觉结构

- 顶部保留统一导航，标题为“回忆录”
- 中心使用私密空间 Hero 卡片，图形可使用心形、锁、信封、相册等柔和符号
- 密码输入区使用圆角胶囊或分格数字输入，不使用冷硬边框
- 主按钮使用品牌主色，文案根据状态切换：
  - `设置密码`
  - `进入回忆录`

### 5.3 业务逻辑要求

- 首次进入必须设置密码并二次确认
- 两次密码不一致时，输入区给出轻量错误反馈
- 后续进入必须输入密码
- 密码错误时不进入列表，显示轻提示
- 当前 MVP 不展示修改密码、忘记密码和重置密码入口

## 六、回忆录列表页设计指南

### 6.1 页面目标

列表页是回忆录模块的管理首页。

它要完成四件事：

- 展示用户所有已归档的多段回忆
- 明确哪一段回忆被置顶
- 支持进入详情闪回
- 支持置顶和删除等低频管理动作

### 6.2 视觉结构

- 顶部使用固定 `TopAppBar`，左侧返回，居中标题，右侧心形图标
- 顶部下方是圆角搜索框，提示文案为 `搜索回忆片段...`
- 回忆卡片使用白色容器、大圆角、轻粉色阴影
- 置顶卡片使用轻发光、图钉角标和更高视觉层级
- 普通卡片保持安静，避免每张卡片都高亮

### 6.3 卡片内容要求

每张回忆卡片至少包含：

- 对方头像
- 回忆标题
- 关系时间范围
- 日记数量
- 赌局或回忆瞬间数量
- 更多操作入口

置顶卡片需要额外包含：

- 置顶角标
- 更清晰的统计摘要区
- 轻微呼吸或柔和发光

### 6.4 列表业务逻辑要求

- 点击卡片主体进入回忆录详情页
- 点击更多按钮打开操作菜单
- 操作菜单至少包含：
  - `置顶这段回忆`
  - `取消置顶`
  - `删除这段回忆`
- 同一用户只能置顶一段回忆
- 删除必须二次确认
- 删除只影响当前用户列表，不自动删除对方账号里的回忆

## 七、回忆录详情页设计指南

### 7.1 页面目标

详情页不是普通内容详情页，而是沉浸式闪回页。

它要完成三件事：

- 用卡片轮播展示服务端整理的回忆片段
- 用进度条建立“正在回看一段旅程”的节奏
- 用总结卡温柔收尾，不制造分手后的情绪压力

### 7.2 视觉结构

- 背景采用柔和渐变或淡色 mesh，允许少量心形粒子
- 顶部使用分段进度条展示当前卡片位置
- 标题区展示回忆名称，如 `春日回忆录`
- 右侧关闭按钮使用半透明圆形玻璃按钮
- 主卡片居中展示，比例建议为 `9:16`
- 卡片圆角建议为 `32px`
- 底部保留低权重滑动提示

### 7.3 闪回卡片类型

服务端返回的闪回卡片可以映射为以下前端卡片类型：

| 卡片类型 | 设计重点 | 内容来源 |
|---|---|---|
| 封面卡 | 大图 + 起始时间 + 关系开场文案 | 绑定时间、封面图 |
| 统计卡 | 大数字 + 日记数 + 关键词 | 日记统计、关键词 |
| 精选瞬间卡 | 图片主体 + 短标题 | 图片日记、重点日期 |
| 赌局高光卡 | 赌局结果 + 奖励 + 兑现情况 | 已归档赌局 |
| 总结卡 | 情绪收尾 + 轻 CTA | 关系统计摘要 |

### 7.4 交互要求

- 支持左右滑动切换卡片
- 桌面或大屏可显示左右切换按钮
- 当前卡片应为清晰状态，非当前卡片可轻微缩放、降低透明度或模糊
- 进度条随卡片切换更新
- 关闭按钮返回列表页
- 总结卡可保留 `保存此回忆` 之类低频动作，但不应强推分享

## 八、双页面的共性与差异

### 8.1 共性

- 都继承暖粉色系统、圆角卡片和粉调阴影
- 都强调私密、温柔、轻仪式感
- 都避免冷硬的工具化管理界面
- 都通过轻动效表达状态，而不是强提醒

### 8.2 差异

| 维度 | 回忆录列表页 | 回忆录详情页 |
|---|---|---|
| 页面目标 | 管理多段回忆 | 沉浸回看单段回忆 |
| 视觉核心 | 回忆卡片列表 | 9:16 闪回卡片 |
| 主操作 | 进入详情 | 左右滑动 |
| 次级动作 | 置顶 / 删除 / 搜索 | 关闭 / 保存 / 分享 |
| 页面情绪 | 安静、整理、私密 | 仪式、回顾、温柔 |

## 九、组件级实现约束

### 9.1 TopAppBar

- 列表页使用固定顶部导航
- 标题为 `回忆录`
- 左侧返回按钮，右侧可放心形或设置入口
- 背景使用 `bg-surface/80` 和 `backdrop-blur-md`

### 9.2 Memory Card

- 白色卡片 + `24px` 圆角 + 粉调阴影
- 主体点击进入详情
- 更多按钮必须和主体点击区域分离，避免误触
- 置顶卡片使用图钉角标和轻发光

### 9.3 Search Input

- 使用圆角胶囊
- 左侧搜索图标
- 聚焦态使用主色柔和描边或阴影
- 不因为搜索框聚焦造成列表明显跳动

### 9.4 Flashback Card

- 使用 `9:16` 竖向卡片比例
- 当前卡片清晰，非当前卡片弱化
- 卡片类型之间可以有不同内容布局，但圆角、阴影和文字气质必须统一
- 图片卡需要使用底部渐隐或柔和遮罩保证文字可读

### 9.5 Operation Sheet

- 置顶、取消置顶、删除建议放在底部弹层或小型操作菜单中
- 删除使用低饱和危险色或文字强调，不使用刺眼红色大面积按钮
- 删除确认文案必须清楚说明作用范围

## 十、给 LLM 的页面还原要求

### 10.1 还原目标

LLM 生成回忆录模块页面时，必须同时还原以下三层内容：

- **视觉层**：暖粉背景、圆角、阴影、字体、轻动效、沉浸式闪回
- **布局层**：密码入口、列表页、详情页的页面骨架
- **业务层**：密码校验、列表排序、单个置顶、删除确认、闪回轮播

### 10.2 不允许遗漏的信息

LLM 不得遗漏：

- 首次进入设置密码
- 后续进入输入密码
- 多段回忆列表
- 同一用户只能置顶一段回忆
- 删除必须二次确认
- 详情页必须是闪回轮播，不是普通列表
- 闪回卡片由服务端整理生成

### 10.3 视觉验收检查

落地页面需要检查：

- 列表页首屏是否能看到至少一张回忆卡片，不能只剩顶部和搜索框
- 置顶卡片和普通卡片是否有清晰但不过度的层级差异
- 详情页主卡片是否在移动端完整可见
- 详情页文字是否没有压到图片主体或页面边缘
- 进度条、关闭按钮和滑动提示是否不遮挡主卡片内容
