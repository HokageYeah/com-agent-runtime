## 二、页面角色与设计目标

### 2.1 页面角色

回忆录列表页是用户进入回忆录模块后的第一个正式内容页，负责展示多段已归档关系，并承接进入详情、置顶、删除等管理动作。

### 2.2 设计目标

- 让用户一眼看懂“这里有多段回忆”
- 让置顶回忆拥有更高优先级，但不破坏整体安静感
- 让删除等敏感操作藏在更多菜单中，降低误触
- 让搜索成为辅助能力，不抢夺列表主层级

---

## 三、页面信息架构

页面结构固定为：

1. TopAppBar
2. 搜索输入区
3. 回忆卡片列表
4. 置顶卡片
5. 普通卡片
6. 更多操作菜单
7. 删除二次确认弹层
8. 空状态

```text
TopAppBar
  -> 搜索回忆片段
  -> 置顶回忆卡片
  -> 普通回忆卡片列表
  -> 更多菜单
      -> 置顶 / 取消置顶
      -> 删除
  -> 删除二次确认
```

## 四、视觉设计规则

### 4.1 背景与导航

- 页面背景使用 `#fff8f7` 或浅粉动态渐变。
- 顶部导航固定在顶部，使用半透明背景和轻微阴影。
- 标题为 `回忆录`，颜色使用品牌深粉。
- 左侧返回按钮和右侧心形按钮使用图标按钮，不使用文字按钮。

### 4.2 搜索区

- 搜索框使用胶囊形态，背景为淡粉或浅灰粉。
- 左侧固定搜索图标。
- placeholder 使用 `搜索回忆片段...`。
- 聚焦态使用主色柔和描边或轻阴影。
- 搜索区下方需要保留足够间距，让列表卡片有呼吸感。

### 4.3 回忆卡片

普通卡片视觉规则：

- 白色背景
- `24px` 圆角
- 粉调轻阴影
- 左侧头像，右侧文本内容
- 右上角更多操作按钮
- 点击卡片主体进入详情页

卡片必须展示：

- 回忆标题
- 对方头像
- 关系时间范围
- 日记数量
- 赌局数量或回忆瞬间数量

### 4.4 置顶卡片

置顶卡片需要比普通卡片更醒目，但仍然保持柔和。

置顶态要求：

- 显示图钉角标
- 使用轻微外发光或更明显的粉色阴影
- 可以展示更完整的统计摘要，如日记总数、达成赌约
- 置顶角标允许轻呼吸动效

## 五、交互规则

### 5.1 进入详情

- 点击卡片主体进入对应回忆录详情页。
- 点击更多按钮不能触发进入详情。
- 卡片按下时使用轻微缩放反馈。

### 5.2 置顶与取消置顶

```text
点击更多
  -> 打开操作菜单
  -> 点击置顶这段回忆
  -> 系统取消旧置顶
  -> 当前卡片移动到列表第一位
  -> 当前卡片展示置顶态
```

- 同一用户只能置顶一段回忆。
- 已置顶卡片的菜单中应显示 `取消置顶`。
- 取消置顶后，列表按解绑时间倒序排列。

### 5.3 删除回忆

```text
点击更多
  -> 点击删除这段回忆
  -> 展示二次确认
  -> 用户确认删除
  -> 当前卡片从列表移除
```

删除确认文案需要明确：

```text
删除后，这段回忆将不再出现在你的回忆录中。此操作不会删除对方账号中的回忆记录。
```

### 5.4 搜索

- 搜索只过滤当前用户可见的回忆列表。
- 搜索范围包括回忆标题、对方昵称、关键词、关系时间。
- 无搜索结果时展示轻量空状态，不展示错误态。

## 六、状态设计

### 6.1 有数据状态

- 优先展示置顶回忆。
- 普通回忆按解绑时间倒序排列。
- 每张卡片之间保持 `16px` 以上间距。

### 6.2 空状态

没有任何已解绑记录时，页面应展示空状态：

- 图形可使用信封、相册、心形锁等柔和符号
- 主文案建议：`还没有归档的回忆`
- 辅助文案建议：`未来每一段认真记录过的时光，都会被温柔保存`
- 不提供创建回忆按钮，因为回忆由解绑归档自动生成

### 6.3 搜索无结果

搜索无结果时，保留搜索框并展示：

- 主文案：`没有找到相关回忆`
- 辅助文案：`换一个关键词试试`

### 6.4 加载状态

- 初次进入可使用卡片骨架屏。
- 骨架屏形态需要模拟头像、标题、时间和统计区域。

## 七、组件级实现约束

### 7.1 MemoryListItem

- 接收回忆 ID、标题、头像、时间范围、统计摘要、是否置顶。
- 主体区域负责跳转详情。
- 更多按钮负责打开操作菜单。

### 7.2 PinnedBadge

- 用图钉图标表达置顶，不使用大段文字。
- 动效保持轻微呼吸，不做高频闪烁。

### 7.3 MemoryActionSheet

- 操作项顺序建议为：置顶 / 取消置顶、删除。
- 删除项视觉权重低于主操作，但需要明确。
- 删除前必须弹出确认层。

---

## 八、给 LLM 的页面还原要求

LLM 生成列表页时不得遗漏：

- TopAppBar
- 搜索输入区
- 多段回忆列表
- 置顶卡片
- 普通卡片
- 更多操作入口
- 单个置顶规则
- 删除二次确认
- 空状态

落地后需要额外检查：

- 移动端首屏是否能看到列表卡片，不能只露出顶部和搜索框。
- 置顶态是否明显但不过度。
- 更多按钮是否不会和卡片点击冲突。
- 删除确认文案是否说明作用范围。
