# 回忆录需求设计文档

> **模块定位：** 负责情侣关系解除后的多段历史数据归档、受保护访问与闪回式回看。
> **上级入口：** [情侣日记总文档](../../2026-06-11-情侣日记小程序-需求设计总文档.md)

---

## 一、模块目标与边界

### 1.1 模块目标

- 在每段情侣关系解除后，独立保留该段关系下的共同记录
- 支持用户在一个回忆录列表中查看多段恋情回忆
- 通过独立密码保护所有历史回忆
- 以“记忆闪回轮播”的方式回看由系统整理后的美好片段

### 1.2 模块边界

- 本模块只负责归档、解锁、回忆列表、列表管理和闪回浏览规则
- 回忆录内容来自解绑前的日记与赌局，当前版本不支持用户在回忆录内新增内容
- 回忆详情不直接还原完整日记/赌局操作页，只展示服务端整理后的纪念卡片
- 密码与隐私要求同时受 [设置与安全](../设置与安全/需求设计文档.md) 约束
- 当前 MVP 暂不设计修改密码与忘记密码重置流程，仅预留后续能力入口

---

## 二、角色与前置条件

### 2.1 参与角色

- 当前用户：回忆录的访问者，可解锁、浏览、删除和置顶自己的回忆列表
- 系统：负责归档生成、密码校验、回忆摘要生成、闪回卡片整理和列表排序

### 2.2 前置条件

- 用户曾经存在至少一段已解除的情侣关系
- 已解除关系下存在可归档的数据，或至少存在绑定与解绑时间等基础关系信息
- 用户已设置回忆录密码，或首次进入时完成设置

---

## 三、页面与入口

| 页面 | 入口 | 作用 |
|---|---|---|
| 回忆录入口页 | 我的页 | 首次设置密码或输入密码解锁 |
| 回忆录列表页 | 验证密码后 | 查看多段恋情回忆，支持置顶和删除 |
| 回忆录详情页 | 点击某段回忆 | 以闪回轮播查看该段关系的系统整理内容 |

### 3.1 回忆录列表页展示规则

- 列表中的每一项代表一段已经解除的情侣关系。
- “一段关系”必须按稳定双人空间 ID `space_id` + 绑定段号 `relationship_segment_no` 定义；同一对用户多次分合会生成多段回忆，不合并成一段。
- 每段回忆必须展示对方昵称、关系时间范围、共同记录摘要和封面信息。
- 用户可能存在多段历史关系，列表必须支持多条回忆记录，不允许只展示最近一段。
- 列表默认排序为：置顶回忆优先，其余按解绑时间倒序排列。
- 同一用户只能置顶一段回忆，新的置顶会自动取消旧的置顶状态。
- 用户可以删除指定回忆，删除前必须二次确认。

### 3.2 回忆录详情页展示规则

- 详情页以“记忆闪回轮播图”为核心形态，不采用普通列表作为主视图。
- 闪回内容由服务端基于该段关系下的日记、赌局、绑定时间、解绑时间和统计信息自动整理生成。
- 展示效果参考“年度账单”类体验：一张卡片承载一个片段，通过左右滑动或自动播放形成回顾节奏。
- 当前版本只做回看，不提供编辑、评论、重新发布、再次发起赌局等操作。

## 四、核心流程

### 4.1 回忆录生成流程

```text
情侣关系解除
  -> 系统读取本次关系的 space_id 与 relationship_segment_no
  -> 系统汇总该稳定双人空间下当前绑定段号的日记与赌局
  -> 生成一条独立 memory 归档记录
  -> 写入绑定时间、解绑时间、对方信息、绑定段号和统计摘要
  -> 服务端生成闪回卡片数据
  -> 用户后续可在回忆录列表中访问该段回忆
```

回忆录只归档“某个稳定双人空间下的某一段绑定关系”。同一对用户解除后又重新绑定，会进入同一个稳定双人空间的新绑定段；新段结束时再生成新的回忆录记录，不能把多段数据混成一条回忆。

### 4.2 首次设置密码流程

```text
用户首次进入回忆录
  -> 系统提示设置独立密码
  -> 用户输入 4-6 位数字
  -> 用户再次输入确认密码
  -> 系统校验两次输入一致
  -> 系统保存密码哈希
  -> 设置完成后进入回忆录列表
```

### 4.3 解锁访问流程

```text
用户进入回忆录
  -> 输入密码
  -> 系统校验
  -> 校验成功则展示回忆录列表
  -> 校验失败则提示重试
```

### 4.4 置顶回忆流程

```text
用户在回忆录列表选择某段回忆
  -> 点击置顶
  -> 系统取消该用户已有置顶回忆
  -> 将当前回忆标记为置顶
  -> 列表刷新，当前回忆展示在第一位
```

### 4.5 删除回忆流程

```text
用户在回忆录列表选择某段回忆
  -> 点击删除
  -> 系统展示二次确认
  -> 用户确认删除
  -> 系统将该回忆从当前用户列表移除
  -> 若删除的是置顶回忆，则同步清除置顶状态
```

### 4.6 闪回详情浏览流程

```text
用户点击某段回忆
  -> 进入回忆详情页
  -> 系统返回该 memory 的闪回卡片集合
  -> 默认从第一张封面卡片开始展示
  -> 用户左右滑动或点击下一张浏览
  -> 最后一张展示该段关系的总结卡片
```

### 4.6.1 闪回轮播内容示意

```text
封面卡片
  -> 我们从 2025年3月14日 开始记录
  -> 这一段回忆持续了 286 天
  -> 我们一共写下 124 篇日记
  -> 最常出现的关键词：火锅、晚安、散步
  -> 那天你们都记录了同一件小事
  -> 最热闹的一场打赌：谁会先睡着
  -> 我们完成了 18 个赌约，兑现率 94%
  -> 总结卡片：谢谢你们认真记录过这一段时光
```

### 4.6.2 闪回卡片生成规则

- 服务端负责整理和生成闪回卡片，前端只负责展示服务端返回的卡片集合。
- 卡片来源优先级为：重点日期、双方同日记录、图片日记、高互动赌局、待兑现/已完成赌局、关系统计摘要。
- 卡片文案必须温和克制，避免评价双方关系好坏，避免使用刺激分手情绪的表述。
- 若某段关系数据较少，仍需生成封面卡片、基础统计卡片和总结卡片。
- 若日记或赌局内容已被正式删除，不再进入闪回卡片。

## 五、状态流转

### 5.1 回忆录访问状态

```text
未设置密码
  -> 设置密码中
  -> 已设置密码
  -> 待解锁
  -> 已解锁
```

### 5.2 归档生命周期

```text
情侣关系有效
  -> 关系解除
  -> 数据归档生成
  -> 闪回卡片生成
  -> 用户可解锁查看
  -> 用户删除后不再展示
```

### 5.3 列表管理状态

```text
普通展示
  -> 已置顶
  -> 取消置顶
  -> 已删除
```

## 六、字段与约束

### 6.1 回忆录字段

| 字段 | 说明 | 约束 |
|---|---|---|
| 回忆 ID | 单段回忆唯一标识 | 必填 |
| 稳定双人空间 ID `space_id` | 该回忆来源的长期情侣空间 | 必填；同一对用户多次绑定时保持一致 |
| 绑定关系 ID `relationship_id` | 触发该段回忆生成的具体关系记录 | 必填；用于追踪绑定与解绑时间 |
| 绑定段号 `relationship_segment_no` | 该回忆属于稳定空间下第几段绑定 | 必填；与稳定双人空间 ID 共同定义一段回忆 |
| 当前用户 ID | 回忆所属访问者 | 必填 |
| 对方用户 ID | 该段关系中的另一方 | 必填 |
| 对方昵称 | 用于列表展示 | 必填 |
| 对方头像 | 用于列表封面或摘要 | 可选 |
| 回忆标题 | 列表展示标题 | 系统生成，可后续预留编辑 |
| 封面图 | 列表封面 | 优先取图片日记，否则使用系统默认封面 |
| 绑定时间 | 关系开始时间 | 必填 |
| 解绑时间 | 关系结束时间 | 必填 |
| 共同记录数 | 日记总数 | 自动统计，仅统计当前绑定段号 |
| 打赌次数 | 赌局总数 | 自动统计，仅统计当前绑定段号 |
| 兑现率 | 已完成赌局占比 | 自动统计，仅统计当前绑定段号；无赌局时不展示 |
| 是否置顶 | 当前用户是否置顶该回忆 | 同一用户只能有一个 true |
| 删除状态 | 当前用户是否已删除 | 删除后不再出现在列表 |
| 闪回卡片集合 | 详情页轮播内容 | 服务端生成 |

### 6.2 密码规则

- 密码为 4-6 位数字
- 首次进入回忆录时必须先设置密码
- 每次重新进入回忆录入口都要输入密码
- 密码必须以哈希形式存储
- 当前 MVP 不设计修改密码、忘记密码和重置密码操作
- 后续如开放改密或重置能力，应放入 [设置与安全](../设置与安全/需求设计文档.md) 统一设计

### 6.3 列表操作约束

- 删除回忆必须二次确认，确认文案需要说明“删除后该段回忆将不再出现在你的回忆录中”。
- 删除操作只影响当前用户的回忆录列表，不自动删除对方账号中的独立回忆记录。
- 已删除回忆不参与置顶排序，也不能从普通列表进入详情。
- 同一用户只能置顶一段回忆，不能出现多个置顶。
- 当用户置顶新的回忆时，系统必须自动取消旧置顶，不需要用户手动取消。

### 6.4 闪回展示约束

- 详情页主形态必须是轮播闪回，不能退回普通时间线或纯列表。
- 闪回卡片应遵循整体 UI 设计规范：柔和、私密、带仪式感，避免工具化报表堆叠。
- 卡片内容以“回忆摘要 + 关键数据 + 温和文案”为主，不展示过长原文。
- 日记与赌局只作为闪回素材来源，详情页不承载原模块的编辑、删除、结算或兑现操作。
- 服务端返回空卡片时，前端展示基础封面卡片与空态总结，不显示空白轮播。

## 七、异常与边界场景

- 用户没有任何已解绑记录时，不展示空的回忆录详情，只展示空列表状态。
- 密码连续输错时，应有基础风控或冷却策略。
- 两次设置密码输入不一致时，禁止保存并提示重新输入。
- 关系解除后无历史内容时，也应保留一条基础归档摘要。
- 同一对用户多次分合时，每次解除只归档当前绑定段号的数据，不能把前一段或后一段内容混入本段回忆。
- 用户删除置顶回忆后，列表中不再存在置顶项，除非用户重新选择置顶。
- 服务端闪回卡片生成失败时，详情页应降级展示基础统计卡片。
- 已删除的日记、已删除的回忆或无权访问的历史数据不能出现在闪回卡片中。

## 八、与其他模块的数据关系

- 数据来源于 [日记](../日记/需求设计文档.md) 与 [打赌系统](../打赌系统/需求设计文档.md)
- 触发条件、稳定双人空间 ID `space_id`、绑定关系 ID `relationship_id` 和绑定段号 `relationship_segment_no` 来自 [登录与绑定](../登录与绑定/需求设计文档.md) 的解绑结果
- 密码与隐私要求来自 [设置与安全](../设置与安全/需求设计文档.md)
- 闪回内容生成需要读取同一 `space_id + relationship_segment_no` 下的日记、赌局和情侣关系基础信息，但不反向修改原模块数据
- 同一对用户重新绑定后，原稳定双人空间会继续用于日记、赌局和情侣空间恢复展示；回忆录仍按各自绑定段号保持多段独立记录
