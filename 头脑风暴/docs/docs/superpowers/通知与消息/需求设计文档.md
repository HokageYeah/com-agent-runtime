# 通知与消息需求设计文档

> **模块定位：** 负责横向承接系统通知、站内消息和关键状态提醒。
> **上级入口：** [情侣日记总文档](../../2026-06-11-情侣日记小程序-需求设计总文档.md)

---

## 一、模块目标与边界

### 1.1 模块目标

- 为跨模块动作提供统一通知出口
- 让用户及时感知绑定、删除申请、赌局变化等状态
- 区分站内消息与外部推送的职责

### 1.2 模块边界

- 本模块只定义通知类型、触发规则、已读状态和展示方式
- 不负责决定业务状态本身，状态主定义仍在对应业务模块中

---

## 二、角色与前置条件

### 2.1 参与角色

- 接收方用户：阅读通知的人
- 触发方用户：发起业务动作的人
- 系统：生成消息、发送站内提醒、触发微信订阅消息

### 2.2 前置条件

- 用户处于已登录状态
- 需要有业务事件触发通知
- 使用外部推送时，用户需已授权微信订阅消息

---

## 三、页面与入口

| 页面 | 入口 | 作用 |
|---|---|---|
| 消息通知页 | 我的页 / 系统推送 | 查看所有通知记录 |
| 业务详情页 | 点击通知后跳转 | 处理对应业务动作 |

---

## 四、核心流程

### 4.1 通知生成流程

```text
业务模块发生关键事件
  -> 系统生成 notification
  -> 写入类型、内容、跳转目标、已读状态
  -> 站内展示
  -> 按规则决定是否触发外部推送
```

### 4.2 已读流程

```text
用户进入通知列表
  -> 系统展示消息
  -> 用户点击某条消息
  -> 系统标记已读
  -> 跳转到对应业务详情
```

---

## 五、状态流转

### 5.1 通知状态

```text
已生成
  -> 未读
  -> 已读
  -> 已跳转处理
```

---

## 六、字段与约束

### 6.1 通知字段

| 字段 | 说明 | 约束 |
|---|---|---|
| 类型 | 通知类别 | 必填 |
| 内容 | 展示文案 | 必填，保持温暖语气 |
| 接收人 | 目标用户 | 必填 |
| 跳转目标 | 对应业务页面 | 可选但建议明确 |
| 已读状态 | 是否已读 | 必填 |
| 触发时间 | 生成时间 | 必填 |

### 6.2 通知类型

- 绑定邀请通知
- 绑定成功通知
- 和平解绑申请通知
- 拉黑结果通知
- 新日记提醒
- 日记删除申请通知
- 新赌注邀请通知
- 赌局待结算通知
- 赌局待兑现提醒
- 回忆录相关密码或安全提醒

---

## 七、异常与边界场景

- 用户关闭通知开关后，站内消息仍需保留
- 外部推送失败时，不影响站内消息生成
- 同一时间多个待兑现提醒可合并展示
- 跳转目标已失效时，应展示兜底提示页
