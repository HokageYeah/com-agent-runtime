# “关系管理”模块设计目录

本目录用于存放“登录与绑定”模块下的关系管理设计说明，覆盖已绑定后的管理入口、和平解绑、强制拉黑、解绑待处理和拉黑冷却期状态。

阅读顺序建议：

1. 先阅读 [关系管理模块前端设计指南](./关系管理模块前端设计指南.md)
2. 再查看全局设计基线 [整体设计/前端UI设计规范与AI提示词指南](../../../整体设计/前端UI设计规范与AI提示词指南.md)
3. 再参考现有关系设置页面 code：[我的/code/登录绑定后关系设置/code.html](../我的/code/登录绑定后关系设置/code.html)
4. 最后回到需求文档确认状态流转与接口契约：[登录与绑定需求设计文档](../../需求设计文档.md)

代码参考位置：

- 基础关系设置参考页面：[`../我的/code/登录绑定后关系设置/code.html`](../我的/code/登录绑定后关系设置/code.html)
- 基础关系设置参考设计系统：[`../我的/code/登录绑定后关系设置/DESIGN.md`](../我的/code/登录绑定后关系设置/DESIGN.md)
- 和平解绑待处理状态稿：[`code/和平解绑待处理/code.html`](./code/和平解绑待处理/code.html)
- 对方处理申请状态稿：[`code/对方处理申请/code.html`](./code/对方处理申请/code.html)
- 拉黑冷却期状态稿：[`code/拉黑冷却期/code.html`](./code/拉黑冷却期/code.html)

使用规则：

- 关系管理页只能服务已绑定、解绑申请中、拉黑冷却中三类关系状态，不承载未登录和未绑定引导。
- 和平解绑与强制拉黑是敏感操作，必须使用低权重入口、强确认弹窗和清晰后果说明。
- 拉黑操作必须和普通解绑在视觉层级、文案语气和确认成本上明显区分。
- 后续补充静态设计稿时，应放在本目录 `code/` 子目录下，并在本 README 中登记入口。
