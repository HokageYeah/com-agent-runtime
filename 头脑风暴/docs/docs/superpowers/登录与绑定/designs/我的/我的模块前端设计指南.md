## 二、页面角色与设计目标

### 2.1 页面角色

“我的”页面是用户进入个人信息、情侣关系状态、功能管理入口和敏感设置操作的总控页面。

它在产品中的角色有两层：

- **登录前**：承担情感化引导与登录转化职责
- **登录后**：承担个人中心、关系展示和功能跳转职责

### 2.2 设计目标

- 让用户一眼感受到“这是一个温柔、亲密、有仪式感的情侣空间”
- 让未登录、登录未绑定、登录已绑定三种状态有明显区别，但共享同一套视觉语言
- 让 LLM 在生成页面时，能够清晰分辨：
  - 什么是固定视觉骨架
  - 什么是状态差异
  - 什么是功能入口
  - 什么是业务逻辑占位

## 三、与整体设计的关联关系

### 3.1 必须继承的全局规则

“我的”模块必须严格继承全局设计规范中的以下内容：

- 主背景使用 `#fff8f7`
- 主要文字使用 `#4a3a3b`
- 卡片使用大圆角 `24px`
- 卡片阴影保持轻量粉调，不使用重黑阴影
- 顶部导航与底部导航沿用统一的 `TopAppBar` / `BottomNavBar`
- 所有按钮、图标、呼吸动效和轻浮动动效都要延续温柔、浪漫、亲密的气质

### 3.2 “我的”页的局部特化

相较于日记和赌局页面，“我的”页不使用中轴时间线，而采用 **中心 Hero + 下方功能卡片列表** 的布局方式。

它的特化重点是：

- 用顶部 Hero 区表达“关系状态”或“待开启状态”
- 用卡片列表表达“模块入口”与“功能可达性”
- 用底部低权重入口承接“解绑 / 拉黑”等敏感操作

## 四、页面信息架构

### 4.1 未登录态信息架构

未登录态页面结构固定为：

1. TopAppBar
2. Hero 引导区
3. 登录 / 注册主按钮
4. 锁定功能预览列表
5. 氛围海报或情绪插图区
6. BottomNavBar

### 4.2 登录未绑定态信息架构

登录未绑定态页面结构固定为：

1. TopAppBar
2. 当前用户头像 + 另一半占位头像 Hero 区
3. 立即绑定另一半主按钮
4. 登录后功能入口卡片区
5. 设置入口
6. BottomNavBar

### 4.3 登录已绑定态信息架构

登录已绑定态页面结构固定为：

1. TopAppBar
2. 双人头像 + 心形联结 Hero 区
3. 关系天数状态胶囊
4. 功能入口卡片区
5. 低权重敏感操作入口
6. BottomNavBar

### 4.4 页面切换逻辑

- 未登录态点击主按钮后，进入登录流程
- 微信登录成功但 `relationshipStatus !== "BOUND"` 时，页面进入登录未绑定态，不能误判为正式登录完成
- 绑定成功且 `relationshipStatus === "BOUND"` 时，页面进入登录已绑定态
- 登录未绑定态参考 `code/登录未绑定/code.html`
- 登录已绑定态参考 `code/登录已绑定/code.html`

## 五、未登录态设计指南

### 5.1 页面目标

未登录态不是“空页面”，而是“情绪化登录转化页面”。

它要完成三件事：

- 传递产品气质
- 告诉用户登录后会得到什么
- 把核心功能以“锁定预览”的方式提前展示出来

### 5.2 视觉结构

- 顶部保留统一导航，标题为“我的”
- Hero 区居中放置一个高识别度的情感化引导组件
- 主按钮必须是页面最强 CTA
- 锁定卡片区要体现“功能存在但暂未解锁”
- 页面底部可放情绪海报，强化产品温度

### 5.3 Hero 区设计要求

- 使用白色大圆角卡片或柔和容器
- 视觉中心是“心形 + 虚线圆环 + 微光晕”的待连接图形
- 主标题应直接表达开启关系旅程的语义
- 副标题要传递“记录两个人的每一个心动时刻”这类情绪价值

### 5.4 功能预览卡片要求

- 卡片必须显示功能名称和锁定说明
- 图标底色使用柔和粉、蓝、米黄等浅色块区分功能类别
- 右侧固定显示锁图标，表达当前不可用
- 点击时的业务提示应为：
  - “请先完成登录”
  - 或“登录后即可开启该功能”

### 5.5 未登录态业务逻辑要求

- CTA 主按钮触发登录 / 注册流程
- 锁定卡片不直接进入功能页
- 锁定卡片点击后只做轻反馈和提示，不做假跳转
- 底部导航中“我的”页签为当前激活状态

## 六、登录未绑定态设计指南

### 6.1 页面目标

登录未绑定态表示用户已经完成微信登录和角色选择，但尚未和另一半建立情侣关系。

它要完成四件事：

- 明确告诉用户“还未绑定另一半”
- 强化邀请或绑定另一半的主行动
- 展示当前用户头像和另一半占位头像，形成“等待连接”的视觉语义
- 对情侣空间等强关系功能做锁定提示，避免用户误以为已经可用

### 6.2 视觉结构

- 顶部采用半透明模糊导航栏，延续全局轻玻璃质感
- 页面视觉重点落在“当前用户头像 + 另一半占位头像”的 Hero 区
- 当前用户头像可使用拍立得/相纸感卡片，另一半位置使用虚线框、`person_add` 图标和 `虚位以待` 文案
- 中间使用轻量心形或虚线桥接，表达“待连接”
- 主按钮必须清晰表达 `立即绑定另一半`
- 情侣空间卡片需要保持锁定态，右侧显示 `绑定后开启` 或锁图标

### 6.3 Hero 区要求

- 左侧展示当前用户头像和编辑入口或资料入口
- 右侧展示另一半占位头像，不使用真实头像假数据
- 占位头像必须表达“等待 TA 加入”，不能表现为已绑定状态
- Hero 文案推荐：
  - 主标题：当前用户昵称
  - 副标题：`您还未绑定另一半，快去邀请 TA 开启双人世界吧`
- 主 CTA 推荐：`立即绑定另一半`

### 6.4 功能入口卡片要求

推荐至少包含以下入口：

- 情侣空间
- 回忆录档案
- 消息通知

其中：

- `情侣空间` 在未绑定状态必须锁定，说明为 `记录你们的甜蜜日常`，右侧提示 `绑定后开启`
- `回忆录档案` 可以展示用户已有个人日记数量，例如 `4 篇已发布的日记`
- `消息通知` 可以展示 `暂无新动态`
- 每张卡片需包含左侧图标容器、中间标题与说明、右侧状态或箭头

### 6.5 业务逻辑要求

- 点击 `立即绑定另一半` 进入绑定页
- 点击锁定的情侣空间时只提示 `绑定另一半后开启`
- 已登录未绑定状态仍不能把来源页刷新为正式可用态
- `onShow` 需要刷新关系状态，若后端返回 `BOUND`，立即切换为登录已绑定态

## 七、登录已绑定态设计指南

### 7.1 页面目标

登录已绑定态才是情侣日记的正式登录完成态，是用户的关系展示、功能入口和敏感关系管理中心。

它要完成四件事：

- 展示当前用户与另一半已经建立联结
- 表达情侣关系的温度与稳定感
- 提供情侣空间、回忆档案、消息通知等关键功能入口
- 收纳 `解除绑定 / 加入黑名单` 等低频敏感操作

### 7.2 视觉结构

- 顶部采用半透明模糊导航栏，延续全局轻玻璃质感
- 页面视觉重点必须落在“双人联结 Hero 区”
- 双方头像使用圆形头像，左右分布
- 中间使用虚线连接和心形呼吸动画，强化“双向关系”感
- 必须展示关系天数胶囊，例如 `甜蜜相守 520 天`
- 功能卡片全部进入可点击态，不再显示绑定锁定文案
- 敏感操作入口放在底部，视觉权重低于普通功能入口

### 7.3 关系联结 Hero 区要求

- 左右对称展示双方真实头像
- 中间心形图标需要轻微呼吸感
- 可增加轻纹理、柔和粒子或淡背景图案，但不能喧宾夺主
- 状态胶囊必须表达已绑定关系，例如：
  - `甜蜜相守 520 天`
  - `已守护 520 天`

### 7.4 功能入口卡片要求

推荐至少包含以下入口：

- 情侣空间
- 回忆档案 / 回忆录档案
- 消息通知

每张卡片需包含：

- 左侧功能图标容器
- 中间主标题与辅助说明
- 右侧导航箭头

### 7.5 敏感操作入口要求

- 单独放在页面底部
- 视觉权重低于普通入口
- 使用文字链接或轻按钮样式
- 文案可为：
  - `解除绑定 / 加入黑名单`
  - `管理情侣关系`

### 7.6 业务逻辑要求

- 点击功能卡片，进入对应模块页面或展示明确占位提示
- 设置按钮进入设置页
- 情侣关系区可承接未来的“查看双方资料 / 查看纪念信息”扩展能力
- 敏感操作入口进入解绑、和平解除或拉黑相关流程
- `onShow` 需要刷新关系状态，若后端返回非 `BOUND`，必须退出已绑定展示态

## 八、三态页面的共性与差异

### 8.1 共性

- 都使用统一的顶部导航和底部导航
- 都继承相同的色彩系统、字体系统和卡片系统
- 都强调情感化而非工具化
- 都保持轻盈、柔和、圆润的页面气质

### 8.2 差异

| 维度 | 未登录态 | 登录未绑定态 | 登录已绑定态 |
|---|---|---|---|
| 页面目标 | 引导登录 | 引导绑定另一半 | 管理关系与功能 |
| 视觉核心 | 待连接 Hero | 当前用户 + 另一半占位 | 双人头像心形联结 |
| 功能列表 | 锁定预览 | 部分入口可见，情侣空间锁定 | 可操作入口 |
| CTA | 登录 / 注册 | 立即绑定另一半 | 功能跳转 / 设置 / 管理 |
| 情绪表达 | 期待、邀请 | 等待、召唤、补全 | 亲密、稳定、归属 |

## 九、组件级实现约束

### 9.1 TopAppBar

- 使用半透明背景和模糊效果
- 左右两侧可放轻量图标
- 标题风格保持温柔、圆润、非工具感

### 9.2 BottomNavBar

- 必须复用全局底导样式
- “我的”页签始终高亮
- 激活态使用圆形底衬或主色容器底色

### 9.3 Hero Card

- 圆角大于普通卡片，可使用 `32px`
- 背景优先用主色浅层、粉白渐变或柔和图案底
- 可承载动效，但动效必须轻

### 9.4 Feature Card

- 白色卡片 + 24px 圆角 + 轻边框 + 柔和阴影
- 图标底色随功能分类变化，但整体仍需在暖色系统内协调
- 点击反馈为轻缩放和轻微色深变化

## 十、给 LLM 的页面还原要求

### 10.1 还原目标

让 LLM 根据资料生成页面时，必须同时还原以下三层内容：

- **视觉层**：颜色、字体、圆角、阴影、动效、组件结构
- **布局层**：未登录态、登录未绑定态、登录已绑定态的页面骨架
- **业务层**：登录按钮、功能入口、锁定状态、解绑入口等交互语义

### 10.2 不允许遗漏的信息

LLM 生成页面时，不能遗漏：

- 顶部导航
- 底部导航
- 未登录态 Hero 引导区
- 登录未绑定态的“当前用户 + 另一半占位” Hero 区
- 登录已绑定态的双人联结 Hero 区
- 功能入口卡片区
- 状态差异逻辑
- 锁定态与可用态的不同交互规则

### 10.3 业务逻辑最小要求

未登录态至少需要具备：

- 登录按钮点击事件
- 锁定卡片点击提示逻辑

登录未绑定态至少需要具备：

- 绑定另一半主按钮
- 情侣空间锁定提示
- `onShow` 刷新关系状态并在绑定后切换到已绑定态

登录已绑定态至少需要具备：

- 功能入口跳转占位
- 设置入口跳转占位
- 敏感操作入口跳转占位
