## 二、登录流程的业务定义

### 2.1 正式登录完成的判定

本产品中的“正式登录完成”不是“微信授权成功”这一刻，而是下面两个条件都满足之后：

1. 用户已完成微信登录
2. 用户已完成情侣绑定

只有在绑定成功后，才算真正进入产品可用状态。

### 2.2 页面流程规则

- 用户从任意来源页进入登录流程
- 首先进入“登录与角色选择”页
- 用户完成微信登录并选择角色标签
- 如果此时用户尚未绑定，则必须继续进入“邀请与绑定”页
- 用户在“邀请与绑定”页完成邀请码绑定或扫码绑定
- 只有绑定成功后，才回到来源页
- 回到来源页后，页面刷新为正式登录态

### 2.3 中途退出规则

- 如果用户只完成登录和角色选择，但没有完成绑定，则不视为正式登录完成
- 这种情况下，不返回来源页进入已登录态
- 前端应继续停留在绑定链路中，或在后续重新进入时优先恢复到“邀请与绑定”页

## 三、与整体设计的关联关系

### 3.1 必须继承的全局规则

登录流程必须继承全局设计规范中的这些内容：

- 主背景使用 `#fff8f7`
- 主文本使用 `#4a3a3b`
- 主要卡片与容器使用大圆角 `24px`
- 主要按钮使用柔和的胶囊形态
- 阴影保持粉调、轻量、不使用重黑阴影
- 顶部导航、玻璃模糊、轻浮动、呼吸感动效延续整体产品气质

### 3.2 登录流程的局部特化

相较于“我的”页和时间线页，登录流程页面的重点不是功能列表，而是：

- 建立用户第一印象
- 传递关系建立的仪式感
- 通过插画、角色卡、邀请码和绑定动作构建“进入情侣空间”的体验

因此登录流程应表现为：

- 更强的引导感
- 更明确的阶段推进感
- 更温柔但更清晰的主操作重心

## 四、页面信息架构

### 4.1 登录与角色选择页结构

页面结构固定为：

1. 品牌展示区
2. 角色选择区
3. 微信一键登录主按钮
4. 协议勾选与辅助说明
5. 氛围背景或装饰元素

### 4.2 邀请与绑定页结构

页面结构固定为：

1. 顶部导航栏
2. 情感插画区
3. 我的邀请码展示卡片
4. 输入绑定码卡片
5. 扫码绑定入口
6. 绑定说明信息区
7. 底部导航栏或全局底导占位

### 4.3 页面链路关系

```text
来源页
  -> 登录与角色选择页
      -> 微信登录成功
      -> 角色已选择
      -> 检查是否已绑定
          -> 已绑定：直接回来源页
          -> 未绑定：进入邀请与绑定页
              -> 绑定成功
              -> 回来源页
```

## 五、登录与角色选择页设计指南

### 5.1 页面目标

“登录与角色选择”页承担两件事：

- 建立产品的第一印象
- 完成角色确认与微信登录的第一步

这张页面必须让用户感受到：

- 产品是温柔、亲密、轻盈的
- 角色选择是一个有仪式感的动作
- 微信登录是清晰、可信任、易操作的下一步

### 5.2 视觉结构

- 顶部是品牌 Logo 与产品名称
- 中心区域是两个对称分布的角色卡片
- 底部是显著的微信一键登录按钮
- 页面背景使用柔和粉调与轻呼吸装饰

### 5.3 角色卡片要求

- 左右对称展示“他 / 她”
- 选中态必须有明显描边、高亮背景或外发光
- 卡片内部头像风格保持温柔、清爽、插画化
- 卡片下方保留“角色设定后不可更改”的低权重提示

### 5.4 主操作按钮要求

- “微信一键登录”是全页面最强 CTA
- 按钮需要是胶囊型、大尺寸、可一眼识别
- 按钮点击时要有轻缩放和阴影扩散反馈

### 5.5 登录与角色选择页业务逻辑要求

- 用户必须先选中角色，再点击微信登录
- 如果未选择角色就点击登录：
  - 角色区域需要有提示性反馈
  - 页面需要出现轻量提示文案或 Toast
- 如果未勾选协议：
  - 勾选区触发轻晃动
  - 页面提示用户先同意协议
- 微信登录成功后：
  - 写入登录态
  - 写入角色标签
  - 判断是否已绑定
  - 未绑定则跳转到“邀请与绑定”页

## 六、邀请与绑定页设计指南

### 6.1 页面目标

“邀请与绑定”页承担的是关系建立动作，不是普通表单页。

它要完成三件事：

- 告诉用户“你已进入绑定阶段”
- 让用户理解两种绑定方式：邀请码 / 扫码
- 在绑定成功后，把用户带回来源页完成正式登录闭环

### 6.2 视觉结构

- 顶部保留统一导航栏
- Hero 插画区作为视觉锚点，传达“连接、联结、同步”的主题
- 中段优先展示“我的邀请码”
- 下段提供输入绑定码和扫码入口
- 底部说明绑定成功后的收益

### 6.3 邀请码展示区要求

- 邀请码应是页面最醒目的信息之一
- 字号大、字距宽、颜色聚焦、可带轻呼吸感
- 复制按钮必须明显可点，并带即时反馈

### 6.4 输入绑定区要求

- 输入框使用柔和背景，不要工具化边框
- “立即绑定”按钮是本页主 CTA
- 扫码入口是次级 CTA，但仍需可见、易理解

### 6.5 邀请与绑定页业务逻辑要求

- 用户可通过两种方式绑定：
  - 输入另一半的邀请码
  - 扫描二维码
- 如果输入为空点击“立即绑定”：
  - 输入框触发错误提示或轻晃动
- 如果绑定失败：
  - 显示轻量错误提示
  - 仍停留当前页
- 如果绑定成功：
  - 标记用户为正式登录完成
  - 返回来源页
  - 来源页刷新为已登录态

## 七、来源页返回逻辑

### 7.1 来源页定义

来源页是用户触发登录流程时所在的页面，例如：

- “我的”页未登录态
- 某个需要权限的功能页
- 未来任何要求先登录再继续的业务页面

### 7.2 返回规则

- 进入登录流程时，前端要记录来源页
- 绑定成功后，必须回到来源页
- 回到来源页后，页面重新拉取用户状态
- 如果来源页本身依赖登录结果，则刷新成正式登录后的页面内容

### 7.3 不回退规则

- 只完成登录但未绑定时，不回来源页
- 绑定失败时，不回来源页
- 用户中途关闭流程，保留未完成状态，后续继续恢复绑定流程

## 八、双页面的共性与差异

### 8.1 共性

- 都继承全局暖粉色系统与圆角卡片体系
- 都强调轻盈、浪漫、亲密的气质
- 都通过呼吸感动效和柔和阴影传达仪式感
- 都采用清晰的单主操作逻辑，避免过载选择

### 8.2 差异

| 维度 | 登录与角色选择 | 邀请与绑定 |
|---|---|---|
| 页面目标 | 建立身份并发起登录 | 建立情侣关系并完成闭环 |
| 视觉中心 | 角色卡片 | 邀请码 / 绑定卡片 |
| 主 CTA | 微信一键登录 | 立即绑定 |
| 次级动作 | 协议确认 | 扫码绑定 / 复制邀请码 |
| 页面情绪 | 初见、信任、期待 | 仪式感、趣味、联结 |

## 九、组件级实现约束

### 9.1 品牌 Header / Logo 区

- 使用圆润的品牌容器和心形图标
- 保持居中、轻浮动和柔和阴影
- 主标题和副标题要突出“情侣日记”的陪伴感

### 9.2 Role Card

- 白色卡片 + 大圆角 + 粉调阴影
- 选中态必须明显
- 卡片点击有轻缩放反馈

### 9.3 Invite Code Card

- 邀请码必须是高强调层
- 容器可使用轻渐变、白卡片或柔和描边
- 支持复制动作反馈

### 9.4 Binding Input Card

- 输入框背景柔和
- 立即绑定按钮必须高于扫码入口
- 验证失败时优先使用轻量摇动 + 文案提示

## 十、给 LLM 的页面还原要求

### 10.1 还原目标

LLM 生成登录流程页面时，必须同时还原：

- 视觉层：颜色、圆角、阴影、字体、呼吸感、插画气质
- 布局层：两张页面的骨架与主操作层级
- 业务层：角色选择、微信登录、协议校验、绑定成功闭环、来源页返回逻辑

### 10.2 不允许遗漏的信息

LLM 不得遗漏：

- 角色选择逻辑
- 协议勾选逻辑
- 登录成功后检查绑定状态
- 未绑定跳转邀请与绑定页
- 绑定成功后回来源页
- 邀请码复制、绑定输入、扫码绑定三类动作入口

### 10.3 业务逻辑最小要求

登录与角色选择页至少需要具备：

- 角色选择状态
- 协议是否勾选状态
- 微信登录按钮事件
- 登录成功后的状态判断与跳转逻辑

邀请与绑定页至少需要具备：

- 邀请码展示与复制反馈
- 绑定码输入状态
- 绑定按钮事件
- 扫码绑定入口事件占位
- 绑定成功后回来源页逻辑
