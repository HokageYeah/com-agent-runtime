**Goal:** 完成“登录与绑定”模块中已绑定关系的和平解绑、强制拉黑、拉黑冷却期和关系状态刷新闭环。

**Architecture:** 本计划只负责冻结契约、执行顺序、联调边界和验收口径；前端页面、后端服务和数据库迁移分别进入子计划执行。和平解绑使用独立申请记录，强制拉黑使用独立冷却记录，不把两种敏感动作塞进一个关系状态字段里硬扛。

**Tech Stack:** FastAPI + MySQL + SQLAlchemy + Alembic + UniApp/Vue3/TypeScript + Pinia。

## 2. 核心原则

- 和平解绑与强制拉黑是两个不同业务动作：前者需要对方确认，后者单方立即生效。
- 和平解绑必须有独立申请记录，不能只靠 `couple_relationships.status` 存一个临时状态。
- 强制拉黑必须立即关闭当前关系，并写入双方冷却限制。
- 拉黑冷却期内，生成邀请码、预览邀请码、绑定邀请码都必须被后端拒绝。
- 前端只负责流程展示和确认成本；关系唯一性、处理权限、冷却期、过期时间以后端为准。
- 所有接口继续返回统一响应：`platform/api/data/ret/v`。
- 所有新增前后端字段、状态和接口类型必须保留中文业务注释。

## 3. 契约冻结

### 3.1 状态枚举

```text
RelationshipStatus:
  UNBOUND
  INVITING
  BOUND
  UNBIND_REQUESTED
  UNBOUND_ARCHIVED
  BLOCK_COOLDOWN

UnbindRequestStatus:
  PENDING
  ACCEPTED
  REJECTED
  CANCELLED_BY_REQUESTER
  EXPIRED
  CANCELLED_BY_BLOCK

BlockReleaseSource:
  AUTO_EXPIRED
  ADMIN_RELEASED
```

### 3.2 接口清单

| 接口 | 方法 | 责任 |
|---|---|---|
| `/api/v1/relationship/unbind-requests` | POST | 当前用户发起和平解绑申请 |
| `/api/v1/relationship/unbind-requests/current` | GET | 查询当前关系下待处理或最近一条解绑申请 |
| `/api/v1/relationship/unbind-requests/{request_id}/accept` | POST | 被申请方同意和平解绑 |
| `/api/v1/relationship/unbind-requests/{request_id}/reject` | POST | 被申请方拒绝和平解绑 |
| `/api/v1/relationship/unbind-requests/{request_id}/cancel` | POST | 发起方撤回待处理和平解绑申请 |
| `/api/v1/relationship/block` | POST | 当前用户强制拉黑对方并进入冷却期 |
| `/api/v1/relationship/me` | GET | 返回最新关系状态，需包含解绑待处理和冷却期信息 |

### 3.3 前端正式登录判定

本阶段不改变上一阶段铁律：

```ts
const formalLoggedIn = userStore.isLogin && userStore.relationshipStatus === 'BOUND';
```

如果后端返回 `UNBIND_REQUESTED`，前端可以展示“已绑定但有待处理解绑申请”的管理提示，但不能在本地伪造关系解除结果。共享业务空间能否进入，必须以后端接口返回和业务接口鉴权结果为准。

## 6. 非目标

本轮不实现：

- 微信订阅消息真实发送，只保留通知事件或后续接入点。
- 回忆录归档的具体数据搬迁逻辑，只产生“关系已解除，需要归档”的状态或事件。
- 管理后台人工解除拉黑冷却，只预留 `ADMIN_RELEASED` 枚举。
- 复杂申诉、举报、证据上传能力。
- 多段历史关系合并展示。

## 7. 风险与处理

- 和平解绑和强制拉黑都改关系状态：后端 service 必须统一收口，避免多个接口分别改关系表。
- `UNBIND_REQUESTED` 不是关系解除：前端不能看到该状态就清空关系信息。
- 拉黑冷却不能只在绑定接口校验：生成邀请码、预览邀请码、绑定邀请码都要校验。
- 回忆录归档尚未实现：本阶段只能记录归档待处理状态，不要假装数据已经搬迁完成。
- 通知模块尚未实现：接口成功不代表对方已收到真实订阅消息，联调记录必须写清楚。
