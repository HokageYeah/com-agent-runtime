# 登录与绑定稳定双人空间前端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `frontend/couple-diary-f` 中补齐关系空间上下文字段，让登录、绑定、解绑、拉黑后的前端状态能稳定消费后端返回的 `spaceId` 与 `relationshipSegmentNo`。

**Architecture:** 前端不负责计算稳定双人空间，只在类型、API 响应、Pinia Store 和页面刷新链路中保存后端返回值。页面仍按用户可感知的登录/未绑定/已绑定/冷却状态展示，不把技术段号直接产品化展示。

**Tech Stack:** UniApp、Vue 3 `<script setup>`、TypeScript、Pinia、`request<T>()`、ThorUI / XXT easycom、SCSS。

## Global Constraints

- 前端不能按双方用户 ID 推导 `spaceId`，只能使用后端返回值。
- `spaceId`、`relationshipId`、`relationshipSegmentNo` 都必须有中文字段注释，避免后续业务模块混用。
- 登录、绑定、解绑、拉黑成功后必须重新刷新 `/relationship/me` 或合并后端返回的最新关系上下文。
- 不改变用户可见主流程：普通用户仍只看到未登录、未绑定、已绑定、解绑申请中、冷却期。
- 遵守 [frontend/couple-diary-f/.claude/rules/UniApp模块化工程规范.md](../../../../../frontend/couple-diary-f/.claude/rules/UniApp模块化工程规范.md)：API 放 hooks/公共 API 文件，页面不堆请求逻辑，弹窗挂页面层。

## 3. 类型契约

当前 `couple-auth.ts` 里 `CoupleRelationshipInfo` 已经存在，字段是 `status`、`coupleId`、`boundAt`、`partner`、`blockCooldown`。本轮**不重命名、不重组**这个 interface，只在其上追加新字段，保证旧页面读取 `coupleId`、`status` 不被打断。后端 `/relationship/me`、`/relationship/bind`、`/auth/wechat-login` 也都返回这个扁平对象，不要在响应外再包一层 `relationship/space`。

```ts
export interface CoupleRelationshipInfo {
  /** 当前关系状态，是前端流程分流的核心字段。 */
  status: RelationshipStatus;
  /** 历史兼容字段：后端实际返回 relationship.id，旧页面仍在读取，不要删除。 */
  coupleId?: string | number;
  /** 当前绑定关系 ID，只代表本次绑定关系段；与 coupleId 同值，语义更明确。 */
  relationshipId?: string | number;
  /** 稳定双人空间 ID，同一对用户多次绑定时保持不变，赌局/日记/回忆录按它恢复历史。 */
  spaceId?: string | number;
  /** 当前关系在稳定空间下的绑定段号，供回忆录按段归档。 */
  relationshipSegmentNo?: number;
  /** 当前稳定空间已创建到第几段绑定关系；解绑或拉黑后不会回退。 */
  currentSegmentNo?: number;
  /** 当前稳定空间内的有效关系 ID，未绑定或冷却时为空。 */
  currentRelationshipId?: string | number | null;
  /** 绑定成功时间，用于“我的”页计算关系时长。 */
  boundAt?: string;
  /** 另一半的最小资料；未绑定时为空。 */
  partner?: CoupleUserInfo | null;
  /** 拉黑冷却详情；仅 BLOCK_COOLDOWN 状态下用于展示冷却截止时间。 */
  blockCooldown?: RelationshipBlockCooldownInfo | null;
}
```

字段优先级说明（写注释和联调时统一用这套口径）：

- `spaceId`：长期空间，业务模块恢复历史数据用这个。
- `relationshipId` / `coupleId`：本次关系段，二者同值；新代码优先用 `relationshipId`。
- `relationshipSegmentNo`：分段归档号，回忆录用。
- 前端不要按双方用户 ID 自己拼 `spaceId`，只消费后端返回值。
