## 1. 成功标准

- 我的页已绑定态可以进入关系管理页。
- 关系管理页展示双方头像、昵称、绑定天数和当前关系状态。
- 当前存在待处理和平解绑申请时，发起方看到“等待对方处理”和“撤回申请”，接收方看到“同意 / 拒绝”操作。
- 用户可以发起和平解绑申请，成功后刷新关系状态和当前申请。
- 发起方可以在对方处理前撤回和平解绑申请，撤回后回到已绑定态。
- 接收方可以同意或拒绝和平解绑，同意后展示已解绑归档态，拒绝后回到已绑定态。
- 用户可以强制拉黑对方，必须输入 `确定拉黑` 后才能提交。
- 拉黑成功后进入冷却期展示，绑定入口禁用并展示冷却截止时间。
- 所有接口失败由公共请求层展示后端文案，页面只恢复状态和记录日志。
- 执行 `npm run type-check` 与 `npm run build:mp-weixin`，若历史问题阻断必须记录原因。

## 3. API 契约

```ts
export type UnbindRequestStatus =
  | 'PENDING'
  | 'ACCEPTED'
  | 'REJECTED'
  | 'CANCELLED_BY_REQUESTER'
  | 'EXPIRED'
  | 'CANCELLED_BY_BLOCK';
export type BlockReleaseSource = 'AUTO_EXPIRED' | 'ADMIN_RELEASED';

export interface RelationshipUnbindRequestInfo {
  /** 和平解绑申请 ID，用于同意或拒绝接口。 */
  id: string | number;
  /** 申请归属的情侣关系 ID。 */
  relationshipId: string | number;
  /** 发起和平解绑的一方。 */
  requester: CoupleUserInfo;
  /** 需要处理和平解绑的一方。 */
  receiver: CoupleUserInfo;
  /** 当前申请状态，决定页面展示等待、处理或历史结果。 */
  status: UnbindRequestStatus;
  /** 发起方可选说明，第一版允许为空。 */
  reason?: string;
  /** 申请过期时间，超过后不能再处理。 */
  expiresAt: string;
  /** 申请创建时间，用于提示用户处理时效。 */
  createdAt: string;
  /** 申请被处理或关闭的时间。 */
  handledAt?: string | null;
}

export interface RelationshipBlockCooldownInfo {
  /** 拉黑冷却记录 ID。 */
  id: string | number;
  /** 主动拉黑的一方。 */
  blocker: CoupleUserInfo;
  /** 被拉黑的一方。 */
  blocked: CoupleUserInfo;
  /** 冷却截止时间，截止前禁止双方重新绑定。 */
  cooldownUntil: string;
  /** 冷却解除时间，未解除时为空。 */
  releasedAt?: string | null;
  /** 冷却解除来源，第一版主要使用 AUTO_EXPIRED。 */
  releaseSource?: BlockReleaseSource | null;
}

export interface RelationshipManageStateData {
  /** 当前用户关系状态。 */
  relationship: CoupleRelationshipInfo;
  /** 当前关系下待处理或最近一条和平解绑申请。 */
  unbindRequest?: RelationshipUnbindRequestInfo | null;
  /** 当前用户与对方之间的拉黑冷却状态。 */
  blockCooldown?: RelationshipBlockCooldownInfo | null;
}
```

接口封装：

- `createUnbindRequestApi(data: { reason?: string })`
- `getCurrentUnbindRequestApi()`
- `acceptUnbindRequestApi(requestId: string | number)`
- `rejectUnbindRequestApi(requestId: string | number, data: { reason?: string })`
- `cancelUnbindRequestApi(requestId: string | number, data: { reason?: string })`
- `blockCurrentPartnerApi(data: { confirmText: string })`

## 5. 业界实践校准

- 敏感操作不直接暴露在“我的”页主界面，减少误触。
- 前端确认文案只能降低误操作概率，不能替代后端权限校验。
- `UNBIND_REQUESTED` 只是待处理事项，不等于关系已经解除。
- 拉黑冷却期展示必须以后端返回时间为准，不用前端本地计算强行覆盖。
- 页面和 hook 分离，避免把请求、弹窗状态和大段 UI 堆在一个 `.vue` 文件里。
