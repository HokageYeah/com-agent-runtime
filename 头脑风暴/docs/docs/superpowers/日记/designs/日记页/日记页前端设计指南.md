## 二、页面角色与设计目标

### 2.1 页面角色

“日记页”是产品 TabBar 首页，也是《情侣日记》的主首页体验。它负责承接用户进入产品后的核心记忆流：

- **登录前**：承担情感引导和登录转化职责
- **登录后**：承担共享日记浏览、按日期回看、写日记入口和日记详情入口职责

### 2.2 设计目标

- 让用户一眼感受到“这是两个人共同记录生活的地方”
- 用中轴时间线强化双方日常内容的并列关系
- 让日期、时间、作者、正文和图片状态清楚可读
- 让日历入口帮助用户快速回看某一天
- 让写日记入口始终可达，但不打断阅读时间线
- 让 LLM 能够清晰分辨：
  - 什么是页面固定骨架
  - 什么是登录状态差异
  - 什么是日记内容展示规则
  - 什么是业务动作入口

## 三、与整体设计的关联关系

### 3.1 必须继承的全局规则

日记页必须严格继承全局设计规范中的以下内容：

- 主背景使用 `#fff8f7`
- 主文本使用暖深色，不使用纯黑
- 卡片使用大圆角，核心卡片接近 `24px`
- 阴影保持轻量粉调或暖调，不使用重黑阴影
- 顶部导航与底部导航沿用统一的 `TopAppBar` / `BottomNavBar`
- 列表布局必须使用中轴时间线
- 左侧固定表示 `TA / 对方`，右侧固定表示 `我 / 自己`
- 页面动效保持轻盈，优先使用淡入、轻浮动、轻缩放和柔和涟漪

### 3.2 日记页的局部特化

相较于“赌局页”的状态提醒和游戏感，日记页更强调：

- 记录感：通过日期、时间、正文和图片沉淀日常记忆
- 亲密感：通过左右并列展示双方生活片段
- 回看感：通过日历入口、日期分组和历史内容透明度表达时间流动
- 纸张感：通过白色卡片、柔和阴影、图片圆角和手账式留白营造温暖质感

## 四、页面信息架构

### 4.1 未登录态信息架构

未登录态页面结构固定为：

1. TopAppBar
2. 情感插画 Hero 区
3. 主标题与副标题
4. 登录 / 注册主按钮
5. 共享日记预览时间线
6. 氛围装饰或手账式分隔
7. BottomNavBar

### 4.2 已登录态信息架构

已登录态页面结构固定为：

1. TopAppBar
2. 日历入口按钮
3. 日期分组
4. 中轴日记时间线
5. 日记卡片
6. 写日记 FAB
7. BottomNavBar

### 4.3 页面切换逻辑

- 未登录态点击“登录 / 注册”后，进入 [登录与绑定](../../../登录与绑定/需求设计文档.md) 的登录流程
- 只有完成微信登录且完成情侣绑定后，才进入日记页正式已登录态
- 已登录但未绑定时，不应展示真实共享日记，应进入绑定链路或展示待绑定引导
- 已登录且已绑定，但当天没有日记时，应保留日记页框架，展示轻量空状态和写日记入口

## 五、未登录态设计指南

### 5.1 页面目标

未登录态不是空白页，而是“情感预告 + 登录转化”页面。

它要完成三件事：

- 告诉用户这里用于记录两个人的日常
- 预告登录后可以看到共享日记时间线
- 引导用户进入登录与绑定流程

### 5.2 视觉结构

- 顶部保留统一导航，标题为“情侣日记”
- Hero 区使用日记本、花瓣、温暖插画或手账元素
- 主标题直接表达开启记录，如 `开启你们的记录`
- 副标题表达情绪价值，如 `记录属于你们的每一个心动时刻`
- 登录 / 注册按钮是页面最强 CTA
- 预览区使用中轴双边卡片展示共享日记的样子
- 底部导航中“日记”页签为当前激活状态

### 5.3 预览时间线要求

- 必须保留中轴线和左右卡片结构
- 左侧表示对方日记预览，右侧表示我的日记预览
- 预览内容可使用示例文案，但不得误导为真实数据
- 预览卡片应保持柔和、温暖、手账感
- 中轴可使用心形节点强化“共同记录”的情绪
- 提示文案建议使用：
  - `登录后即可查看与 TA 的共享日记`
  - `登录后开启你们的共同时间线`

### 5.4 未登录态业务逻辑要求

- 点击主 CTA 进入登录流程
- 点击预览日记卡片时，只提示用户先登录，不跳转详情
- 登录完成但未绑定时，必须继续进入绑定流程
- 绑定完成后，回到日记页并刷新为正式已登录态

## 六、已登录态设计指南

### 6.1 页面目标

已登录态是用户浏览和发布共享日记的主页面。

它要完成五件事：

- 默认展示今天的日记内容
- 以日期分组组织历史日记
- 用中轴时间线清楚表达双方内容归属
- 支持查看图片内容和进入详情
- 提供写日记入口和日历回看入口

### 6.2 视觉结构

- 顶部使用半透明模糊导航栏，标题为“情侣日记”
- 左上角或导航内提供日历入口
- 页面主体按日期分组展示
- 每个日期分组中央使用日期胶囊
- 日期下方使用中轴虚线串联时间点
- 左侧卡片展示对方发布的日记
- 右侧卡片展示自己发布的日记
- 右下角使用圆形 FAB 写日记

### 6.3 中轴时间线要求

- 中轴线固定在页面中间
- 左右卡片不得反转归属
- 每条日记必须通过时间点圆点连接中轴
- 同一天内按时间倒序排列
- 某一侧没有内容时允许留空
- 日期分组之间需要有明显垂直间距
- 历史日期可适度降低透明度，但不能影响可读性
- 连续多条来自同一侧的日记不能合并到失去时间粒度

### 6.4 日记卡片内容要求

每张日记卡片至少包含：

- 作者标签：如 `他`、`她`、`我`、`TA`
- 发布时间：精确到分钟
- 正文内容：最多 500 字，列表态可适度截断
- 图片状态：
  - 无图片：只展示正文
  - 1 张图片：展示单张缩略图
  - 2-9 张图片：展示网格缩略图
- 删除申请状态提示：仅在存在删除申请时展示

### 6.5 图片展示要求

- 图片缩略图使用圆角，建议 `12px-16px`
- 图片网格最多展示 9 张
- 多图使用 3 列网格
- 图片必须保持 `object-cover`，避免拉伸
- 图片加载失败时使用柔和占位，不出现破碎图标
- 点击图片或卡片进入日记详情页，由详情页承接大图预览

### 6.6 日历入口要求

- 日历入口位于顶部导航左侧或明显可见位置
- 点击后打开日历模式或日历浮层
- 日历模式必须能表达：
  - 当天有日记
  - 当天有图片日记或重点回忆
  - 当前选中日期
- 点击某个日期后，跳转或滚动到对应日期时间线
- 日历模式与时间线必须使用同一份数据源

### 6.7 写日记 FAB 要求

- FAB 固定在右下角，位于 BottomNavBar 上方
- 使用圆形主色或柔和渐变按钮，图标为 `add`
- 点击后进入“写日记页”
- 按下反馈为轻缩放、涟漪或轻浮动，不使用剧烈弹跳
- 如果用户未绑定，不展示真实发布能力，应引导完成绑定

## 七、日记状态与删除申请视觉规范

### 7.1 日记状态映射

前端展示状态必须能映射需求文档中的状态：

```text
已发布
  -> 删除申请中
  -> 已删除
  -> 删除申请失效
  -> 删除申请已撤回
```

### 7.2 删除申请状态展示

| 状态 | 页面含义 | 视觉策略 | 操作语气 |
|---|---|---|---|
| 已发布 | 正常可见日记 | 常规卡片 | 温暖、记录感 |
| 删除申请中 | 一方发起删除，等待另一方确认 | 轻提示条或状态胶囊 | 中性、低压 |
| 已删除 | 另一方同意删除 | 当前空间不再展示正文 | 不做情绪化表达 |
| 删除申请失效 | 7 天未处理 | 保留原内容，可在详情中弱提示 | 轻量说明 |
| 删除申请已撤回 | 发起方撤回 | 保留原内容，可在详情中弱提示 | 轻量说明 |

### 7.3 删除申请文案要求

推荐：

- `删除申请处理中`
- `等待 TA 确认`
- `申请已撤回`
- `申请已失效，日记已保留`

避免：

- `强制删除`
- `对方拒绝了你`
- `你必须处理`
- `超时惩罚`

列表态只需要轻量标识，完整处理动作应放在日记详情页。

## 八、组件级实现约束

### 8.1 TopAppBar

- 使用 `bg-surface/80` 和 `backdrop-blur-md`
- 标题为“情侣日记”
- 左侧建议使用 `calendar_month` 或 `calendar_today` 作为日历入口
- 右侧可保留心形图标或未来消息入口

### 8.2 BottomNavBar

- 必须复用全局底导样式
- “日记”页签始终高亮
- 激活态使用主色容器底色或柔和粉色渐变
- 图标使用填充态 `auto_stories`

### 8.3 Diary Card

- 白色或浅暖色背景
- 圆角接近 `24px`
- 内部信息顺序固定为：作者 / 时间 -> 正文 -> 图片 -> 状态补充
- 点击反馈使用轻缩放或轻阴影变化
- 日记正文保持自然换行，不使用过度压缩排版

### 8.4 Date Pill

- 日期胶囊位于中轴正上方
- 今天可展示 `2026年6月10日 今天`
- 历史日期可降低字号或透明度
- 日期标题必须承担分组作用，不只是装饰

### 8.5 Timeline Marker

- 时间点使用圆点或心形节点
- 重点内容可使用主色描边圆点
- 普通内容使用暖灰或浅粉节点
- 节点必须与对应卡片在垂直方向上对齐

## 九、业务逻辑最小要求

### 9.1 未登录态至少需要具备

- 登录 / 注册按钮点击事件
- 预览卡片点击提示逻辑
- 登录成功后的绑定状态判断
- 绑定完成后刷新日记页为已登录态

### 9.2 已登录态至少需要具备

- 日记列表按日期分组
- 日记按左右归属渲染
- 同一天内按时间倒序排列
- 点击日记卡片进入日记详情页
- 点击日历入口进入日历模式或打开日历浮层
- 点击指定日期跳转对应日期时间线
- 点击 FAB 进入写日记页

### 9.3 写日记入口约束

写日记页不在本指南中展开，但日记页入口必须承接需求文档中的发布约束：

- 内容为空不能提交
- 正文最多 500 字
- 图片最多 9 张
- 发布成功后回到日记页并刷新时间线
- 网络异常时需要明确提示未成功保存

## 十、空状态、加载状态与异常状态

### 10.1 空状态

当已登录且已绑定，但当前日期没有日记时：

- 保留顶部导航、底部导航和 FAB
- 中央展示轻量空状态
- 文案建议使用：
  - `今天还没有新的记录`
  - `写下今天第一个心动瞬间`
- 不应展示未登录态插画和登录按钮

### 10.2 加载状态

- 时间线可使用日记卡片骨架屏
- 骨架屏仍需保留左右中轴结构
- 不要在加载期间左右归属错位

### 10.3 异常状态

- 拉取失败时展示轻量错误提示和重试入口
- 不使用刺眼警告色
- 文案建议使用：
  - `暂时没有加载出来，稍后再试一次`
  - `重新加载`

## 十一、文案语气规范

### 11.1 基础语气

日记页文案应温暖、轻松、像手账提示，而不是工具型后台提示。

推荐：

- `开启你们的记录`
- `记录属于你们的每一个心动时刻`
- `登录后即可查看与 TA 的共享日记`
- `今天还没有新的记录`
- `写下今天第一个心动瞬间`

避免：

- `暂无数据`
- `无权限访问`
- `操作失败`
- `必须登录`

### 11.2 正文展示语气

- 正文按用户原文展示，不额外加工语气
- 列表态截断时保持自然，不插入强营销文案
- emoji 可自然展示，但不强制添加

## 十二、给 LLM 的页面还原要求

### 12.1 还原目标

让 LLM 根据资料生成页面时，必须同时还原以下三层内容：

- **视觉层**：颜色、字体、圆角、阴影、插画、图片网格、轻动效、手账感
- **布局层**：未登录态与已登录态页面骨架、中轴时间线、日期分组、日历入口和 FAB
- **业务层**：登录跳转、绑定判定、日记详情跳转、日历跳转、写日记入口、删除申请状态

### 12.2 不允许遗漏的信息

LLM 生成页面时，不能遗漏：

- 顶部导航
- 底部导航
- “日记”页签激活态
- 未登录态登录 CTA
- 未登录态预览时间线
- 已登录态中轴时间线
- 左侧 `TA / 对方`，右侧 `我 / 自己`
- 日期分组
- 作者标签
- 发布时间
- 日记正文
- 图片缩略图或图片数量状态
- 日历入口
- 写日记 FAB

### 12.3 不能破坏的规则

- 不能把左侧和右侧归属反转
- 不能把时间线改成单列平铺
- 不能让日历模式和时间线模式使用不同数据口径
- 不能在未登录态展示真实共享日记
- 不能只做静态 UI 而不体现最小点击行为
