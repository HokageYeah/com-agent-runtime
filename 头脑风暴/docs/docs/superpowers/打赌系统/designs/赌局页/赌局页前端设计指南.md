## 二、页面角色与设计目标

### 2.1 页面角色

“赌局页”是打赌系统的首页，也是 TabBar 第二页。它负责承接用户进入模块后的第一眼信息：

- **登录前**：承担功能预告和登录转化职责
- **登录后未绑定**：承担绑定引导和功能锁定预告职责
- **登录后已绑定**：承担赌局时间线浏览、状态提醒、发起赌局和战绩概览职责
- **发起赌约时**：承担轻量表单填写、奖励提醒、截止时间选择和发布确认职责

### 2.2 设计目标

- 让用户一眼理解“这是两个人之间的趣味胜负记录”
- 用中轴时间线强化情侣双方的对等互动关系
- 让待处理、待结算、待兑现等状态清晰可见
- 让待兑现提醒足够醒目，但保持温柔、轻松、无压迫感
- 让 LLM 能够清晰分辨：
  - 什么是页面固定骨架
  - 什么是登录与绑定状态差异
  - 什么是赌局状态差异
  - 什么是业务动作入口

## 三、与整体设计的关联关系

### 3.1 必须继承的全局规则

赌局页必须严格继承全局设计规范中的以下内容：

- 主背景使用 `#fff8f7`
- 主文本使用暖深色，不使用纯黑
- 卡片使用大圆角，核心卡片接近 `24px`
- 阴影保持轻量粉调或暖调，不使用重黑阴影
- 顶部导航与底部导航沿用统一的 `TopAppBar` / `BottomNavBar`
- 列表布局必须优先使用中轴时间线
- 左侧固定表示 `TA / 对方`，右侧固定表示 `我 / 自己`
- 状态提醒优先使用柔和描边、局部高亮、呼吸发光和轻浮动

### 3.2 赌局页的局部特化

相较于“我的”页的关系管理和登录流程的阶段引导，赌局页更强调：

- 游戏感：通过骰子、奖杯、胜负数字、奖励标签表达轻松互动
- 时间感：通过日期胶囊、时间节点、截止时间表达赌局进展
- 状态感：通过状态角标、卡片强弱、待兑现动效表达当前优先级
- 双人感：通过左右归属和发起方标签表达“谁发起、谁回应、谁赢了”

## 四、页面信息架构

### 4.1 未登录态信息架构

未登录态页面结构固定为：

1. TopAppBar
2. 趣味赌局 Hero 区
3. 登录 / 注册主按钮
4. 锁定时间线预览
5. 锁定战绩统计区
6. 氛围装饰图
7. BottomNavBar

### 4.2 已登录未绑定态信息架构

已登录未绑定态页面结构固定为：

1. TopAppBar
2. 甜蜜赌约 Hero 区
3. 我的头像 + 待邀请另一半占位
4. 立即绑定主按钮
5. 锁定时间线预览
6. BottomNavBar

### 4.3 已登录已绑定态信息架构

已登录已绑定态页面结构固定为：

1. TopAppBar
2. 按日期分组的中轴时间线
3. 赌局状态卡片
4. 战绩统计区
5. 发起赌局 FAB
6. BottomNavBar

### 4.4 已登录发起赌约页信息架构

已登录发起赌约页页面结构固定为：

1. 顶部关闭导航栏
2. 发起新赌约装饰 Header
3. 主表单卡片
4. 奖励快捷选项
5. 截止日期 / 时间选择
6. 挑战关系确认区
7. 温和说明卡片
8. 底部固定发布按钮

### 4.5 页面切换逻辑

- 未登录态点击“登录 / 注册”后，进入 [登录与绑定](../../../登录与绑定/需求设计文档.md) 的登录流程
- 完成微信登录但未绑定情侣关系时，进入已登录未绑定态，对应参考代码 `code/已登录未绑定/code.html`
- 已登录但未绑定时，不应展示真实赌局列表、真实战绩或发起赌局能力，应展示待绑定引导
- 只有完成微信登录且完成情侣绑定后，才进入赌局页正式已登录已绑定态，对应参考代码 `code/已登录已绑定/code.html`
- 已登录且已绑定，但没有赌局数据时，应保留中轴时间线语义，展示轻量空状态和发起赌局入口
- 已登录已绑定态点击 FAB / 发起赌约按钮后，进入发起赌约页，对应参考代码 `code/已登录发起赌约/code.html`
- 发起赌约页点击关闭按钮时返回赌局页，不创建草稿
- 发起赌约页发布成功后返回赌局页，并刷新为包含新 `pending` 赌局的已登录已绑定态

## 五、未登录态设计指南

### 5.1 页面目标

未登录态不是空页面，而是“功能预告 + 登录转化”页面。

它要完成三件事：

- 告诉用户赌局是情侣之间的趣味互动功能
- 预告登录后可以查看双方赌约和战绩
- 引导用户进入登录与绑定流程

### 5.2 视觉结构

- 顶部保留统一导航，标题可使用“情侣日记”或当前模块标题
- Hero 区使用骰子或赌局相关图标，保持温柔、圆润、轻游戏感
- 主按钮“登录 / 注册”是全页面最强 CTA
- 时间线预览以左右锁定卡片展示，不出现真实内容
- 战绩统计区使用模糊遮罩和“解锁完整数据”提示
- 底部导航中“赌局”页签为当前激活状态

### 5.3 锁定时间线预览要求

- 必须保留中轴线和左右卡片结构
- 左侧表示对方赌约预览，右侧表示我的赌约预览
- 卡片内容使用骨架块或模糊占位，不展示真实赌局数据
- 每张卡片上覆盖锁图标，传达“登录后可见”
- 下方提示文案建议使用：
  - `登录后查看正在进行的赌约`
  - `登录后解锁你们的甜蜜胜负`

### 5.4 锁定战绩区要求

- 战绩区可展示统计结构，但数字使用 `--`
- 胜场、履约率、常见奖励等真实数据必须被锁定
- 可使用柔和白色遮罩或玻璃模糊
- 中央提示文案建议使用：
  - `解锁完整数据`
  - `登录后查看我们的战绩`

### 5.5 未登录态业务逻辑要求

- 点击主 CTA 进入登录流程
- 点击锁定时间线卡片时，只提示用户先登录，不跳转详情
- 点击锁定战绩区时，只提示用户先登录
- 登录完成但未绑定时，进入已登录未绑定态，由该状态承接绑定引导
- 绑定完成后，回到赌局页并刷新为已登录已绑定态

## 六、已登录态设计指南

### 6.1 页面目标

已登录态需要继续区分绑定状态：已登录未绑定负责引导用户建立情侣关系；已登录已绑定才是用户查看和管理赌局状态的首页。

### 6.2 已登录未绑定态设计目标

已登录未绑定态不是未登录态的重复，也不是正式赌局列表。

它要完成四件事：

- 确认用户已经登录，页面可以展示“我的头像 / 我的身份感”
- 明确提示当前缺少另一半，赌局数据仍未解锁
- 引导用户点击“立即绑定”进入邀请与绑定流程
- 保留锁定时间线预览，让用户理解绑定后会看到双人赌约

### 6.3 已登录未绑定态视觉结构

- 顶部保留统一导航和当前“赌约”页签激活态
- Hero 区标题使用“甜蜜赌约”等轻松文案
- 中部使用“我的头像 + 虚线连接 + 添加另一半占位”表达关系未完成
- 主按钮使用“立即绑定”，视觉层级高于锁定预览
- 锁定时间线预览可出现示例性赌约文案，但必须覆盖锁定或模糊效果
- 不展示真实战绩统计，不展示发起赌局 FAB，不允许进入赌注详情

### 6.4 已登录未绑定态业务逻辑要求

- 点击“立即绑定”进入 [登录与绑定](../../../登录与绑定/需求设计文档.md) 的邀请与绑定流程
- 点击另一半占位区域同样进入绑定流程
- 点击锁定时间线卡片时，提示先绑定另一半，不跳转详情
- 绑定完成后回到赌局页并刷新为已登录已绑定态
- 如果绑定流程被取消，仍停留在已登录未绑定态

### 6.5 已登录已绑定态设计目标

已登录已绑定态是用户查看和管理赌局状态的首页。

它要完成五件事：

- 展示双方赌局时间线
- 强化赌局左右归属
- 明确当前赌局状态
- 提醒用户处理待结算、待兑现事项
- 提供发起新赌局入口

### 6.6 已登录已绑定态视觉结构

- 顶部使用半透明模糊导航栏，标题为“赌局首页”或“赌局”
- 页面主体按日期分组展示
- 每个日期分组中央使用胶囊日期标签
- 日期下方使用中轴虚线串联时间点
- 左侧卡片展示 `TA 发起`
- 右侧卡片展示 `我发起`
- 页面底部展示“我们的战绩”
- 右下角使用圆形 FAB 发起新赌局

### 6.7 中轴时间线要求

- 中轴线固定在页面中间
- 左右卡片不得反转归属
- 每个赌局卡片必须通过时间点圆点连接中轴
- 同一天内按时间倒序排列
- 某一侧没有内容时允许留空
- 日期分组之间需要有明显垂直间距，避免时间线拥挤

### 6.8 赌局卡片内容要求

每张赌局卡片至少包含：

- 发起方标签：`TA 发起` / `我发起`
- 状态标签：如 `进行中`、`待结算`、`待兑现`、`已完成`
- 赌局标题：清楚表达赌什么
- 奖励信息：用 `奖励：xxx` 结构表达
- 状态补充信息：
  - 进行中：展示截止时间或剩余时间
  - 待结算：展示等待确认、已到期等信息
  - 待兑现：展示胜负结果和兑现提醒
  - 已完成：展示兑现完成时间或完成说明

### 6.9 战绩统计区要求

统计区固定放在时间线之后，作为页面收束信息。

推荐包含：

- 她赢了 / TA Wins
- 我赢了 / Me Wins
- 履约率
- 最常出现的奖励

统计区视觉应比赌局卡片更稳定、更总结，不要抢夺待处理状态的注意力。

### 6.10 发起赌局 FAB 要求

- FAB 固定在右下角，位于 BottomNavBar 上方
- 使用圆形主色按钮，图标为 `add`
- 点击后进入“发起赌注页”
- 按下反馈为轻缩放，不使用剧烈弹跳
- 如果用户未绑定，不展示真实发起能力，应引导完成绑定

### 6.11 发起赌约页设计目标

发起赌约页是从已登录已绑定赌局页进入的二级页面。

它要完成五件事：

- 让用户轻松填写“赌什么”
- 让用户填写或选择奖励
- 让用户选择明确截止时间
- 让用户确认这是“我向 TA 发起挑战”
- 发布后创建 `pending` 赌局并回到赌局页刷新

### 6.12 发起赌约页视觉结构

- 顶部导航使用关闭图标，不使用返回箭头，表达“退出发起”
- 页面标题使用“发起新赌约”
- Header 使用圆形浅粉图标容器和轻文案，如 `赌一个充满爱的小愿望`
- 主表单放在白色圆角卡片内，圆角接近 `24px`
- 表单输入区使用浅暖粉底色，聚焦时使用主色描边
- 奖励快捷选项使用柔和 chip，不使用强竞技标签
- 截止日期和时间使用双列选择卡片
- 挑战关系确认区展示“我 / TA”头像和中间挑战图标
- 底部发布按钮固定在屏幕底部，使用豆沙红或主行动色
- 信息提示文案保持轻柔，例如 `赌约发布后，TA 会收到通知。只有双方都同意后，赌局才正式开启哦。`

### 6.13 发起赌约页表单要求

表单至少包含：

- 赌什么：对应后端 `title` 或赌约主题
- 赢的判定规则：对应后端 `winCondition`，如果参考代码中没有独立输入框，落地时应在“我们要赌什么？”下方补一个同风格输入区
- 奖励：对应后端 `reward`
- 截止日期和截止时间：合并为后端 `deadlineAt`
- 挑战关系确认：MVP 中当前用户始终是发起方，另一半始终是接收方

奖励快捷选项可包含：

- `冰淇淋`
- `按摩`
- `看电影`

点击快捷选项时，只填充奖励输入框，不直接提交。

### 6.14 发起赌约页业务逻辑要求

- 只有 `isLogin === true` 且 `relationshipStatus === 'BOUND'` 时允许进入
- 未登录进入时跳登录流程
- 已登录未绑定进入时跳绑定流程或返回赌局页未绑定态
- 点击关闭按钮返回赌局页
- 点击发布按钮前必须校验：
  - 赌什么不能为空
  - 赢的判定规则不能为空
  - 奖励不能为空
  - 截止时间必须晚于当前时间
- 发布前调用奖励敏感词检查
- 命中奖励敏感词时展示温和提醒，允许用户修改或继续提交
- 提交中禁用发布按钮，避免重复创建
- 发布成功后展示轻提示，如 `甜蜜赌约已发起`
- 发布成功后返回赌局页，并触发时间线刷新

## 七、赌局状态视觉规范

### 7.1 状态与视觉层级

| 状态 | 页面含义 | 视觉策略 | 是否需要强提醒 |
|---|---|---|---|
| `pending` | 已发起，待对方同意 | 主色或柔和高亮，文案强调待回应 | 中 |
| `rejected` | 对方拒绝 | 降低饱和度，弱化显示 | 否 |
| `active` | 已接受，进行中 | 清晰展示截止时间，保持正常卡片权重 | 低 |
| `settling` | 已到期，待双方确认结果 | 状态标签加重，提示确认结果 | 中 |
| `redeeming` | 结果已确认，待兑现 | 呼吸发光 + 轻浮动 + 主色描边 | 高 |
| `completed` | 奖励已兑现完成 | 弱化、灰粉背景、可带轻划线或完成说明 | 否 |
| `expired` | 超时未结算作废 | 低饱和、弱文案，不做情绪化指责 | 否 |

### 7.2 待兑现提醒规则

`redeeming` 是赌局页最高优先级状态，但提醒必须温柔。

推荐表现：

- 卡片边框使用 `#ff8fa3` 或主色浅描边
- 状态角标使用主色文字或星星图标
- 卡片使用 3-4 秒一轮的呼吸发光
- 可伴随 `translateY(-4px)` 左右的轻浮动

禁止表现：

- 剧烈闪烁
- 高频抖动
- 大面积警告红
- “快点兑现”“别拖了”等强压式文案

### 7.3 已完成与已拒绝弱化规则

- 终态卡片应降低视觉权重
- 可使用浅粉灰背景、轻透明、低饱和图标
- 不应完全隐藏，避免破坏时间线连续性
- 已完成奖励可用轻划线或完成时间表达“已经收束”

## 八、组件级实现约束

### 8.1 TopAppBar

- 使用 `bg-surface/80` 和 `backdrop-blur-md`
- 标题颜色使用主色或暖深色
- 左侧可使用 `calendar_today`、`casino` 等图标
- 右侧可保留心形图标或未来消息/设置入口

### 8.2 BottomNavBar

- 必须复用全局底导样式
- “赌局”页签始终高亮
- 激活态使用主色容器底色和填充态 `casino` 图标

### 8.3 Bet Card

- 白色或浅暖色背景
- 圆角接近 `24px`
- 内部信息顺序固定为：发起方 / 状态 -> 标题 -> 奖励 -> 状态补充
- 点击反馈使用轻缩放
- 不同状态只改变局部强调，不改变基础卡片结构

### 8.4 Date Pill

- 日期胶囊位于中轴正上方
- 使用浅粉灰背景和辅助文字色
- 文案可为具体日期，如 `2026年6月10日`，也可在业务层补充 `今天`、`昨天`

### 8.5 Statistics Card

- 使用柔和容器包裹
- 胜场数字可以比普通文本更大
- 统计名称使用低权重文字
- 不使用过度竞技化、排行榜式的强刺激视觉

## 九、业务逻辑最小要求

### 9.1 未登录态至少需要具备

- 登录 / 注册按钮点击事件
- 锁定卡片点击提示逻辑
- 锁定战绩区点击提示逻辑
- 登录成功后的绑定状态判断
- 绑定完成后刷新赌局页为已登录未绑定态或已登录已绑定态

### 9.2 已登录未绑定态至少需要具备

- 绑定状态判断逻辑
- “立即绑定”按钮点击事件
- 另一半占位区域点击进入绑定流程
- 锁定时间线卡片点击提示逻辑
- 禁用真实赌局列表、战绩统计、详情跳转和发起赌局 FAB
- 绑定完成后刷新赌局页为已登录已绑定态

### 9.3 已登录已绑定态至少需要具备

- 赌局列表按日期分组
- 赌局按左右归属渲染
- 赌局按状态展示不同视觉层级
- 点击赌局卡片进入赌注详情页
- 点击 FAB 进入发起赌注页
- 点击待结算或待兑现卡片时，详情页承接确认结果或兑现确认操作

### 9.4 发起赌约页至少需要具备

- 登录和绑定状态守卫
- 关闭返回逻辑
- 表单输入状态
- 奖励快捷选项填充逻辑
- 截止日期 / 时间选择逻辑
- 奖励敏感词检查逻辑
- 发布按钮防重复提交逻辑
- 发布成功后的返回和赌局页刷新逻辑

### 9.5 状态映射最小要求

前端展示状态必须能映射需求文档中的状态机：

```text
pending
  -> rejected
  -> active
  -> settling
  -> redeeming
  -> completed
  -> expired
```

不得在 UI 中发明无法映射到业务状态机的状态名称。如果需要更口语化文案，应在展示层映射，例如：

| 业务状态 | 展示文案 |
|---|---|
| `pending` | 待回应 |
| `active` | 进行中 |
| `settling` | 待结算 |
| `redeeming` | 待兑现 |
| `completed` | 已完成 |
| `rejected` | 已拒绝 |
| `expired` | 已作废 |

## 十、文案语气规范

### 10.1 基础语气

赌局页文案应轻松、有趣、亲密，但不能让用户感到被催促或被评判。

推荐：

- `等待确认结果...`
- `该兑现小奖励啦`
- `登录后查看正在进行的赌约`
- `解锁你们的甜蜜胜负`
- `已于 06-08 兑现`

避免：

- `马上处理`
- `你已经拖很久了`
- `未兑现惩罚`
- `强制结算`
- `逾期警告`

### 10.2 奖励文案

- 奖励应保持生活化、轻量、可爱
- 可使用适量 emoji 强化趣味感
- 敏感词提醒由业务层承接，前端不应将敏感奖励渲染成鼓励性文案

## 十一、给 LLM 的页面还原要求

### 11.1 还原目标

让 LLM 根据资料生成页面时，必须同时还原以下三层内容：

- **视觉层**：颜色、字体、圆角、阴影、图标、呼吸动效、柔和游戏感
- **布局层**：未登录态、已登录未绑定态、已登录已绑定态页面骨架，以及绑定后中轴时间线、战绩统计和 FAB
- **业务层**：登录跳转、绑定判定、状态映射、详情跳转、发起赌局入口、发起赌约表单提交闭环

### 11.2 不允许遗漏的信息

LLM 生成页面时，不能遗漏：

- 顶部导航
- 底部导航
- “赌局”页签激活态
- 未登录态登录 CTA
- 未登录态锁定时间线预览
- 已登录未绑定态立即绑定 CTA
- 已登录未绑定态头像与另一半占位
- 已登录已绑定态中轴时间线
- 左侧 `TA 发起` / 右侧 `我发起`
- 赌局状态标签
- 奖励信息
- 待兑现呼吸提醒
- 战绩统计区
- 发起赌局 FAB
- 发起赌约页表单
- 发起赌约页底部固定发布按钮
- 发起成功后返回并刷新赌局页

### 11.3 不能破坏的规则

- 不能把左侧和右侧归属反转
- 不能用强烈警告色表达待兑现
- 不能把未登录态做成纯空白页
- 不能把已完成赌局完全从时间线中移除
- 不能只做静态 UI 而不体现最小点击行为
- 不能让已登录未绑定用户进入真实发起赌约页
- 不能允许前端伪造为 TA 代发起赌局
