# 打赌系统模块设计目录

本目录用于存放“打赌系统”模块的交互设计、页面原型、状态样式和文案方案。

编写要求：

- 开始模块设计前，先遵守 [整体设计/前端UI设计规范与AI提示词指南](../../整体设计/前端UI设计规范与AI提示词指南.md)
- 重点覆盖发起、待处理、结算协商、待兑现、已完成等状态页面
- 区分醒目状态与轻状态的视觉层级
- 提醒文案保持温柔，不采用强压式催促语气

专项设计入口：

- “赌局页”专项设计：[赌局页/赌局页前端设计指南](./赌局页/赌局页前端设计指南.md)

阅读顺序建议：

1. 先阅读 [需求设计文档](../需求设计文档.md)，理解赌局状态机、发起/结算/兑现闭环
2. 再阅读 [整体设计/前端UI设计规范与AI提示词指南](../../整体设计/前端UI设计规范与AI提示词指南.md)
3. 再阅读 [赌局页/赌局页前端设计指南](./赌局页/赌局页前端设计指南.md)
4. 最后查看赌局页代码参考，按未登录、已登录未绑定、已登录已绑定、已登录发起赌约四种状态分别还原页面

设计输出约束：

- 赌局页必须继承产品全局中轴时间线规则：左侧为 `TA / 对方`，右侧为 `我 / 自己`
- 未登录态不能展示真实赌局内容，只展示锁定预览和登录入口
- 已登录未绑定态不能展示真实赌局内容，应展示绑定另一半的引导和锁定预览
- 已登录已绑定态必须清楚表达赌局状态、左右归属、截止/结果/奖励信息
- 发起赌约页只能从已登录已绑定态进入，表单视觉必须继承暖粉卡片、底部固定发布按钮和温和提示文案
- `redeeming` 待兑现状态必须有温和提醒，但不得使用强压迫、强警告式视觉
