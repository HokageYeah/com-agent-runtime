## 二、项目概述

### 2.1 产品简介

「情侣日记」是一款面向情侣用户的微信小程序，围绕 **共同记录日常** 与 **趣味打赌互动** 两条主线，提供一个温暖、私密、轻松的情侣空间。

### 2.2 目标用户

- 处于恋爱关系中的年轻情侣
- 希望拥有一个专属且私密的双人记录空间
- 更偏好轻互动、弱工具感的产品体验

### 2.3 产品定位

产品定位为 **甜蜜轻松向**。整体体验更接近“恋爱备忘录 + 趣味互动小游戏”，强调陪伴感、仪式感和情绪价值，不追求复杂社交功能。

### 2.4 MVP 范围

第一版只做以下核心范围：

| # | 功能模块 | 说明 |
|---|---|---|
| 1 | 登录与绑定 | 完成微信登录、角色选择、情侣绑定关系建立 |
| 2 | 日记 | 建立双人共享的日常记录时间线 |
| 3 | 打赌系统 | 提供完整的打赌闭环与趣味兑现机制 |
| 4 | 回忆录 | 在解绑后保留共同记录，并通过密码保护访问 |

不在 MVP 范围内的能力见文末“后续迭代方向”。

## 三、技术架构

### 3.1 技术栈

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 前端 | uni-app（Vue 3 + TypeScript） | 支持微信小程序为主，兼顾后续跨端 |
| 后端 | FastAPI（Python） | 负责业务规则、状态流转和接口服务 |
| 数据库 | MySQL | 承载用户、关系、日记、赌局、通知等核心数据 |
| 缓存 | Redis | 用于会话、状态缓存、提醒队列 |
| 部署 | 云服务器（腾讯云/阿里云） | 初期单机部署，后续再演进 |

### 3.2 系统架构图

```text
┌─────────────────────────────────────────────────┐
│                 uni-app 前端                      │
│          （微信小程序 / H5 / App）                 │
└──────────────────────┬──────────────────────────┘
                       │ HTTPS
                       ▼
┌─────────────────────────────────────────────────┐
│              FastAPI 后端服务                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐     │
│  │ 用户模块  │ │ 日记模块  │ │  打赌模块    │     │
│  └──────────┘ └──────────┘ └──────────────┘     │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐     │
│  │ 回忆录   │ │ 通知消息  │ │ 设置与安全   │     │
│  └──────────┘ └──────────┘ └──────────────┘     │
└────────┬───────────────────────┬────────────────┘
         │                       │
         ▼                       ▼
┌─────────────────┐    ┌─────────────────┐
│     MySQL       │    │      Redis      │
│  （持久化存储）   │    │  （缓存/队列）   │
└─────────────────┘    └─────────────────┘
```

### 3.3 数据同步方式

- 所有业务数据以服务端为准，双方打开小程序即可看到同一份情侣空间内容。
- 实时性需求主要体现在：
  - 新日记发布后的可见性
  - 绑定与解绑状态变化
  - 赌局阶段变化与兑现提醒
  - 删除申请、系统通知、站内消息
- 同步实现可采用 WebSocket 或轮询，具体技术方案在后续开发计划中细化。

## 四、模块串联关系

### 4.1 用户主流程

```text
打开小程序
  -> 微信登录
  -> 选择角色标签
  -> 进入未绑定态
  -> 发起绑定或输入绑定码
  -> 绑定成功
  -> 进入日记首页
  -> 在日记 / 打赌 / 我的之间切换
  -> 如发生解绑
  -> 共同数据归档进入回忆录
```

### 4.1.1 首次使用流程示意

```text
打开小程序
    │
    ├─ 微信一键登录
    │
    ├─ 选择角色标签：「他」或「她」
    │
    ├─ 进入等待绑定页面
    │   ├─ 方式一：点击「邀请另一半」→ 生成绑定码 / 二维码 → 分享给对方
    │   └─ 方式二：输入对方给的绑定码 → 确认绑定
    │
    └─ 绑定成功 → 进入日记首页（开始记录）
```

### 4.2 模块之间如何串联

- 登录与绑定是所有核心功能的前置入口。
- 绑定成功后，双方共享同一个情侣空间，日记和打赌系统都挂在该空间之下。
- 通知与消息横向贯穿绑定、删除申请、赌局状态变化、兑现提醒等流程。
- 设置与安全用于承接通知开关、密码管理和隐私边界控制。
- 回忆录依赖解绑结果，它是情侣空间历史数据的归档出口。

### 4.3 跨模块协作原则

- 单模块文档只描述本模块内部规则和接口边界。
- 涉及跨模块动作时，必须明确写清“触发源模块 -> 结果模块”。
- 同一条规则只在一个文档中作为主定义，其它文档通过链接引用，避免重复和冲突。

## 五、功能模块摘要

### 5.1 登录与绑定

- 支持微信一键登录
- 登录后必须选择角色标签「他」或「她」
- 支持邀请码或二维码建立情侣关系
- 支持和平解绑与强制拉黑两种关系解除方式

详细规则见：[登录与绑定/需求设计文档](./superpowers/登录与绑定/需求设计文档.md)

### 5.2 日记

- 支持双人共享时间线记录
- 支持日历模式查看历史日期
- 日记包含文字、图片、作者、时间与日期归属
- 删除采用双方协作确认机制

时间线示意保留在子文档中，便于后续继续扩展展示样式与交互说明。

详细规则见：[日记/需求设计文档](./superpowers/日记/需求设计文档.md)

### 5.3 打赌系统

- 提供发起、接受、进行中、待结算、待兑现、已完成的完整生命周期
- 支持奖励内容敏感词温和提醒
- 到期后双方共同确认结果，兑现阶段提供持续提醒
- 首页时间线与战绩统计共同展示

赌局时间线示意与双人结算示意保留在子文档中，便于后续衍生页面设计。

详细规则见：[打赌系统/需求设计文档](./superpowers/打赌系统/需求设计文档.md)

### 5.4 回忆录

- 解绑后将共同记录归档进入回忆录
- 用户通过独立密码访问回忆录
- 支持多段恋情回忆列表、单条置顶、指定删除和闪回式详情回看

详细规则见：[回忆录/需求设计文档](./superpowers/回忆录/需求设计文档.md)

### 5.5 横向能力模块

- 通知与消息：承接系统通知、提醒和站内消息规则
- 设置与安全：承接通知开关、密码管理、隐私要求
- 首次引导与全局流程：承接首次进入和全局状态切换

详细规则见：

## 七、关键数据流

### 7.1 绑定数据流

```text
用户登录
  -> 创建或更新 user
  -> 发起绑定邀请
  -> 生成绑定码 / 二维码
  -> 对方确认绑定
  -> 创建或更新 couple
  -> 双方进入共享情侣空间
```

### 7.1.1 绑定交互示意

```text
用户A（发起方）                    用户B（接收方）
    │                                  │
    ├─ 点击「邀请另一半」               │
    │   生成专属绑定码 / 二维码          │
    │                                  │
    │       发送绑定邀请 ──────────►    │
    │                                  ├─ 扫码 / 输入绑定码
    │                                  ├─ 看到对方昵称和头像
    │                                  ├─ 点击「同意绑定」
    │                                  │
    │   ◄────────── 绑定成功通知 ────────┤
    │                                  │
    ├─ 双方进入主页（日记时间线）         │
```

### 7.2 日记数据流

```text
用户发布日记
  -> 写入 diary
  -> 建立作者和情侣空间归属
  -> 触发通知
  -> 对方在时间线中可见
```

### 7.2.1 日记时间线示意

```text
📅 2026年6月10日（今天）
├── 14:30  🌸 她：今天午饭吃了麻辣烫，好辣好好吃！
│           [图片 x2]
├── 12:15  🧢 他：中午遛狗的时候发现小区门口开了家新咖啡店
├── 09:00  🌸 她：早上好呀，今天天气真不错 ☀️
└── ...
```

### 7.3 赌局数据流

```text
用户发起赌注
  -> 写入 bet
  -> 对方接受或拒绝
  -> 到期后进入结算
  -> 双方确认结果
  -> 进入兑现阶段
  -> 完成后沉淀到历史统计
```

### 7.3.1 赌局时间线示意

```text
📅 2026年6月10日（今天）
├── 14:00  🔥 进行中
│   她：「今天会下雨」 · 奖励：汉堡包🍔
├── 10:30  ⏳ 待结算
│   他：「昨晚比赛曼联赢」 · 奖励：奶茶🧋
├── 09:00  💰 待兑现
│   她赢了 · 奖励：蛋糕🍰
└── ...
```

### 7.4 解绑与回忆录数据流

```text
触发解绑
  -> 关系解除
  -> 共同日记与赌局归档
  -> 生成 memory 记录
  -> 服务端生成闪回卡片
  -> 用户通过回忆录密码访问多段历史回忆
```

## 八、数据模型概要

### 8.1 核心数据表

| 表名 | 说明 |
|---|---|
| `user` | 用户信息（openid、昵称、头像、角色标签） |
| `couple` | 情侣关系（双方 ID、绑定时间、状态） |
| `diary` | 日记条目（内容、图片、作者、时间、情侣空间） |
| `diary_delete_request` | 日记删除申请（发起方、确认状态、过期时间） |
| `bet` | 赌注主体（内容、奖励、截止时间、状态、结果） |
| `bet_message` | 赌局协商消息 |
| `blacklist` | 拉黑记录（双方 ID、冷却截止时间） |
| `memory` | 回忆录归档记录 |
| `memory_password` | 用户级回忆录密码 |
| `memory_flashback_card` | 回忆录闪回卡片 |
| `reward_blacklist` | 奖励敏感词列表 |
| `notification` | 通知消息（类型、内容、已读状态） |

### 8.2 赌注状态流转

```text
pending
  -> rejected
  -> active
  -> settling
  -> redeeming
  -> completed
  -> expired
```

状态含义详见：[打赌系统/需求设计文档](./superpowers/打赌系统/需求设计文档.md)

## 九、非功能性需求

| 项目 | 要求 |
|---|---|
| 响应时间 | 页面加载 < 2s，接口响应 < 500ms |
| 可用性 | 99.5% 以上 |
| 数据安全 | HTTPS 传输加密，密码哈希存储，敏感信息不落日志 |
| 并发 | 初期支持 1000 DAU |
| 存储 | 图片上传对象存储，单张限制 5MB |
| 消息推送 | 通过微信订阅消息实现，需用户授权 |
