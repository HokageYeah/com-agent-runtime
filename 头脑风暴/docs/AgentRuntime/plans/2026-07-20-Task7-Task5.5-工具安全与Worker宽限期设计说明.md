# Task 7 工具安全与 Task 5.5 Worker 宽限期设计说明

## 目标

在不增加第二套 Worker 状态机、后台 heartbeat 线程或可变网络路由的前提下，完成工具调用的统一安全边界，并让 draining Worker 在安全边界停止新工作、保存可信 checkpoint 后交由 reaper 接管。

## 已确认的实现选择

采用“同步安全边界 + 调用超时受宽限期限制”方案：Worker 开始 draining 后不再认领或发起新的模型、工具调用；已经开始的同步调用只在现有请求超时内返回。节点返回后，执行器复用 `LeaseService.heartbeat()` 和 `can_write()` 校验 lease、fencing、privacy、authorization、cancel；有效时仅完成当前节点的安全 Artifact/checkpoint，随后返回非终态结果，让现有 reaper 接管。

不新增后台 heartbeat 线程。该选择避免后台线程与 SQLAlchemy Session 并发访问、draining 后旧 Worker 持续写入以及第二套 lease 生命周期。长于既有同步请求超时的上游调用不在本期支持；应由 Provider/Tool 固定 timeout 先返回，再在下一安全边界处理。

## 范围

### Task 7：工具安全收尾

- 固定 HTTP Tool 继续只从 Runtime connector registry 读取 origin、method、path 和服务身份；禁止 Package 或运行输入覆盖。
- 在现有 `ToolGateway` 输出 JSON/敏感字段校验和 `AgentState.apply_tool_output()` 白名单之上，补齐工具返回写入前的运行上下文复核与取消行为声明。
- 只提供少量无网络 Native Tool：一次 JSON repair、摘要压缩、敏感扫描；LangChain 仅提供薄适配边界，不新增 Agent 动态选工具能力。
- 写工具在取消或返回不确定时继续使用现有 `ToolCallAuditService` 的逻辑操作键、原幂等键和摘要查询，不重放副作用。
- connector origin 保持既有 HTTP(S)、无 userinfo/path/query/fragment、禁重定向校验；DNS/IP 与内网部署策略只通过可注入解析器做最小 fail-closed 检查，不引入服务发现或自定义 DNS 缓存。

### Task 5.5：Worker 宽限期

- 将 draining 判定传入已存在的 `WorkflowExecutor`、`ModelGateway`、`ToolGateway` 边界，不创建第二套 Worker 状态。
- 节点开始前拒绝新调用；节点返回后若 draining，只允许通过有效 lease 写本节点安全 checkpoint，再返回 pending，禁止启动下一节点。
- 每次同步调用 timeout 不超过其固定业务 timeout、剩余 run deadline 和已确认的 draining 宽限期；宽限期耗尽时返回受控错误码，不写入后续业务状态。
- 不中断已经在 HTTP 客户端内部提交的写副作用；其结果由审计服务按原逻辑键查询恢复。

## 关键数据流

1. Worker 开始 draining，`is_draining()` 在执行器和 Gateway 安全边界返回真。
2. 未开始的节点、模型调用、工具调用被拒绝，不占用新的 permit，也不发送 HTTP。
3. 已完成的节点先经过 lease heartbeat 与 `can_write()`；失效时不写 Artifact/checkpoint。
4. 有效且 draining 时写当前节点的脱敏 Artifact、加密 checkpoint，返回非终态结果；RunQueueService/reaper 负责 lease 到期后的唯一接管。
5. 写工具的超时或取消仅写安全审计状态；恢复只查询原 operation/idempotency/digest。

## 验收与非目标

- 回归覆盖：draining 前后工具拒绝、取消语义、工具输出控制字段拒绝、节点返回后的 checkpoint 边界、宽限期 timeout 截断和旧 lease 不可写。
- 日志、Artifact、checkpoint 摘要不记录日记正文、prompt、完整播放文档或工具原始输出。
- 不实现媒体任务、动态工具选择、后台续约线程、长连接/流式调用取消、DNS 缓存或外部服务发现。
