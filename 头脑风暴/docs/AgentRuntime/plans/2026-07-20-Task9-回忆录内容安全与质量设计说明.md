# Task 9 回忆录内容安全与质量设计说明

## 目标

让 MemoirAgent 在发布前先生成可追溯但无正文泄漏的语义脱敏素材，并稳定产出符合 MVP 数量、长度、情绪安全和媒体关闭契约的播放文档。

## 已确认的脱敏策略

采用“保留引用、最小语义脱敏、敏感素材降权”：

- 每个素材保留稳定 `source_ref`、类型和最小统计信息，供后续引用校验与回忆链路追溯。
- 普通日记/赌局仅允许传入长度受限的摘要；昵称替换为“我/TA”，手机号、证件号、邮箱、地址、openid、token 和 URL 签名不进入 `sanitized_material`。
- 明确标记敏感的素材不传文本，只留下 `source_ref`、类型和 `sensitive=true`；高光、章节、场景只可降权或跳过该引用。
- 业务后端返回的未过滤敏感标识视为安全失败：只写标准错误码和计数，不保存触发内容，不调用模型。

## 工作流与状态

`workflow.graph.py` 的静态节点顺序调整为：

`load_snapshot -> sanitize_materials -> compute_stats -> extract_highlights -> plan_chapters -> generate_scenes -> generate_actions -> safety_review -> publish_document`

`AgentState.sanitized_material` 是唯一供高光/章节/场景模型节点读取的语义素材视图。原始 `snapshot` 只供 `sanitize_materials` 和计数型统计使用；日志、Artifact 和 checkpoint 摘要继续不展开两个字段的正文。

## 内容与发布约束

- 生成 3～8 张 `summary` Scene；素材不足时用无 `source_refs` 的基础卡补足 3 张。
- Scene 可选 `body` 文案最多 80 字；未接入模型正文时模板 Scene 不携带正文。
- `safety_review` 将超过 16 张的 Scene/Action 视为无效，回退为 3 张基础卡；发布前保证 `media_manifest=[]`。
- 第一版没有媒体节点；Package 的固定 fallback 已声明 `media=skipped(capability_disabled)`，播放文档显式保留空 `media_manifest`，不创建 MediaTask。
- 禁止“关系失败、责备、复合暗示”等情绪风险表达；发现后回退基础统计卡，而不是把原始文案写入错误或审计。

## 非目标

- 不保存或分享完整日记/赌局正文，不接入视觉、TTS、图片或视频生成。
- 不修改业务后端 snapshot 权限过滤，不创建动态工作流、动态工具选择、媒体队列或新数据库表。
- 不以 Runtime 日志、Artifact 或公开 callback 替代业务后端的完整作品存储。

## 验收

- 脱敏节点拒绝未过滤敏感标识，日志不回显正文。
- 敏感素材不进入模型请求数据，普通素材只以 `source_ref`/短摘要存在。
- 空素材、少素材、模型脏输出、超量 Scene、过长文案和媒体关闭均产生确定性 fallback。
- 最终发布文档包含 3～8 Scene、合法 Action、空 `media_manifest`；所有 Artifact/checkpoint 安全摘要无日记正文与 prompt。
