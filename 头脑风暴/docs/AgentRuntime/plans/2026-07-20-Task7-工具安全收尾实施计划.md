# Task 7 工具安全收尾 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将固定 `memory.*` ToolGateway、写副作用审计和 Worker 停机边界收敛为可恢复、不可越权、不会泄漏正文的执行闭环。

**Architecture:** HTTP 路径只由 Runtime 固定注册表和部署 connector 决定，拒绝自动重定向；写工具在发送前持久化运行中审计，超时只保留原幂等键供查询；Executor 在 draining 后不启动新的节点或工具，允许已完成节点完成安全 checkpoint 后交还 lease。

**Tech Stack:** Python、httpx、SQLAlchemy、pytest、现有 HMAC、ToolCallAuditService、LeaseService。

## Global Constraints

- 不新增 HTTP/模型 SDK、第二套签名、Outbox、RunRef、幂等或审计服务。
- 日记正文、Prompt、完整播放文档不得进入日志、Artifact、checkpoint 或 ToolCall 审计摘要。
- Package、工具输入和工具输出不能覆盖 archive/snapshot/run/epoch、identity、authorization、connector、privacy 或 fencing 边界。
- 共享脏工作区不 reset/checkout/自动提交；只修改本任务文件。

---

### Task 1: 固定 ToolGateway 的传输边界

**Files:** `app/runtime/tool_gateway.py`、`tests/test_runtime_snapshot_tool_gateway.py`

- [✅] 先写失败测试：固定工具面对 3xx 重定向时拒绝；connector URL 非 http(s)、缺 host 或含 query/fragment 时拒绝；读取仍只重试一次、写入仍不重试。
- [✅] 将 connector URL 在网关构造时解析为固定 origin；`_call()` 使用固定绝对 URL、`follow_redirects=False` 和已签名的固定 path，日志只包含 tool/connector/受控错误码。
- [✅] 保持现有输出 JSON/敏感标识符扫描与 Runtime context 引用来源，不为单一 connector 新建 transport abstraction。
- [✅] 定向验证：`poetry run pytest -q tests/test_runtime_snapshot_tool_gateway.py`。

### Task 2: 副作用提交前审计与未知结果恢复

**Files:** `app/agents/memoir_agent/runner.py`、`app/services/tool_call_audit_service.py`、`tests/test_memoir_publish_audit.py`、`tests/test_tool_call_audit_service.py`

- [✅] 先写失败测试：发布 HTTP 调用发生时已有可查询的 `AgentToolCall.running`；接管 attempt 保持同一 logical key/digest；timeout 或已提交成功只查询原 key，不能产生第二次写调用。
- [✅] 复用 `begin_side_effect()`，在写 HTTP 前提交运行中审计；成功、确认失败、未知结果只写脱敏摘要和标准码。
- [✅] 保持已存在的 `get_publish_result()` 对账入口，不新增通用重试循环或第二套 key 生成器。
- [✅] 定向验证：`poetry run pytest -q tests/test_memoir_publish_audit.py tests/test_tool_call_audit_service.py`。

### Task 3: Worker / Workflow 工具与 draining 安全边界

**Files:** `app/runtime/executor.py`、`app/worker.py`、必要的 `tests/test_runtime_executor.py` 或 `tests/runtime_test_worker_entry.py`

- [✅] 先写失败测试：draining 在节点边界停止新的节点/工具调用，并在此前成功节点 checkpoint 后返回非终态；失租或取消后不写 Artifact/checkpoint。
- [✅] 将 `is_draining` 以最小 callable guard 注入 WorkflowExecutor；每个节点开始前和副作用返回后复核 guard、Lease、fencing/privacy/authorization，返回安全可接管状态。
- [✅] 保持 ModelGateway 既有 draining guard，不创建全局 worker 状态机；工具取消细分与 query-after-commit 只为当前 publish 写工具提供最小实现。
- [✅] 定向验证：Worker、Executor、发布审计回归；最后全量 `pytest`、`ruff`、`git diff --check`。
