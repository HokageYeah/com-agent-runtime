## 1. 基线与替代关系

实际 Runtime HEAD `f3825266ae99a4d2f40e8aef4fd9e20843129330`，最新 Memoir 包1.0.7；M7 已部署并测试通过由用户确认，本轮未连接生产复核。既有 runner 只生成图片，图片 manifest 六键且每场景一条；`memory.enqueue_tts`禁用；OSS图片上传明确public-read；恢复时重算媒体，只有publish具备已实现的稳定幂等对账。不能把旧媒体设计中的Phase E预留当作音频已经接入。

## 2. 专属 Agent 边界与时序

新建 `app/agents/memoir_agent/1.0.8/`，复制后定向修改配置，不改1.0.0–1.0.7。包号已被占用时先重新冻结而非覆盖。Business创建Archive冻结资格并选包，Snapshot/held input不用添加前端可控资格；新包才允许音频节点。

```text
生成并覆盖修复正文 → generate_actions → enqueue_media_tasks（图片）
→ safety_review → enqueue_audio_tasks（Memoir专属服务）
→ publish_document（单次图文+成功音频）
```

`enqueue_audio_tasks`是Memoir runner识别的确定性业务步骤，沿用既有工作流节点能力，不引入公共Memoir节点类型。保留历史Business工具`memory.enqueue_tts`禁用；音频provider/转码/上传由本仓专属服务直接编排。允许Worker依赖注入、ToolGateway新包映射到现有memory wire1.1.0，不改变公共Run状态机、消息、SSE事件、callback或调度恢复语义。以后客服等Agent不加载Memoir音频规则。

只读审核后最终`scene.body`，全部成功分段拼成每场景一条MP3；生成后正文不可再改。仅生成模式每作品提交一首60秒舒缓纯音乐，固定无隐私提示词，不按场景变化。音频全部失败依然可发布完整图文，不新增整体失败状态、不后台补revision。

## 3. Provider 和私有存储

TTS采用官方HTTP/SSE `https://openspeech.bytedance.com/api/v3/tts/unidirectional/sse`，Key/resource/request-id鉴权；固定温柔淑女2.0、普通话、略慢语速。`sample_rate`位于`req_params.audio_params`，MP3/24000Hz/64000bit/s/speech_rate=-10；additions为JSON字符串，固定温柔普通话指令、`max_length_to_filter_parenthesis=0`保留括号。按句拆到每段≤200Unicode字符且≤900UTF8字节，逐段完整合成，ffmpeg解码再拼，不直接连接独立MP3字节。该分段阈值是项目策略，不冒称厂商长度上限。

收集Base64音频并验证合法帧、成功终态code20000000（官方event152）；151/153、坏帧、无终态断流或任一分段失败不得发布半段旁白。`ffprobe`测量最终时长。`X-Control-Require-Usage-Tokens-Return:*`请求实际text_words用量，原始供应商响应不入日志。

音乐使用 `https://open.volcengineapi.com/`，Action显式配置GenBGM或GenBGMForTime，API Version2024-08-12、Service imagination、Region cn-beijing；请求Text/Version=v5.0/Duration=60/EnableInputRewrite=false。存TaskID后QuerySong，0/1等待、2成功、3失败。临时AudioUrl仅内存，HTTPS与精确host白名单、每跳重定向/DNS/IP私网拒绝、字节上限和解码校验后转MP3；任务响应和URL不得入账本、checkpoint或Artifact。

Runtime使用专门private上传方法，禁止调用现有public-read图片上传后再“补改权限”；上传即private。正式背景`memoir/audios/background/`、旁白`memoir/audios/narrator/`；测试背景`memoir-test/audios/background/`、旁白`memoir-test/audios/narrator/`。拼接`<scope>/<opaque-asset>.mp3`，scope=HMAC-SHA256(专用共享key, canonical JSON数组[business_id,archive_id,run_id,generation_epoch])hex，前三字符串末整数，UTF8无空白且非ASCII不转义。与Business标准向量一致；轮换先排空在途音频作业。

私有是ACL，Business播放URL需公网可达HTTPS endpoint；Runtime上传可用网络适合endpoint，两仓bucket/角色前缀/scope须相同。Runtime需要上传与未发布资源清理权限，Business拥有发布后资源权限/生命周期，不把长期读URL放到文档。

## 4. Playback与发布

新包输出业务`schema_version=2.0.0`，图片manifest保持原六键；新增必填`audio.narrations`和`audio.background_music`。每条旁白为scene_id/media_id/object_key/mime/duration_ms五键，背景为除scene_id外四键或null；mime仅audio/mpeg、时长真实正整数毫秒，资源ID跨图/音唯一。空音频使用空数组+null，仍为2.0.0。旧文档1.0.0不改。

Runtime只发布已上传成功且正文匹配、当前lease/epoch仍有效的资源。Business按冻结资格+生产者包+scope校验，公开投影去掉object_key，不持久签名URL。Business按header协商向旧客户端返回原图文v1；owner/visitor媒体授权POST路径、revision/错误码/TTL以Business主设计§4–5为准。前端两个音轨负责混播，Runtime不预混背景到每场景旁白，也不输出串行play_tts阻塞画面。

主Agent持有两仓`tests/fixtures/memory_playback_shared_v2.json`（Business位于后端根）；包含内部/公开v2/v1投影、错误资源、scope标准向量、重复正文不同scene、授权成功失败。旧fixture不覆盖，公共wire不升版。

## 5. 副作用账本、预算与恢复

新建Memoir专属音频作业表，属于Runtime执行元数据而非业务作品表，禁止存正文、私有URL、prompt、音频字节。最小字段：job_id、business_id、run_id、generation_epoch、package_version、role、scene_id（BGM为空）、segment_index、input_hmac、attempt、state、provider_task_id、object_key、mime、duration_ms、reserved_cost/settled_cost/currency、usage_text_words/requested_music_seconds、lease fencing token、expires_at/created_at/updated_at、固定error_code。最终场景资产与分段提交使用同表不同role，临时分段不上OSS，记录只承担用量与副作用追踪。

唯一键含run/epoch/package/role/scene/segment/input HMAC；BGM用作品级固定槽，scene/segment以显式哨兵参与唯一约束，不能依赖数据库NULL相等语义。不同场景相同正文不共享media_id。input HMAC覆盖完整正文、分段规则版本及所有声音参数；媒体ID和对象键在上传前固定，恢复可对账同一个对象，不因重试UUID产生未知孤儿。

状态：reserved → submitting → submitted（音乐已知TaskID）/processing → uploaded → published；终结分支failed/cancelled/submission_unknown/cleaned。提交前原子占作业槽和费用预留，提交返回立即存安全TaskID；网络可能已接受但响应/保存未知时标submission_unknown，不自动重提收费。只有明确未受理限流或连接前失败可一次退避重试；已知TaskID只查不重建。TTS SSE不可断点续传，未知状态的整个场景降级，不能重新付费补齐。已成功整场景资产可同Run同输入复用；未完成分段恢复不能假定临时文件仍存在，不为缺临时文件自动重新收费。

每次请求/查询/上传前检查取消、当前lease/fencing、隐私授权/epoch和剩余deadline；旧worker不能写入新owner结果。临时文件限权限随机名，finally清理，转码子进程有超时与取消终止，stderr只映射安全枚举。节点返回仅安全资源引用及有界计数，不把字节或正文存checkpoint。

新包Run1200秒；音频最多300秒且留下30秒发布预算，单TTS45秒；最多2场景+1音乐并发，进程全局默认4，扩容按账号配额收紧。图文节点也受新Run剩余deadline约束。任一音频门禁/时间/单价配置不足，停止未提交工作、保留成功资源并发布图文；不得扩展无限等待或重复收费。

使用Decimal费用，音频账本独立封顶，不将字符伪装token，不改公共AgentModelUsage schema。各分段提交前按完整输入和已确认计费口径保守预留；重试重新预留，每次真实提交都占预算；按text_words/音乐请求秒数结算。未知结果或缺用量不释放预留且标pending reconciliation，避免并发透支；不能以缺用量为0。若所用计费口径不能给出保守上界则不提交，先补配置/官方证据。Budget原子更新与任务唯一键在同事务，禁止多个场景各自读取旧余额。实际费用不承诺仅凭本地预算达到供应商硬封顶，账号控制台配额也须设置。

上传未发布资源由音频维护命令对账，先使用既有publish query确认；已发布保留并移交Business生命周期，不确定保留；明确未发布且超过MEMOIR_AUDIO_ORPHAN_RETENTION_HOURS（默认24小时）的资源才删，404视为成功。不得按超时盲删可能发布的文件。Business删除/隐私撤回通过其purge_audio Outbox处理指定revision；关闭分享不删owner资源。账本清理仅在无在途作业、无未结算费用且对象已移交/删除后按运维保留策略进行，不在本期引入通用数据清理平台。
