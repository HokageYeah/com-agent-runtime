> 收尾设计；目标架构中 Archive/Snapshot/PlaybackDocument 由 `couple-diary-b`
> 持有。本仓只保留迁移与兼容证据。后续 `memoir_agent@1.0.5` 不改变

> [通用受控循环与 Memoir 动态生成设计说明](./2026-08-31-通用受控循环与Memoir动态生成设计说明.md)，

## 目标

在既有双方 Archive、加密 Snapshot、revision 0 baseline 与原子发布实现上，补齐数据契约、素材引用和生命周期边界，使回忆录能安全支持后续隐私删除、对账、用户详情与播放器。

## 已有基础与范围

现有 `MemoryArchiveService` 已在同一业务事务创建双方独立归档、版本 1 加密快照与 revision 0；`MemorySnapshotMaterializer` 已按关系段、解绑截止时间和删除状态读取情侣日记库；`MemoryPlayerService` 已按 `published_revision` 读取完整作品。

本块不实现 Runtime purge 请求、用户密码/API、播放器、媒体任务、动态 LangChain 包装或连接后对端 IP 校验。这些分别留给 Task 10.5、10.75/11、7/8。

## 方案选择

采用“复用现有表和服务，按三段串行收口”的方案：

1. 为已有模型补充必要字段、数据库约束和版本校验，而不新建第二套 archive/snapshot 容器。
2. 在现有完整文档发布事务中校验并写入 Scene/Action/source-ref 映射；映射只保存素材类型和 ID，不保存素材正文。
3. 在现有发布指针模型上增加 superseded revision 的可回收标记与最小 GC 服务；隐私删除的写屏障和 Runtime 对账仍由 Task 10.5 实现。

未选择建立独立“索引服务”或通用 schema 引擎：当前只需要随发布事务写入和按来源反查的关系表/等价映射，额外服务会扩大一致性和运维面。

## 数据与安全边界

- `MemorySnapshot` 继续只持久化加密 payload、冻结 manifest/hash、过滤版本、截止时间与版本；解密仅限 Memory service 和内部工具身份。
- Scene 类型固定为 `cover/stats/diary_highlight/bet_highlight/image/milestone/summary`；安全等级固定为 `normal/sensitive/fallback`；Action 类型固定为 `show_card/focus_image/type_text/hold/play_tts/transition`。
- 发布时每个 AI Scene 的 `source_refs_json` 必须属于当前 Snapshot canonical allowlist，前缀只允许 `diary/completed_bet/handbook_note/matured_wish/bucket_list_completion`；旧 `bet:<id>` 仅能在 legacy reader 内单向归一化为 `completed_bet:<id>`，新发布不得回写旧前缀。同时写入可按来源反查 archive/revision 的最小映射。日志只记录 archive、revision、数量和错误码。
- `MemoryArchive` 的 `content_status` 仅由 baseline/原子发布/受验签 callback 投影更新，`generation_status` 继续在读取层由 content/enhancement 派生，不落为第二个可竞争写入字段。
- 播放器读取始终从 archive 的 `published_revision` 取得同一 document 下的 Scene/Action；禁止草稿或跨 revision 拼接。
- 普通替代版本在 `retain_until` 后才可删除；本块仅提供幂等候选清理。删除 archive 的立即撤权、generation epoch 递增、Runtime purge 与确认完成由 Task 10.5 负责。

## 实施分段

### 第一段：模型契约与冻结快照

审计并补齐 Archive、Snapshot、RunRef 的缺失字段/唯一约束和注释；补 Snapshot/文档/场景/动作的 schema major 读取校验。测试冻结输入变化拒绝覆盖、双方隔离、截止时间和 source manifest/hash。

### 第二段：发布校验与 source-ref 反查

在 `publish_playback_document()` 内验证完整 document 的场景、动作、引用和持续时间；同一事务写入 document、scene、action、source-ref 映射并切换 published 指针。测试非法引用不写入、跨 snapshot 引用拒绝、同源素材可定位已发布 revision。

### 第三段：版本读取与回收

为旧 revision 设置 `retain_until`，提供只删除非发布且到期版本的幂等 GC；详情读取同时取回同 document 的 Scene/Action。测试 revision 指针一致性、重复 GC 无副作用和未到期/当前发布版本不删除。

## 验收标准

1. 冻结输入、加密快照和双方 Archive 在重复触发下保持幂等，冻结边界外的素材不会进入快照。
2. 发布只接受固定 schema、合法 action、当前 Snapshot 五类 canonical allowlist 内的 source ref，并在失败时不切换 published revision；Scene 数不在业务发布层设置 8/16 的产品上限。
3. 详情不会混读 revision；清理不会删除当前版本或越过 retain window。
4. 测试、Ruff 和 `git diff --check` 通过；日志、Artifact、checkpoint 不出现日记正文、prompt 或完整播放文档。
