# Task 6.5 归档、快照与播放文档收尾 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将回忆录 Archive、加密 Snapshot 与 PlaybackDocument 补齐为可校验、可按素材反查、可安全读取和回收的业务底座。

**Architecture:** 复用 `MemoryArchiveService`、`MemorySnapshotService` 与 `MemoryPlayerService`，不引入第二套容器或索引服务。发布在已有数据库事务内校验当前 Snapshot manifest、落 Scene/Action/source-ref 映射后再切换 `published_revision`；GC 只删除非发布且已过 `retain_until` 的完整 revision。

**Tech Stack:** Python 3.13、SQLAlchemy、Alembic、MySQL JSON/SQLite 测试、Pydantic、pytest。

## Global Constraints

- 共享脏工作区：不得 reset、checkout、自动提交或删除其他人的改动。
- 回忆录素材来自情侣日记现有数据库表；Snapshot 仅通过冻结 manifest 获取，不扫描任务期间新增素材。
- 日志、Artifact、checkpoint、异常信息不得记录日记正文、prompt、完整播放文档、密钥或签名 URL。
- 复用现有 Fernet、IdempotencyService、RunRef 与 `published_revision` 指针；不新增依赖、后台线程或通用 schema 引擎。
- 所有新增模型字段、方法和安全分支使用中文注释；日志仅记录 archive/revision/count/error_code 等安全摘要。
