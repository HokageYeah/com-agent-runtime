# 回忆录媒体通道设计说明（M6 / Phase D）

> **2026-08-26 当前版本校准：** 本文原始方案对应 `memoir_agent@1.0.3`，
> 当前代码已发布 `1.0.4`。`1.0.4` 从“仅 `image` Scene 可配图”
> 放宽为“任意 Scene 均可按 `body` 配图”，同时取消场景总数和
> `body` 字数上限，只保留至少 3 个场景。这是 AgentPackage 行为
> 放宽，播放文档 `schema_version=1.0.0`、payload 两键白名单、
> manifest 六键结构和 Tool wire `1.1.0` 都没有改变。`1.0.3` 及以前
> 继续执行最多 8 个场景、单场景最多 80 字的冻结合同。
> 当前实现只使用场景文案做文生图，不读取用户照片，不执行图生图。

## 目标

为 MemoirAgent 生成的回忆录作品补齐图片媒体通道：场景规划后、发布前，按场景 `body` 生成配图，经阿里云 OSS 公共客户端上传，URL 随 `memory.publish_playback_document` 原子发布进业务侧 `media_manifest` 列。本文最初是 2026-08-20 的设计增补，**同日 D2 已按本文实现并经测试验证**（任务勾选见下）；当前内容已按现行实现校准，是 Runtime 侧 D2 的设计事实源。

## 已有基础与范围

已预留的骨架（零契约变更即可复用）：

- `image` Scene 与 `focus_image` 动作词表三端冻结；evaluator `_CAPABILITY_ACTIONS` 门控已按能力放行；
- `enqueue_media_tasks` 节点已从发布后移到 `generate_actions` 与 `safety_review` 之间，`state.media_tasks` 承载发布前生成的 manifest；
- 业务表 `memory_playback_documents.media_manifest` 列已存在，当前会与文档、Scene 和 Action 在业务侧一个事务中发布；
- `app/utils/aliyun/oss_client.py` 公共客户端已具备文件上传与预签名能力，配置键已进 `app/core/config.py`（见 `ENV_CONFIG.md` §9.3）。

不在本块范围：TTS/音乐/视频生成（Phase E，条目 schema 已为其预留 `audio/video` kind）；S3 私有媒体代理通道（§9.1/9.2，服务对象是用户私密媒体，与本文公共读生成图通道互不混用）；前端渲染（D4，属情侣日记仓）。

## 方案选择

采用“同一节点单通道分支 + 一次冻结条目 schema”的方案：

1. **生成时机与等待语义**：`generate_scenes` 之后、`publish` 之前按场景串行执行，不是多图并发。`1.0.3` 的场景数是 3–8；`1.0.4` 可有更多场景。图片张数不再读取历史 `model_policy.max_media_images`，唯一批次上限是 `MEMOIR_MEDIA_NODE_BUDGET_SECONDS` 的墙钟预算；每张完成后续约 lease，预算耗尽或续约被 fencing 拒绝后，剩余场景降级文字卡。不引入异步二段 revision：媒体节点仍会增加 Run 的发布前耗时；“失败降级”是指图片失败不会让文字作品发布失败，不代表图片生成与发布并行。
2. **单通道文生图**：在既有 `enqueue_media_tasks` 节点内，只把场景 `body` 与固定风格指令组成 prompt，调用文生图 Provider。Snapshot 中即使有照片元数据也会忽略，当前无照片下载器、无图生图分支、无用户照片出域。
3. **降级阶梯**：单张失败/超时 → 该 Scene 降级文本卡（manifest 不含该条目）；全部失败 → 发布纯文字 revision（即现状）。任何图片异常都不产生重试节点、不回滚已生成文案。
4. **存储**：OSS 上传至 `memoir/images` 前缀（`memoir/videos`、`memoir/audios` 为 Phase E 预留）；object_key = 前缀 + 不可猜测 UUID；桶保持私有、**对象级公共读 ACL**；落库与下发用公共读 URL，预签名 URL 有时效不落库。
5. **兼容**：播放文档 `schema_version` 维持 `'1.0.0'` 不升版；老小程序包精确匹配失败时按既有降级路径渲染文本卡。

## 火山引擎接入事实（历史调研与当前取舍）

- 火山视觉智能 3.0 使用两段式异步接口：先以 `Action=CVSync2AsyncSubmitTask&Version=2022-08-31` 提交任务并取得 `task_id`，再以 `Action=CVSync2AsyncGetResult&Version=2022-08-31` 查询 `in_queue/generating/done` 状态；两次请求都按各自 canonical query 重新计算 AK/SK HMAC-SHA256 签名；
- 当前实现只调用文生图 `req_key: high_aes_general_v30l_zt2i`。历史调研过的 `seededit_v3.0` 图生图路线没有进入当前服务，不得据此向 Runtime 传照片；
- 查询接口不传可选 `req_json.return_url`，直接读取 `binary_data_base64`，避免临时 URL 下载与外泄面；
- `AgentModelUsage.image_count` 已落地，仅成功交付计为 1 张；当前这是计量和成本观测字段，不是张数配额器。

## 安全与隐私边界

- **用户照片不出域**：当前媒体服务不接收照片加载器，不读取 Snapshot 照片，Provider 请求只携带由场景正文构造的最小 prompt。未来若新增图生图，必须作为新能力重新设计授权、数据驻留、审计和独立开关，不得视为当前隐含能力。
- **出域内容最小化**：图像 prompt 只含场景摘要与风格指令，不含来源 ID、账号标识与完整正文；prompt、图片字节、临时 URL 不进入日志、trace、checkpoint、callback、Artifact 或测试输出。
- **计量与资源闸门**：成功交付的图片按张进 ModelUsage 结算；当前忽略历史 `model_policy.max_media_images`，不设图片张数配额。节点时间预算、逐张 lease 心跳/fencing 和 Provider 自身容量是实际闸门；预算内未完成的场景降级文字卡。
- **URL 边界**：公共读 URL 只写入结构化白名单字段（manifest 条目与 image payload）；scene `body/title` 禁 URL 的既有防护不变。
