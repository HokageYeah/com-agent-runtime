# 多 Agent 注册收口开发计划

编写日期：2026-10-27。前置：[QA Agent 接入计划](2026-10-27-QA-Agent接入与公共Runtime最小解耦开发计划.md) T0–T6 已全部完成，工作区尚未提交。设计依据：[08-多Agent扩展性与目录评审](../../hucci-agent设计思路/08-多Agent扩展性与目录评审.md)。

## 0. 目标

**新增一个 Agent 时，只新建 `app/agents/<agent_id>/`，并在 `app/agents/registry.py` 中加一行；不修改任何其他公共文件。** Memoir 和 QA 的行为、包内容、digest、对外契约全部不变。

**非目标：**不重组 `app/runtime/` 目录；不移动 Memoir 的守卫、评价器、媒体和音频服务；不移动测试设施文件；不新增流式输出、条件分支等执行能力；不改动 `MEMOIR_*` 配置。

## 1. 全局约束

沿用 [QA 接入计划](2026-10-27-QA-Agent接入与公共Runtime最小解耦开发计划.md) 第 2 节的全部约束（Memoir 零回归、安全门禁只能收紧、可信注册只来自代码、隐私边界、不做迁移、不做 Git 写操作、中文注释、TDD、不顺手改动），以及该计划第 5、5.1 节的执行与审核协议。补充两条：

- **兼容别名：**已有的公共导入路径（例如 `app.runtime.tool_gateway.AgentToolProfile`、`app.agents.output_targets.AGENT_TOOL_OUTPUT_FIELDS`、`app.worker.configured_memoir_executor`）如有测试或代码在用，保留为薄别名；没有调用方的就直接删除，不留死代码。
- **基线：**审核方在沙箱外的全量结果为 1417 passed / 0 failed / 20 skipped（只因缺 DSN）；mypy 有 19 个历史错误。Codex 沙箱内会多出 1 个回环端口失败和 8 个跳过，属于环境限制。

## 2. 任务

### R1 注册描述与可信注册表

1. 新建中立模块 `app/runtime/agent_registration.py`，放置以下内容：
   - `AgentToolProfile`，从 `tool_gateway.py` 移入，原位置保留别名；
   - `AgentRegistration(agent_id, tool_profiles: Mapping[business_type, AgentToolProfile], tool_output_fields, executor_factory_loader)`。`executor_factory_loader` 是一个无参函数，调用时才 import 该 Agent 的 bootstrap，避免在 API 进程或注册脚本中加载 Worker 依赖。
   - 该模块不得 import 任何具体 Agent，也不得 import `app.worker`。
2. 新建 `app/agents/memoir_agent/registration.py` 和 `app/agents/qa_agent/registration.py`，内容与现有登记逐项一致。R1 阶段 loader 仍指向 `app.worker` 中现有的工厂，工厂在 R2 再迁移。
3. `app/agents/registry.py` 改为：
   - 维护一份可信清单 `REGISTRATIONS`，每个 Agent 一行；
   - 提供 `is_executable_agent`、`get_executor_factory`、`get_tool_profile(agent_id, business_type)`、`get_tool_output_fields(agent_id)`；
   - 清单中出现重复 `agent_id` 时，在 import 阶段直接报错。
4. 消费方改为查询注册表：
   - `tool_gateway.py` 删除 `_AGENT_TOOL_PROFILES` 和对 `qa_agent` 的 import，改用 `get_tool_profile`，判断逻辑和错误码不变；
   - `schemas/agent_package.py` 改用 `get_tool_output_fields`，`ToolManifest` 单独构造时的“并集校验”保持不变；
   - `output_targets.py` 按兼容别名规则保留或删除。
   - 注意循环导入：`schemas`、`tool_gateway` 与注册表之间的导入链必须能一次加载成功。
5. **测试**
   - 注册表：查询结果正确；重复登记会报错；未登记 Agent 返回 None。
   - 现有的 ToolGateway 档案测试、输出目标测试、注册表测试全部通过。
   - 公共内核 `tool_gateway.py` 不再 import `app.agents.qa_agent` 或 `app.agents.memoir_agent`（用测试断言）。

**验收：**新增测试和全量测试通过，结果与基线一致；ruff 通过；mypy 不新增错误；Memoir 1.0.0–1.0.8 和 QA 1.0.0 的 digest 不变。

### R2 装配下沉与通用模型路由配置

1. 在 `app/worker.py` 中抽出公共构建函数，Memoir 和 QA 不再各自重复装配代码：
   - `build_tool_gateway(session, agent_run, connector_config, lease_context, *, is_draining, dependencies, runtime_settings)`：统一构建 ToolGateway，包括授权复核、执行许可、拒绝审计、peer transport、测试 transport 和私网放行开关；
   - `build_checkpoint_store(session, runtime_settings)`；
   - 已有的 `build_model_gateway` 保留。
2. 把 Memoir 工厂迁到 `app/agents/memoir_agent/bootstrap.py`，把 QA 工厂迁到 `app/agents/qa_agent/bootstrap.py`。迁移时：
   - 业务逻辑原样搬过去，只把公共装配部分改为调用第 1 步的函数；
   - Memoir 中 `configured_model_gateway`、`configured_media_service`、`configured_audio_service` 这些只有 Memoir 使用的装配函数一并迁入 Memoir 的 bootstrap，Worker 中保留兼容别名（前提是仍有调用方）；
   - 两个 Agent 的 `registration.py` 中的 loader 改为指向各自的 bootstrap。
3. `app/worker.py` 不再 import 任何具体 Agent。
4. 现有测试中 `monkeypatch.setattr(worker, "MemoirNodeRunner", ...)` 一类的替换，改为替换新模块中的符号；只改替换目标，不改断言。
5. **通用模型路由配置**
   - 新增 `AGENT_MODEL_NODE_ROUTES_JSON`，格式为 `{"<agent_id>": {"<node_id>": "<route_id>"}}`，必须是严格的 JSON 对象，解析失败时报错，不输出配置值；
   - 提供按 `agent_id` 取节点路由的方法；
   - QA 改为读取 `AGENT_MODEL_NODE_ROUTES_JSON["qa_agent"]`，节点集合仍必须恰好为 `{"compose_answer"}`；
   - 删除 `QA_MODEL_NODE_ROUTES_JSON` 字段，同步更新 `.env.example`、`docker/backend/*.env.example`、`ENV_CONFIG.md`、`tests/conftest.py`；
   - `MEMOIR_MODEL_NODE_ROUTES_JSON` 保持不变。
6. **R1 审核遗留（并入本任务）**：`app/runtime/tool_gateway.py` 第 72–74 行为了给历史测试保留别名 `_TOOL_WIRE_VERSION_BY_AGENT_VERSION`，在公共内核里按名字查询 `memoir_agent`，而且用了模块级 `assert`。该别名只有 `tests/test_runtime_contract_compatibility.py` 和 `tests/test_runtime_capabilities.py` 两个测试在用。处理方式：把这两个测试改为从 Memoir 的注册描述读取 wire 表（断言内容不变），然后删除别名和 `assert`。
7. **测试**
   - 公共构建函数：沿用两个 Agent 的工厂测试证明行为不变，另补构建函数的单元测试；
   - 通用配置：合法、非法、缺少 agent 键、节点集合不符，四种情况；
   - `app/worker.py` 不 import 具体 Agent（用测试断言）。

**验收：**全量测试通过，结果与基线一致，其中 Memoir 的 Worker、版本和跨项目桥接测试必须全部通过；ruff 通过；mypy 不新增错误；digest 不变；`app/worker.py` 行数明显下降（在回执中报告前后对比）。

### R3 护栏测试、接入指南与文档

1. **架构测试** `tests/test_agent_architecture_boundaries.py`：通过 AST 扫描，断言以下位置不 import `app.agents.<具体 Agent>`：
   - `app/runtime/`；
   - `app/schemas/`；
   - `app/worker.py`；
   - `app/api/`；
   - `app/services/` 中除 `memoir/` 子目录以外的部分；
   - `app/core/`。

   `app/agents/registry.py` 和各 Agent 自己的目录不在检查范围内。
2. **注册一致性测试** `tests/test_agent_registration_consistency.py`：遍历 `REGISTRATIONS` 中的每个 Agent，确认：
   - 至少有一个包版本，并且所有版本都能加载；
   - 包里 HTTP 工具的名称都在该 Agent 的工具档案中，且符合工具名前缀；
   - 包里的 `output_to` 都在该 Agent 的允许字段内；
   - `executor_factory_loader()` 能解析出可调用对象；
   - 包的 `allowed_business_types` 都有对应的工具档案（如果包声明了工具）。
3. **接入指南** `app/agents/README.md`，内容包括：
   - 目录约定：`registration.py`、`bootstrap.py`、`runner.py`、版本包目录；
   - 版本包必须包含的文件；
   - 注册步骤：在注册表加一行；
   - 配置方法：connector 配置和 `AGENT_MODEL_NODE_ROUTES_JSON`；
   - 必须遵守的安全约束：私有状态只放内存、checkpoint 白名单、幂等提交、配置缺失时明确失败；
   - 必须通过的测试；
   - 以 QA 作为参考实现；
   - 当前不支持的能力（流式输出、条件分支、公共 TTS），并链接 08 文档。
4. 文档更新：
   - `VERIFICATION.md` 新增本计划的验证一节，只写真实执行过的命令和结果；
   - `ENV_CONFIG.md` 补充 `AGENT_MODEL_NODE_ROUTES_JSON` 的说明；
   - 本计划第 4 节勾选完成。

**验收：**两个护栏测试通过。另外要做一次**故意违规验证**：临时在公共文件中加一个违规 import，确认架构测试会失败，然后恢复。回执中写明执行步骤，并确认文件已经恢复。全量测试、ruff、mypy、`git diff --check` 和链接检查都通过。

## 3. 执行方式

与 QA 接入计划第 5.1 节相同：执行方是 Codex，使用 `-m gpt-6.1-sol -c model_reasoning_effort='"high"'`，沙箱为 workspace-write，每个任务开一个新会话。审核方负责审核并在沙箱外补测，每个任务审核通过后才能开始下一个。模型和思考强度的这个设置只对本计划生效。
