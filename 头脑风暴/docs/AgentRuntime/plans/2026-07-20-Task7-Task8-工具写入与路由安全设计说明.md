# Task 7 工具写入与 Task 8 路由安全设计说明

## 目标

让工具输出只能在有效 lease 下写入明确的 AgentState 字段，并让模型/业务 connector endpoint 在 Runtime 配置期和请求前以 fail-closed 方式拒绝不安全地址。

## 工具结果写入

- Tool 输出先经过 manifest `output_schema` 的最小 JSON 对象校验、已有敏感标识扫描和 `AgentState.apply_tool_output()`。
- 写入前复用 `LeaseService.can_write(run_id, context)`；fencing、privacy、authorization、cancel 或 lease 失效时丢弃输出，不写 AgentState、Artifact、checkpoint 或 callback。
- 写副作用结果不重新发送；继续由 `ToolCallAuditService` 以原 logical operation key、idempotency key、request digest 查询恢复。
- 不创建工具专用状态机、审计表或第二套 fence validator。

## Endpoint 安全

- 只接受管理员注册的 HTTP(S) endpoint；拒绝 userinfo、query、fragment、loopback、unspecified、multicast、link-local、private/reserved IP 字面量与本机 hostname。
- 注册期和请求前都对 hostname 做标准库解析；任一结果不安全即拒绝，不记录 endpoint secret 或请求正文。
- connector 的固定 origin、HMAC 和禁重定向维持现有实现。
- 真实 DNS rebinding 的“连接后实际对端 IP”验证需要自定义 transport 或部署 egress policy，本轮不实现且总控保持未完成。

## 非目标

- 不新增服务发现、DNS 缓存、动态 endpoint、动态工具选择或新的第三方依赖。
- 不改变 ProviderTrafficController、Admission、ToolCallAudit 与现有 Route permit 语义。
