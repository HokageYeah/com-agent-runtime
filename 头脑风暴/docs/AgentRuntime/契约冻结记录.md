## 已冻结的边界

- Runtime API：健康检查、capabilities，以及 AgentRun 的 create/start/query/retry/cancel/human-approval/purge 请求与响应模型均使用 `contract_version=1.0.0`。
- 状态与调度：Run 状态、`held -> queued -> claimed -> finished` 调度状态、held create/start、独立 active/held/queue/approval/wall-clock 时间预算遵循总控计划第 3 节。
- 事件：详细 RuntimeEvent 只映射到安全 callback 事件；模型、工具内部事件统一压缩为 `step_changed`，`waiting_human` 只允许显式启用该能力的 Package 使用。
- 工具与产物：Business Tool 只允许可信 connector 的相对路径，预留 MCP 元数据但不连接 MCP；Artifact 只保存版本、摘要、digest 和业务资源引用。
- 安全与可靠性：签名原文为 `{method}\n{path}\n{timestamp}\n{body_sha256}`，默认时间容忍 300 秒；写请求按 client + scope + key 幂等，request hash 覆盖 method、包含资源 ID 的 normalized path 和 body hash；事件序号在单个 Run 生命周期内单调递增。
- 并发与隐私：Worker 使用 lease/heartbeat/fencing 和 execution attempt；副作用键使用稳定逻辑操作键，不能包含物理 attempt；privacy version、authorization version、trusted/untrusted envelope 与语义校验是后续所有写入的前置条件。
- 生命周期与审计：Package 生命周期固定为 active/deprecated/revoked；AuditEvent 只记录无私密内容的操作摘要，生产环境必须具备持久且访问受限的审计 sink 才能 ready。

## 兼容性规则

- 新增 optional 字段可在同一 major 内发布；删除 required 字段、改变枚举含义或改变既有字段类型必须提升 major。
- `memoir_agent@1.0.0` 是首个 Workflow AgentPackage；第一版不支持 ToolLoopAgent、动态 Agent、完整 MCP 与 Runtime 原生 SSE。
- Runtime 模块固定在当前 com-agent-runtime 根工程的 `app/` 目录，运行权威库将在下一任务以 SQLAlchemy/Alembic 落地，不连接情侣日记业务数据库。
