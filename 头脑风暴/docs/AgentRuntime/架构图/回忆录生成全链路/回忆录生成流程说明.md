# 回忆录生成流程说明（小白版）

配套时序图：[memoir-generation-flow.html](./memoir-generation-flow.html)

一句话总览：**用户点击生成 → 业务后端建作品秒回 → 后台 Worker 委托 Runtime 跑 Agent → Agent 调模型写好回忆录 → 原子发布 → 前端轮询拿到作品播放**。

前端永远只调业务后端（couple-diary-b），从不直连 Runtime；Runtime 也只通过约定的工具接口/callback 回业务后端，不直连业务数据库。

## 四步流程（人话版）

### ① 创建：点击生成，接口秒回

用户在小程序点「生成回忆录」，前端调业务后端的创建接口。后端在同一事务里做资格校验、防重复（幂等键），建一个 rev 0 的 baseline 作品（Archive）和一个待物化的快照任务（Snapshot），然后**立刻返回**。重的活全部扔到后台。

### ② 启动：业务 Worker 两段握手委托 Runtime

业务 Worker（后台进程）先物化快照（把五类素材冻结、加密），然后和 Runtime 做「两段握手」：

1. **held create**：先在 Runtime 占个位（拿到 run_id，但不开始跑，不占生成配额）
2. **CAS 绑定**：回业务库原子地把 run_id 绑到 Archive 上；绑定失败就把孤儿 run 取消清掉
3. **start**：绑定成功后才真正启动

这样崩溃重启不会留下「跑了却没绑上」的脏数据。

### ③ 生成：Runtime Worker 跑十节点工作流

Runtime Worker 认领这个 run，按 MemoirAgent 1.0.7 的十节点工作流执行（支持 checkpoint 续跑，崩溃不重头）：

读脱敏素材 → 清洗 → 统计 → 分批调模型生成场景 → 缺失补齐 → 生成动作 → 媒体任务排队 → 安全审查 → **原子发布**

其中两次回调业务后端的内部工具接口：读素材（get_snapshot）、发布作品（publish_playback_document）。

### ④ 播放：前端轮询拿作品

前端退避轮询业务后端的 generation-status，看到 succeeded 就拉 playback，播放器按 Scene 逐卡展示。生成失败则展示 rev 0 baseline，可重试。

## 谁拥有什么（边界速记）

- 业务仓拥有：Archive（作品）、Snapshot（素材快照）、PlaybackDocument（播放文档）、所有用户数据
- Runtime 拥有：AgentRun（运行记录）、Plan/Step（计划步骤）、Checkpoint（断点续跑）
- 两仓之间只走三条通道：**HMAC 签名的 Runtime API**（业务→Runtime）、**内部工具端点**（Runtime→业务）、**状态 callback**（Runtime→业务）
