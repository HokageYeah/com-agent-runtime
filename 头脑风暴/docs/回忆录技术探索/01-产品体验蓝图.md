# 01-产品体验蓝图

## 一、体验目标

回忆录详情页要像一部私密的年度回顾，而不是数据报表。用户输入密码后，看到的是系统为某段关系整理出的回忆作品：有开场、有章节、有高光、有停顿，也有克制的结尾。

首期可以先做卡片轮播。高阶版本再叠加旁白、图片运动、AI 封面、短视频、H5 分享页。

## 二、用户入口

```text
我的页
  -> 回忆录入口
  -> 设置或输入独立密码
  -> 回忆录列表
  -> 点击某段回忆
  -> 进入回忆作品播放器
```

列表项继续沿用既有需求：

- 对方昵称和头像
- 关系时间范围
- 共同记录摘要
- 封面图
- 置顶与删除

高阶版本可增加生成状态：

| 状态 | 展示 |
|---|---|
| 生成中 | “正在整理这段回忆” + 轻动画 |
| 已生成 | 显示封面、标题、摘要 |
| 部分生成 | 显示基础卡片，并提示部分媒体稍后补齐 |
| 生成失败 | 显示基础统计卡入口，提供重试 |

## 三、播放器体验

### 3.1 页面结构

```text
顶部：返回 / 进度 / 静音
中间：沉浸式闪回卡片
底部：上一张 / 暂停播放 / 下一张 / 重新播放
隐藏操作：长按保存封面、分享前确认隐私
```

### 3.2 播放节奏

一段作品建议控制在 8 到 16 张场景卡。数据少时保底 3 张，数据多时系统筛选高光，不做无限长列表。

推荐结构：

1. 封面卡：标题、关系时间、对方信息。
2. 开始卡：从哪一天开始记录。
3. 统计卡：持续天数、日记数、赌局数。
4. 共同日常卡：双方同日记录、常见关键词。
5. 图片回忆卡：图片日记或默认插画。
6. 赌局高光卡：最热闹、最有趣、已完成赌局。
7. 兑现卡：兑现率、完成过的小约定。
8. 总结卡：温和收束，不评价关系好坏。

### 3.3 交互模式

| 模式 | 说明 |
|---|---|
| 手动浏览 | 用户左右滑动或点击上一张/下一张 |
| 自动播放 | 按动作脚本播放，每张卡有停留时间 |
| 旁白模式 | 有 TTS 时播放旁白，无 TTS 时使用文字浮现 |
| 静音模式 | 只展示画面、打字和转场 |
| 低配模式 | 关闭视频和复杂动画，仅保留卡片轮播 |

## 四、内容样例

### 4.1 封面卡

```text
《我们认真记录过的 286 天》
2025.03.14 - 2025.12.25
这是一段只属于你和 TA 的回忆。
```

### 4.2 统计卡

```text
这段时间里，你们写下了 124 篇日记。
其中有 37 天，两个人都留下了记录。
最常出现的词是：火锅、晚安、散步。
```

### 4.3 赌局高光卡

```text
有一场赌约很热闹：
“谁会先睡着”

它从晚上开始，最后变成了一次小小的兑现。
你们一共完成了 18 个赌约，兑现率 94%。
```

### 4.4 数据少时兜底卡

```text
这一段记录不算多。
但系统仍然记下了它开始和结束的时间。
有些关系没有留下很多文字，也曾真实发生过。
```

## 五、视觉方向

### 5.1 风格

- 温暖、私密、柔和。
- 避免过度婚恋化和纪念碑感。
- 避免“复盘分手”的审判语气。
- 颜色以浅色、低饱和、柔和对比为主。

### 5.2 卡片组件

| 组件 | 用途 |
|---|---|
| 封面卡 | 开场、标题、关系时间 |
| 数据卡 | 持续天数、日记数、赌局数 |
| 引用卡 | 摘录短日记，不展示长原文 |
| 图片卡 | 展示图片日记或 AI 封面图 |
| 赌局卡 | 展示赌局内容、结果、奖励 |
| 总结卡 | 结尾和情绪收束 |

## 六、分享策略

高阶版本可以生成可分享 H5，但默认关闭。分享前必须让用户确认：

- 分享页会展示哪些卡片。
- 是否包含对方昵称和头像。
- 是否包含原文摘录。
- 分享链接是否有过期时间。

推荐默认只分享“脱敏作品”，不暴露完整日记、赌局详情和对方可识别信息。
