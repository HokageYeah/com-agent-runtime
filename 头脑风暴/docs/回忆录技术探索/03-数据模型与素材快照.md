# 03-数据模型与素材快照

## 一、归档边界

一段回忆的业务边界由以下字段锁定：

```text
space_id + relationship_segment_no + owner_user_id
```

- `space_id` 表示同一对用户的稳定双人空间。
- `relationship_segment_no` 表示这对用户第几段绑定关系。
- `owner_user_id` 表示当前查看者。双方各有一条独立回忆记录。

同一对用户多次分合时，系统复用 `space_id`，但每次新绑定递增 `relationship_segment_no`。回忆录生成某段关系时，只读取该段号的数据。

## 二、核心实体

### 2.1 MemoryArchive

单段回忆主记录。它承担列表展示、权限、生成状态和用户侧操作。

| 字段 | 说明 |
|---|---|
| `id` | 回忆 ID |
| `space_id` | 稳定双人空间 ID |
| `relationship_id` | 触发归档的关系 ID |
| `relationship_segment_no` | 绑定段号 |
| `owner_user_id` | 当前用户 |
| `partner_user_id` | 对方用户 |
| `partner_nickname_snapshot` | 对方昵称快照 |
| `partner_avatar_snapshot` | 对方头像快照 |
| `title` | 系统生成标题 |
| `cover_media_id` | 封面媒体 |
| `bound_at` | 绑定时间 |
| `unbound_at` | 解绑时间 |
| `summary_json` | 列表摘要和统计 |
| `content_status` | 内容生成摘要：`baseline/pending/running/waiting_human/succeeded/failed/cancelled` |
| `enhancement_status` | 媒体增强：`disabled/pending/running/succeeded/partial/failed` |
| `generation_status` | 面向前端的派生状态，不作为第三个独立写入源 |
| `generation_epoch` | 当前生成世代；删除、重建或主动重新生成时递增 |
| `active_run_id` | 当前 epoch 的有效 Runtime run |
| `published_revision` | 当前播放器可见的作品修订号，初始为 baseline revision 0 |
| `is_pinned` | 当前用户是否置顶 |
| `deleted_at` | 当前用户删除时间 |
| `created_at/updated_at` | 审计时间 |

唯一约束：

```text
unique(space_id, relationship_segment_no, owner_user_id)
```

### 2.2 MemorySnapshot

解绑时冻结的素材快照。`MemoirAgent` 只读取快照，不直接扫描原始日记、赌局和关系表。

| 字段 | 说明 |
|---|---|
| `id` | 快照 ID |
| `archive_id` | 所属回忆 |
| `snapshot_version` | 快照结构版本 |
| `source_range_json` | 关系时间范围、段号、用户快照 |
| `diary_items_json` | 可进入回忆录的日记素材 |
| `bet_items_json` | 可进入回忆录的赌局素材 |
| `stats_json` | 统计摘要 |
| `privacy_filter_version` | 脱敏规则版本 |
| `snapshot_cutoff_at` | 解绑事务冻结的素材时间边界 |
| `source_manifest_hash` | 当时有效素材 ID + source version 的规范化 hash |
| `created_at` | 创建时间 |

MemorySnapshot 会复制亲密关系素材，生产环境必须使用数据库或应用层静态加密，并限制为 memory service 与内部 tool 身份可读。通用后台列表、ORM debug 日志和数据库导出任务不得展开正文。用户删除该 owner 的 archive 后，清理任务删除该用户对应 snapshot；不影响对方独立 archive，也不反向删除原始日记和赌局。

解绑事务不必同步复制全部正文，但必须冻结 `space_id + relationship_segment_no + snapshot_cutoff_at + source manifest/version`，并写入 snapshot outbox。异步 materializer 只能按这份冻结清单生成快照，不能读取“任务执行当下”的可变最新集合。后续正式删除或合规清理通过 tombstone 传播到 snapshot 和已发布作品，而不是依赖重新扫描时偶然过滤。

日记素材建议字段：

```json
{
  "diary_id": "d_001",
  "author_user_id": "u_1",
  "author_role": "self|partner",
  "created_at": "2026-06-10T14:30:00+08:00",
  "date_key": "2026-06-10",
  "text_excerpt": "今天午饭吃了麻辣烫...",
  "image_refs": ["img_001"],
  "has_full_text": false,
  "tags": ["food", "daily"]
}
```

赌局素材建议字段：

```json
{
  "bet_id": "b_001",
  "creator_role": "self|partner",
  "status": "completed",
  "title": "谁会先睡着",
  "reward_excerpt": "一杯奶茶",
  "winner_role": "self|partner|draw",
  "created_at": "2026-06-08T20:00:00+08:00",
  "completed_at": "2026-06-09T12:00:00+08:00",
  "event_count": 4,
  "tags": ["funny", "fulfilled"]
}
```

### 2.3 MemoryAgentRunRef

情侣日记业务记录与公共 Agent Runtime 中 `AgentRun` 的映射。完整执行过程保存在公共 Runtime，情侣日记后端只保存业务侧需要展示和重试的摘要状态。

| 字段 | 说明 |
|---|---|
| `id` | 映射 ID |
| `archive_id` | 所属回忆 |
| `run_id` | 公共 Runtime 的 AgentRun ID |
| `agent_id` | `memoir_agent` |
| `agent_version` | Agent 定义版本 |
| `authorization_version` | Runtime 创建 run 时采用的授权版本，仅用于追踪；工具调用仍按当前权限校验 |
| `status` | 业务摘要状态：`pending_start/pending/running/waiting_human/succeeded/failed/partial/cancelled` |
| `current_step` | 当前 Runtime 步骤摘要 |
| `progress` | 0 到 100 |
| `error_code/error_message` | 错误信息，禁止写入敏感原文 |
| `manual_retry_count` | 用户或后台触发的 run 级重试次数 |
| `auto_retry_count` | Runtime 自动节点重试次数摘要 |
| `last_event_seq` | 最近处理的 Runtime callback 序号 |
| `last_runtime_status_version` | 最近接受的 Runtime 状态版本 |
| `row_version` | 情侣日记业务表自己的乐观锁版本 |
| `create_idempotency_key` | 创建 held run 的稳定幂等键 |
| `start_idempotency_key` | 绑定后 start 的稳定幂等键 |
| `last_retry_idempotency_key` | 最近一次显式 retry 的幂等键 |
| `privacy_purge_status` | `not_requested/requested/purged/failed`，用于跨库清理对账 |
| `privacy_purge_idempotency_key` | Runtime 私密数据清理的稳定幂等键 |
| `privacy_purge_requested_at/completed_at` | 清理请求和确认完成时间 |
| `generation_epoch` | 该 run 所属业务生成世代 |
| `started_at/finished_at` | 执行时间 |

说明：

- `AgentRun`、`AgentStep`、`AgentToolCall`、`AgentCheckpoint` 的完整数据归公共 Runtime 管理。
- 用户侧查询生成状态时，情侣日记后端返回 `MemoryAgentRunRef` 的摘要，不暴露 prompt、中间素材和模型原始输出。
- Runtime 的 `planning/evaluating` 在业务侧统一折叠为 `running`；业务表不复制 Runtime 的全部内部状态机。
- 业务后端处理 callback 时同时比较 `event_seq` 和 Runtime 的 `status_version`，分别更新 `last_event_seq`、`last_runtime_status_version`。`row_version` 只服务本地并发写入，不能拿来比较 Runtime callback。
- `event_seq` 采用方案 A：在同一个 `run_id` 的完整生命周期内全局单调递增，手动 retry 或自动恢复后继续从当前最大值累加，不重置为 1。
- `pending_start` 可作为本地补偿状态：业务归档已创建但 Runtime run 尚未绑定时使用，由补偿任务继续创建或标记失败。
- 删除 archive 时先把 `privacy_purge_status` 写为 requested，再调用 Runtime；业务对账只有在 Runtime 返回 `privacy_state=purged` 后才标记 purged。网络重试复用同一 purge idempotency key，不能把 cancel 成功当作私密 payload 已清理。
- callback 始终更新对应 `MemoryAgentRunRef`；只有 `run_id == MemoryArchive.active_run_id` 且 epoch 相等时，才能更新 archive 的 `content_status/public_trace`。旧 run 事件只保留审计。

约束建议：`unique(run_id)`、`unique(archive_id, generation_epoch)`。显式 retry 复用同一 run/epoch；需要替换 run 或重新生成时先递增 archive generation_epoch，再创建新的 RunRef。

### 2.4 MemoryPlaybackDocument

播放器消费的完整作品版本。它把 Scene、Action 和媒体清单作为一个发布单元。

| 字段 | 说明 |
|---|---|
| `id` | 作品版本 ID |
| `archive_id` | 所属回忆 |
| `revision` | archive 内单调递增；`0` 固定为业务模板 baseline |
| `document_schema_version` | 播放文档契约版本 |
| `source_type` | `baseline/agent_generated` |
| `snapshot_id` | AI 版本引用的素材快照；baseline 可为空 |
| `run_id` | 生成该版本的 Runtime run；baseline 可为空 |
| `generation_epoch` | 必须与发布时 archive 当前 epoch 一致 |
| `content_digest` | scenes/actions/media manifest 的规范化 hash |
| `scene_count/action_count` | 完整性校验摘要 |
| `published_at` | 发布时间 |
| `superseded_at/retain_until` | 被新版本替代后的普通清理宽限期 |

唯一约束：

```text
unique(archive_id, revision)
```

业务后端在创建 archive 时用关系时间和基础统计生成 revision 0（封面、统计、总结和默认 Action），因此 Runtime 未启动或失败时播放器仍有可用作品。AI 版本先在单个数据库事务内校验并写入 document/scenes/actions，再原子更新 `MemoryArchive.published_revision`；详情接口只读取该指针指向的版本，不读取草稿或半成品。

普通新版本发布后，旧 revision 不再返回给新详情请求，但保留短暂、可配置的播放宽限期，避免已打开播放器立刻丢失媒体；宽限期后由 GC 幂等清理。用户删除 archive 或原素材触发隐私清理时不使用普通宽限，先撤销访问和媒体授权，再按隐私流程清理。

### 2.5 MemoryScene

回忆作品中的场景卡。

| 字段 | 说明 |
|---|---|
| `id` | 场景 ID |
| `archive_id` | 所属回忆 |
| `document_id` | 所属 MemoryPlaybackDocument |
| `order_no` | 播放顺序 |
| `scene_type` | `cover/stats/diary_highlight/bet_highlight/image/milestone/summary` |
| `title` | 场景标题 |
| `body` | 场景文案 |
| `payload_json` | 图片、数字、引用、样式等结构化数据 |
| `safety_level` | `normal/sensitive/fallback` |
| `schema_version` | 场景业务契约版本，播放器按版本迁移或拒绝 |
| `source_refs_json` | 可追溯到当前 snapshot 的素材引用 |

### 2.6 MemoryAction

播放动作协议。

| 字段 | 说明 |
|---|---|
| `id` | 动作 ID |
| `scene_id` | 所属场景 |
| `document_id` | 所属 MemoryPlaybackDocument |
| `order_no` | 动作顺序 |
| `type` | `show_card/focus_image/type_text/hold/play_tts/transition` |
| `payload_json` | 动作参数 |
| `duration_ms` | 建议持续时间 |
| `schema_version` | Action 业务契约版本 |

首期动作示例：

```json
[
  {"type": "show_card", "payload": {"scene_id": "s_cover"}, "duration_ms": 800},
  {"type": "type_text", "payload": {"target": "title", "speed": "medium"}, "duration_ms": 2200},
  {"type": "focus_image", "payload": {"media_id": "m_001"}, "duration_ms": 1800},
  {"type": "transition", "payload": {"name": "fade"}, "duration_ms": 600}
]
```

### 2.7 MemoryMediaTask

业务后端拥有的异步媒体任务。Runtime 只负责幂等创建任务，不执行后续状态回写。

| 字段 | 说明 |
|---|---|
| `id` | 媒体任务 ID |
| `archive_id/document_id` | 明确绑定作品版本 |
| `generation_epoch` | 创建任务时的业务世代 |
| `task_type` | `tts/cover/video` |
| `status` | `pending/running/succeeded/failed/cancelled` |
| `idempotency_key/request_hash` | 防止重复创建收费任务 |
| `attempt_count/max_attempts` | 媒体 worker 独立重试预算 |
| `error_code/safe_message` | 不含私密正文的错误摘要 |
| `created_at/updated_at/finished_at` | 审计时间 |

媒体 worker 可以完成旧 document 的任务并保存结果，但只有 `document_id` 等于 archive 当前 `published_revision` 对应 document、epoch 仍匹配且 archive 未删除时，才能参与当前 `enhancement_status` 聚合。过期任务标记 `cancelled/superseded` 或进入旧 revision 清理，不得修改当前作品状态。

### 2.8 MemoryMediaAsset

AI 或系统生成媒体。

| 字段 | 说明 |
|---|---|
| `id` | 媒体 ID |
| `archive_id` | 所属回忆 |
| `document_id` | 所属作品版本 |
| `task_id` | 生成该资源的 MemoryMediaTask；原始媒体可为空 |
| `scene_id` | 可选，关联场景 |
| `media_type` | `image/audio/video` |
| `source_type` | `diary_original/ai_generated/tts/default_asset` |
| `storage_key` | 对象存储键或受控媒体服务资源 ID |
| `access_url` | 只在 API 响应中生成的短期授权地址，不持久化私有签名参数 |
| `provider` | 生成 provider |
| `status` | `ready/deleting/deleted`；生成中和失败状态归 MediaTask |
| `prompt_hash` | prompt 哈希，不保存敏感 prompt 原文 |

`generation_status` 派生规则：没有 AI 版本时 baseline 仍可播放；当前 run 执行中显示 `running`；内容发布成功且增强关闭/成功显示 `succeeded`；内容已发布但当前 run 为 partial 或增强失败显示 `partial`；内容失败显示 `failed`，但详情继续返回 revision 0 或最近一次已发布版本。

状态写入边界：callback 更新 `MemoryAgentRunRef`，并在 active run/epoch 匹配时推进 `content_status` 的 pending/running/failed/cancelled；原子发布工具把 `content_status` 提交为 succeeded 并切换 `published_revision`；媒体任务创建和 worker 只更新 `enhancement_status`。`run_succeeded/partial_succeeded` callback 到达时，业务后端必须先确认存在该 run 发布的 revision，不能仅凭事件把内容标成已发布。

## 三、统计摘要

`stats_json` 建议包含：

- 关系持续天数
- 日记总数
- 双方日记数
- 图片日记数
- 双方同日记录天数
- 赌局总数
- 已完成赌局数
- 兑现率
- 最常见奖励
- 高频关键词
- 最早记录、最后记录

无赌局时不展示兑现率。无日记时不制造虚假关键词。

## 四、素材进入规则

### 4.1 可进入

- 当前段号内未删除日记。
- 当前段号内可见赌局。
- 已完成赌局、已兑现赌局、互动事件丰富的赌局。
- 关系开始和结束时间。
- 对方昵称、头像快照。

### 4.2 不可进入

- 已正式删除日记。
- 用户无权访问的数据。
- 其它 `space_id` 的数据。
- 同一 `space_id` 其它段号的数据。
- 用户删除后的回忆详情。
- 敏感字段，如 token、openid、手机号、内部备注。

## 五、快照版本策略

快照加 `snapshot_version`。后续数据结构升级时，不直接改旧快照。读取旧快照时由服务层迁移到播放器当前结构。

推荐版本：

| 版本 | 内容 |
|---|---|
| v1 | 日记摘要、赌局摘要、基础统计 |
| v2 | 增加 AI 标签、高光评分、媒体引用 |
| v3 | 增加分享脱敏配置和视频分镜 |

版本迁移必须保持方向清晰：数据库保存原始版本，服务层读取时迁移为当前领域模型，API 明确返回 `schema_version`。未知的未来高版本不得被旧服务写回覆盖。`MemorySnapshot`、`MemoryScene`、`MemoryAction` 分别演进，不能共用一个含义模糊的全局版本号。
