# 07-安全隐私与情绪安全

## 一、基本原则

回忆录处理的是解绑后的亲密关系数据。系统需要同时保护隐私和情绪安全。

核心原则：

- 用户先解锁，再查看。
- 后端先脱敏，再调用 AI。
- 原文最小化外传。
- 生成文案不评价关系。
- 日志不记录敏感内容。
- 分享默认脱敏，默认不公开。

## 二、密码与访问控制

沿用现有回忆录需求：

- 密码 4 到 6 位数字。
- 密码只存哈希。
- 每次重新进入回忆录入口需要输入密码。
- 当前 MVP 不提供忘记密码和重置密码。

增强建议：

- 连续输错 5 次后冷却 10 分钟。
- 解锁态设置短期有效期，例如 15 分钟。
- 切后台超过一定时间后重新锁定。

## 三、Agent Runtime 与 AI provider 策略

采用公共 Agent Runtime 服务端可配置策略：

| 策略 | 用途 |
|---|---|
| 私有模型 | 生产优先，处理完整摘要 |
| 可信云模型 | 可选，需要用户协议和脱敏 |
| 模板生成 | 无 AI 或隐私限制时兜底 |

前端不传 API Key，不直连模型。情侣日记后端也不直接管理模型密钥，而是通过公共 Runtime 的 ModelGateway 控制：

- provider
- 模型
- 是否允许视觉输入
- 是否允许 TTS
- 是否允许 AI 图片/视频
- 日志级别
- 最大文本长度

情侣日记后端负责业务侧脱敏和权限过滤；Runtime 负责模型路由、prompt 版本、模型调用日志和成本统计。两边都不能记录日记原文。

双重脱敏边界：

| 层级 | 责任 | 示例 |
|---|---|---|
| 情侣日记后端 | 强规则过滤和权限边界 | 删除手机号、openid、token、地址、无权素材、已删除内容、私有图片签名 |
| MemoirAgent `sanitize_materials` | Agent 业务语义脱敏 | 昵称转为“我/TA”、长文本截断、奖励描述截断、敏感片段降权 |
| Runtime ContextManager | 模型调用前二次扫描 | token 预算、工具结果摘要压缩、敏感字段再次检测 |

如果 Runtime 侧发现业务后端已过滤字段重新出现，应视为 P0 隐私告警。处置动作：

- 立即阻断当前模型调用或工具调用。
- 将 run 标记为 `waiting_human` 或 `failed`，不继续生成。
- 只保存脱敏后的告警摘要，不保存触发告警的原文。
- 通知业务后端重新检查 snapshot / tool API 的过滤规则。

Runtime 存储边界：

- `AgentRun` 只长期保存业务定位参数、状态、摘要、hash 和引用。
- 恢复所需 Checkpoint 使用加密 payload、最短 TTL、访问审计和删除联动；过期后只能从业务快照重新创建 run，不能继续依赖旧明文状态。
- `AgentArtifact` 默认不保存完整回忆录正文。业务工具写回成功后只保留 artifact schema version、digest 和业务资源 ID。
- provider、trace exporter、LangSmith 等外部观测通道必须按数据分级启用；未确认零保留或合规边界时，不发送亲密关系正文和私有图片。

不可信内容边界：

- 日记、赌局名称/奖励、图片说明、RAG/Web Search 和工具返回都标记为 `trusted=false`，其中出现的命令不能改变 Runtime policy、AgentPackage、工具清单或权限。
- ContextManager 只把这些内容放入结构化数据槽，不插入 system/developer 指令、工具描述、schema 和输出示例。
- prompt injection 检测用于告警和隔离，不能替代静态 workflow、tool allowlist、trusted 参数映射、确定性语义校验与业务后端二次鉴权。
- 模型输出的 material ID、scene/action 引用、数字、URL 和工具参数必须由代码核对；未知引用或控制字段触发 fallback/failed。

运行中授权边界：Runtime 在每次模型、工具和 callback 动作前复核 caller/tenant、connector、callback target 和数据域的当前授权版本。授权撤销后停止后续动作；业务后端仍按请求当下的用户、archive 和 generation epoch 重新鉴权。

## 四、脱敏规则

发送给模型前处理：

- 用户 ID 替换为 `self`、`partner`。
- 昵称可替换为“我”和“TA”，除非服务端允许使用昵称。
- 删除手机号、地址、身份证、邮箱、openid、token。
- 日记原文截断成短摘录。
- 赌局奖励截断，避免暴露过多私密细节。
- 图片默认不送视觉模型，只传标签或描述。

禁止写入日志：

- 日记正文
- 赌局完整内容
- 图片 URL 的私有签名
- 密码、token、openid
- 模型完整 prompt
- AgentStep 中的私密中间状态
- Checkpoint 解密后的 payload、Artifact 私密 payload

## 五、情绪安全文案规则

### 5.1 禁止表达

生成文案不得使用：

- “谁辜负了谁”
- “这段关系失败了”
- “你该放下”
- “也许你们还会复合”
- “最遗憾的是”
- “错过的人”
- “一别两宽”等强分手叙事

### 5.2 推荐表达

使用中性、克制、记录式表达：

- “这段时间里，你们留下了这些记录。”
- “系统整理了当时的一些片段。”
- “有些日子被写了下来。”
- “谢谢你认真记录过。”
- “这段回忆会按你的选择保存在这里。”

### 5.3 强制拉黑场景

强制拉黑后也生成回忆，但文案不提“拉黑”作为情绪叙事。列表可在管理信息里记录解除方式，播放器只使用中性表达。

## 六、内容审核

生成前：

- 过滤不可进入素材。
- 标记敏感日记和敏感赌局。
- 对高风险片段降权。

生成后：

- 检查敏感词。
- 检查是否编造事实。
- 检查是否出现关系评价。
- 检查是否泄露个人信息。
- 检查卡片长度。

风险结果：

| 风险 | 处理 |
|---|---|
| 轻微 | 替换词语 |
| 中等 | 使用模板文案 |
| 高 | 删除该场景，改用统计卡 |
| 严重 | 标记生成失败，只展示基础回忆 |

## 七、分享安全

默认不自动生成公开分享页。用户主动分享前必须看到预览和确认项。

列表页在未解锁前只展示最小必要信息。默认不展示对方头像、对方昵称、回忆摘要、AI 生成文案和素材缩略图；如产品需要展示“有一段回忆待查看”，也应使用通用占位文案。

分享建议：

- 链接有过期时间。
- 默认隐藏对方头像。
- 默认隐藏原文摘录。
- 默认不展示图片，除非用户勾选。
- 分享页可撤销。
- 分享访问记录可审计。

私密详情和状态接口禁止公共缓存并返回 `Cache-Control: private, no-store`。媒体地址使用鉴权代理或短期授权，URL 中的签名参数不得进入访问日志、前端持久化和错误上报。分享页使用独立的脱敏副本和权限模型，不能复用回忆录详情接口或私密媒体 URL。

## 八、删除与保留

- 用户删除自己的回忆后，自己的列表和详情不可再访问。
- 删除不影响对方账号。
- 业务后端先软删除并立即撤销访问，再由幂等清理任务删除该 owner 派生的 Snapshot、Scene、Action、AI 媒体和短期签名资源。
- 业务后端向 Runtime 发送幂等私密数据清理请求。Runtime 先写入不可逆的 privacy purge tombstone 并递增 `privacy_version`，再删除该 archive 对应 run 的 Checkpoint、临时 Artifact 和模型/工具临时 payload；旧 worker 只有在 `privacy_state=active` 且 version 匹配时才能保存私密内容，避免迟到结果在清理后重新落库。Runtime 只保留不含正文的最小审计元数据。
- purge 进入 `purge_requested` 后，该 run 禁止 retry/resume；重新生成必须使用新 run。cancel 只负责停止执行，不能替代 privacy tombstone。
- 原始日记和赌局是否删除，由原模块规则决定，回忆录不反向删除原数据。

如果原模块在归档后正式删除某条素材，隐私清理任务通过 `source_refs_json` 找到受影响作品，递增 generation_epoch、取消 active run，并在一个事务中发布移除该素材的新 revision；无法安全局部重写时切回 baseline。系统完成指针切换后再清理旧 revision、snapshot 副本和媒体，避免播放器继续暴露已删除内容。

## 九、合规提示

产品文案中应说明：

- 回忆录由系统根据历史记录整理。
- 部分文案可能由 AI 生成。
- 用户可以删除自己的回忆。
- 分享前应确认内容。
- 系统不会把密码明文保存。
