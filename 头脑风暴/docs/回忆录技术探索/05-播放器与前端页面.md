# 05-播放器与前端页面

## 一、页面分层

前端基于 uni-app、Vue 3、TypeScript、Pinia 实现。建议在 `pages-mine` 分包中承接回忆录，因为现有需求入口位于“我的页”。

```text
我的页
  -> memoir-entry        密码入口
  -> memoir-list         回忆列表
  -> memoir-player       回忆作品播放器
  -> memoir-share-preview 可选，分享预览
```

公共能力放在业务分包内部或业务 hooks 中，不塞进公共脚手架。

## 二、播放器数据结构

前端详情接口返回：

```json
{
  "document_schema_version": "1.0.0",
  "archive": {
    "id": "mem_001",
    "title": "我们认真记录过的 286 天",
    "generation_status": "succeeded",
    "content_status": "succeeded",
    "enhancement_status": "disabled",
    "published_revision": 1
  },
  "scenes": [
    {
      "id": "scene_001",
      "schema_version": "1.0.0",
      "type": "cover",
      "title": "我们认真记录过的 286 天",
      "body": "2025.03.14 - 2025.12.25",
      "payload": {"cover_media_url": "..."}
    }
  ],
  "actions": [
    {
      "id": "act_001",
      "schema_version": "1.0.0",
      "scene_id": "scene_001",
      "type": "show_card",
      "payload": {},
      "duration_ms": 800
    }
  ],
  "media": []
}
```

前端只解释后端按 `published_revision` 组装的 `scenes/actions/media`，不回查日记和赌局详情，也不拼接不同 revision 的数据。

详情、生成状态和密码校验响应使用 `Cache-Control: private, no-store`，不进入公共 CDN 缓存。媒体优先走鉴权代理或带 archive/document 授权校验的短期地址；直接对象存储签名 URL 必须使用短 TTL，且不得写入日志、持久 store 或分享 payload。

播放器加载时先校验 document/scene/action schema version，再构建执行队列：scene 引用必须存在、action 只能引用当前 archive 的 scene、`duration_ms` 必须落在产品上限内、媒体引用必须属于详情响应。遇到未知 major version 时停止解释动态 Action，降级为服务端提供的基础静态卡；同 major 的未知可选 Action 可以记录告警后跳过。前端不能对未知字段做猜测性执行。

`generation_status` 由情侣日记后端根据 archive 的 `content_status`（由 active run 生命周期推进）和业务媒体任务的 `enhancement_status` 派生。前端不直接调用 Runtime，也不展示 prompt、模型输出原文或中间推理过程。AI 尚未成功发布时，详情接口返回 revision 0 baseline；生成失败不能让已有作品变空。

如果当前 AgentPackage 允许展示执行轨迹，详情或生成状态接口可返回 `public_trace`：

```json
{
  "generation_status": "running",
  "progress": 60,
  "public_trace": [
    {"step": "load_snapshot", "label": "整理素材", "status": "succeeded"},
    {"step": "generate_scenes", "label": "生成回忆卡片", "status": "running"}
  ]
}
```

前端只能展示 `public_trace`，不能展示 Runtime 内部完整 trace。

## 三、播放器状态机

```text
idle
  -> loading
  -> ready
  -> playing
  -> paused
  -> ended
  -> replay

loading -> error
ready -> low_power_ready
```

状态说明：

| 状态 | 说明 |
|---|---|
| `idle` | 页面刚进入 |
| `loading` | 请求详情 |
| `ready` | 数据已准备 |
| `playing` | 自动播放中 |
| `paused` | 用户暂停或切后台 |
| `ended` | 播放到最后 |
| `error` | 详情加载失败 |
| `low_power_ready` | 媒体缺失，仅文本卡片 |

## 四、生成进度通信

前端只连接情侣日记业务后端，不直接连接公共 Agent Runtime。

推荐：

| 场景 | 通信方式 |
|---|---|
| 打开回忆详情 | HTTP |
| 小程序查询生成状态 | HTTP 轮询，MVP 必做 |
| H5/已验证流式能力的端 | 业务后端 SSE，可选 |
| 多轮聊天或用户打断 Agent | WebSocket，二期 |

状态接口返回 `status_version/updated_at/retry_after_ms`。前端前台生成中可按服务端建议间隔轮询，连续无变化时退避；进入后台、离开页面或到达终态立即停止。现有公共 `request<T>()` 没有定义流式协议，因此小程序首期不能把 EventSource/SSE 当作唯一链路。

可选 SSE 接口：

```text
GET /api/v1/memory/archives/{archive_id}/generation/stream
```

SSE 事件只展示安全摘要：

```json
{
  "event": "step_changed",
  "progress": 60,
  "current_step": "generate_scenes",
  "label": "生成回忆卡片",
  "status": "running"
}
```

SSE 适配器需要鉴权、15 秒左右 heartbeat、`Last-Event-ID`/事件序号恢复和唯一终止事件；连接失败自动回退状态轮询。前端仍只消费业务后端保存的 `public_trace`。

禁止前端展示：

- prompt。
- 工具输入输出。
- 模型原始输出。
- 日记原文。
- Runtime 内部私密状态。

## 五、动作执行

`MemoirActionRunner` 只负责解释经过校验的业务 Action，再调用注入的 scene、timer 和 media 能力。Scene 描述“展示什么”，ActionRunner 描述“何时执行”，具体组件负责“怎样渲染”，对应 OpenMAIC 的 DSL、Stage API、Action/Playback Engine 三层分工。

### 5.1 `show_card`

切换当前 scene，准备卡片渲染。

### 5.2 `type_text`

逐字展示标题或正文。低端设备可直接显示完整文本。

### 5.3 `focus_image`

对图片做轻微缩放或聚焦。没有图片时跳过。

### 5.4 `hold`

保持当前画面指定时长。暂停、切后台或用户手动翻页时必须取消剩余计时。

### 5.5 `play_tts`

播放音频。失败时跳过，不弹错误打断。

### 5.6 `transition`

控制卡片切换。首期只支持 `fade`、`slide`。

## 六、低配与高配展示

| 能力 | 低配 | 高配 |
|---|---|---|
| 卡片 | 普通轮播 | 沉浸式全屏卡片 |
| 文案 | 直接展示 | 打字浮现 |
| 图片 | 静态图 | 聚焦、轻微缩放 |
| TTS | 不显示音频 | 旁白和静音切换 |
| 视频 | 不支持 | 背景短片段 |
| 分享 | 小程序内查看 | 脱敏 H5 分享页 |

前端根据接口返回和设备能力选择展示层级，不让用户看到空白或卡死。

## 七、页面细节

### 7.1 回忆录入口页

- 未设置密码：进入设置密码流程。
- 已设置密码：输入密码解锁。
- 输错密码：提示重试，连续失败后短暂冷却。

### 7.2 回忆录列表页

列表项展示：

- 封面
- 标题
- 对方昵称
- 时间范围
- 摘要
- 生成状态
- 置顶状态

生成中可以进入详情，但详情页展示“正在整理”。如果已有基础卡片，则允许播放基础版本。

如果 `public_trace` 存在，列表或详情页可展示轻量进度：

- “整理素材”
- “寻找值得保留的片段”
- “生成回忆卡片”
- “检查隐私与表达”

如果 AgentPackage 的 `ui_trace.mode` 为 `none` 或 `status_only`，只展示“正在整理回忆”。

### 7.3 回忆作品播放器

操作：

- 返回
- 暂停/继续
- 上一张/下一张
- 静音
- 重新播放

播放规则：

- 页面进入默认停在封面，不自动播放声音。
- 用户点击播放后，才播放 TTS。
- 切后台暂停音频和动作计时。
- 用户手动滑动时暂停自动播放。

### 7.4 分享预览页

后续版本才做。分享前给用户逐项确认：

- 是否展示对方昵称
- 是否展示头像
- 是否展示原文摘录
- 是否展示图片
- 链接有效期

默认脱敏，默认有过期时间。

## 八、前端错误处理

| 场景 | 前端行为 |
|---|---|
| 详情接口失败 | 显示重试按钮 |
| scenes 为空 | 展示基础封面与总结空态 |
| actions 为空 | 按 scenes 默认轮播 |
| 音频加载失败 | 静音跳过 |
| 媒体图加载失败 | 使用默认封面 |
| 回忆已删除 | 返回列表并提示该回忆不可访问 |
| AgentRun 失败 | 展示基础统计卡和重试入口 |

## 九、组件建议

| 组件 | 职责 |
|---|---|
| `MemoirArchiveCard` | 列表卡片 |
| `MemoirUnlockPanel` | 密码输入 |
| `MemoirPlayer` | 播放器容器 |
| `MemoirSceneRenderer` | 根据 scene_type 渲染卡片 |
| `MemoirActionRunner` | 执行动作脚本 |
| `MemoirMediaLayer` | 音频、图片、视频资源管理 |
| `MemoirAgentTrace` | 可选，展示脱敏后的 Agent 执行轨迹 |
