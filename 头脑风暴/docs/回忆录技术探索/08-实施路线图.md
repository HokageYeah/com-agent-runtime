# 08-实施路线图

## 一、阶段划分

推荐分三期，但第一期必须把公共 Runtime 骨架搭完整：

```text
第一版：公共 Agent Runtime 骨架 + MemoirAgent MVP + 基础播放器
二期：媒体增强 + MCP 标准化 + 客服 Agent 验证通用性
三期：平台化治理 + 多 Agent 协作 + 管理后台 + 长期记忆
```

## 二、第一版

### 2.1 目标

在不做巨型平台的前提下，跑通公共 Agent Runtime 的核心闭环：

```text
情侣日记后端创建 snapshot
  -> Agent Runtime 执行 MemoirAgent
  -> 生成 scenes/actions
  -> 写回情侣日记后端
  -> uni-app 播放器展示
```

### 2.2 公共 Runtime 必做

| 模块 | 第一版要求 |
|---|---|
| AgentDefinition | 支持 `memoir_agent@1.0.0` 配置 |
| AgentPackage | 支持业务 Agent 以包形式注册 |
| AgentRun | held/auto 创建、start、查询、重试、取消 |
| AgentPlan | 静态计划生成与落库 |
| AgentStep | 记录 LangGraph 节点状态、execution attempt 和 step attempt |
| AgentToolCall | 记录工具调用摘要、耗时、错误、execution/tool attempt 和稳定逻辑操作键 |
| AgentEvaluation | 记录关键步骤评价结果 |
| AgentArtifact | 保存版本、摘要、hash 和业务资源引用；私密 payload 不默认长期保留 |
| AgentCheckpoint | 支持加密、带 TTL 的节点级恢复状态 |
| Planner | 支持 Workflow Agent 静态计划 |
| Evaluator | 支持 schema、引用、安全、完成度评价 |
| PolicyEngine | 支持 step/token/cost/tool 硬限制 |
| LangGraph Executor | 支持固定 workflow |
| LangChain Components | 使用 PromptTemplate、tool、parser、middleware |
| ModelGateway | 基于 LiteLLM / Provider Adapter 接入模型和结构化输出 |
| ToolGateway | 支持 HTTP Business Tool |
| ContextManager | token 预算、脱敏、摘要压缩 |
| Guardrails | schema、权限、敏感字段、情绪安全 |
| Observability | 基础 trace、日志、token、成本 |
| Runtime Contract | API/Event/Tool/Artifact 的 Pydantic + JSON Schema 契约、版本与兼容性测试 |
| Worker Coordination | outbox、原子认领、lease/heartbeat、fencing、execution attempt、取消传播 |
| Business Publication Contract | generation_epoch、active_run_id、baseline revision 0、完整作品原子发布 |
| Run Start Handshake | held create、业务绑定、幂等 start、held 超时回收 |
| Admission/Backpressure | 全局、caller、tenant、agent、provider 的队列与并发上限 |
| Runtime Operations | liveness/readiness、鉴权能力发现、共享持久化、worker draining 与优雅停机 |
| Data Lifecycle | privacy purge tombstone/version、条件写屏障、package 撤销和 outbox dead letter |
| Trust/Authorization | trusted/untrusted 上下文隔离、语义校验、authorization version 和撤销传播 |

第一版还必须冻结以下横向契约：

- callback `event_seq/status_version` 乱序保护。
- callback HMAC-SHA256 签名、业务侧验签和 `IDEMPOTENCY_CONFLICT` 错误码。
- `Idempotency-Key` 存储、TTL、请求体 hash 和冲突响应。
- HMAC-SHA256 服务间签名、时间戳容忍窗口和密钥下发方式。
- Runtime 与业务库不一致时的 pending、对账和补偿路径。
- 手动重试计数与 Runtime 自动节点重试计数隔离。
- `model_policy.yaml` 最小模型策略映射。
- AgentPackage 不可变版本与 `package_digest`。
- 副作用工具稳定逻辑幂等键；attempt 只用于审计。
- 受信任 AgentPackage 注册边界、出站 connector allowlist、callback target 注册和私密状态保留策略。
- Runtime callback、业务作品 revision、媒体任务三类状态的唯一写入者与派生规则。
- `max_run_seconds` 活跃执行预算与 held、queued、waiting_human、最终 deadline 的独立时钟。
- package `active/deprecated/revoked` 转换、privacy purge 不可逆语义和 outbox 原事件重放规则。
- dispatch/callback dead letter 的差异化恢复、untrusted content envelope 和运行中授权版本复核。

- 按 `space_id + relationship_segment_no` 生成素材快照。

- 暴露 `memory.*` 内部工具。
- 使用 `memory.publish_playback_document` 单事务发布，详情只读 `published_revision`。

### 2.5 前端必做

- 回忆录入口页接入密码设置/解锁。
- 回忆录列表展示多段回忆和生成状态。
- 播放器支持 `show_card/type_text/hold/transition`。
- 小程序通过业务后端状态轮询获取 `public_trace`；H5/已验证流式能力的平台可选 SSE。
- AI 失败时展示基础统计卡。
- 支持基础错误态和空态。

### 2.6 第一版验收

- 和平解绑后双方各生成一条 archive。
- 强制拉黑后双方各生成一条 archive。
- 同一对用户第二次解绑生成第二段回忆。
- 无日记、无赌局也能播放 3 张基础卡。
- Runtime 尚未启动时 revision 0 baseline 已可播放。
- held run 在 active_run_id 绑定前不会调用工具或发送 run_started。
- Agent 失败时可重试。
- Runtime 重试不重复写入 scenes/actions。
- callback 乱序或重复到达时不造成状态倒退和重复写入。
- Runtime 创建/入队/callback 某一步失败时能通过补偿或对账恢复。
- worker 执行中失联后可由新 worker 接管，旧 worker 的迟到结果不能覆盖新状态。
- Step、ToolCall、ModelUsage 能按 execution attempt 区分恢复和重试成本，副作用幂等键保持不变。
- 取消 run 后不再启动新模型/工具调用，已提交副作用不会重复执行。
- 删除、重新生成与旧 run 发布并发时，generation_epoch 能拒绝迟到写回。
- Scene/Action 任一校验或落库失败时 published_revision 保持原值。
- 旧 document 的媒体任务完成时不改变当前 published document 的 enhancement_status。
- 小程序不支持流式适配或 SSE 断线时，状态轮询仍能到达终态。
- liveness/readiness 能区分进程存活、核心依赖不可用和 draining；能力接口不泄露 provider/connector 密钥与地址。
- Runtime API/worker 重启或横向扩容时依赖共享状态恢复，不依赖单实例内存和临时磁盘。
- 排队、held 和人工等待不消耗 `max_run_seconds` 活跃执行预算，各自 TTL 到期后按策略处理。
- purge 与迟到模型结果并发时，Checkpoint/Artifact/临时 payload 不会在清理后复活。
- package 安全撤销后 create/start/retry/resume 全部拒绝，held/queued/running run 按安全边界停止。
- callback 达到上限进入 dead letter；原事件重放和业务主动查询可恢复本地状态。
- run_dispatch dead letter 经重放仍失败时，run 进入 `failed(DISPATCH_FAILED)`，不会永久 pending/queued。
- 日记或赌局包含 prompt injection 文本时，不能改变工具、connector、权限、统计和发布策略。
- caller/tenant/connector 授权在运行中撤销后，后续模型、工具和 callback 动作停止。
- 删除自己回忆不影响对方。
- 日志不记录日记原文和敏感字段。

## 三、二期

### 3.1 目标

增强回忆录质量，并验证公共 Runtime 对第二个业务 Agent 的复用能力。

### 3.2 公共 Runtime 二期

- MCP Client 接入外部工具。
- 将业务 HTTP Tool 适配为 MCP Server 形态。
- 支持 Autonomous Agent。
- 支持 LangChain createAgent。
- 支持动态计划生成和计划修订。
- 支持 LLM-as-judge 和多模型评价。
- 支持基础 RAG / Retriever。
- 支持 prompt 灰度和回滚。
- 支持人工审核 interrupt。
- 支持 Runtime 原生 `/events` SSE 事件流。
- 支持更完整的 LangSmith / OpenTelemetry trace。
- 增加评测集执行器。

### 3.3 回忆录二期

- TTS 生成和音频媒体表。
- `MemoryMediaTask` 表、媒体 worker、按 document/epoch 聚合 enhancement_status。
- `focus_image/play_tts` 动作。
- AI 封面图。
- 分享预览页。
- 媒体任务单独重试。
- 用户可重新生成某一章。
- 列表展示 `partial` 状态。

### 3.4 第二业务 Agent

建议二期接入客服 Agent：

```text
CustomerSupportAgent
  -> classify_intent
  -> search_knowledge_base
  -> check_order_or_user_state
  -> draft_answer
  -> safety_review
  -> escalate_human
```

如果客服 Agent 接入时不需要大改 Runtime，说明公共抽象成立。

## 五、测试场景总表

| 场景 | 预期 |
|---|---|
| 和平解绑 | 只归档当前段号数据 |
| 强制拉黑 | 归档成功，文案克制 |
| 同一对用户重绑 | 新段号生成新回忆 |
| 换人绑定 | 新 `space_id`，不混入旧数据 |
| 无日记无赌局 | 基础卡可播放 |
| 只有赌局 | 生成赌局统计和高光 |
| 只有日记 | 生成日记统计和高光 |
| 已删除日记 | 不进入 snapshot |
| 已发布后素材被正式删除 | 发布脱敏新 revision，再清理旧作品与媒体 |
| Runtime 失败 | 模板卡兜底 |
| TTS 失败 | 静音播放 |
| 重复 callback | 不重复写入 |
| callback 乱序 | 不覆盖更新后的终态 |
| callback 签名伪造 | 业务后端验签失败并拒绝 |
| 重试 AgentRun | 从失败节点恢复 |
| 幂等键重复 | 请求体一致返回原结果，不一致返回 HTTP 409 + `IDEMPOTENCY_CONFLICT` |
| Runtime 与业务库不一致 | 对账或补偿任务恢复 |
| 用户删除回忆 | 只影响当前用户 |
| 未解锁访问详情 | 拒绝访问 |
| Runtime 核心数据库不可用 | liveness 保持存活，readiness 返回 503，停止接收新 run |
| worker 优雅停机 | 停止认领新 run，当前 run checkpoint 后交接且 attempt 可审计 |
| run 排队或等待审批 | 不消耗活跃执行预算，独立 TTL 生效 |
| purge 与模型迟到返回并发 | privacy version 失配，私密结果不落库且 run 不可恢复 |
| AgentPackage 安全撤销 | 新任务和恢复被拒绝，运行中任务安全取消 |
| callback dead letter 重放 | 复用 event_id/event_seq/status_version，不制造新状态版本 |
| run_dispatch dead letter | 重放同一事件；超过上限后 run 条件更新为 failed 并产生 callback |
| 日记包含工具命令或“忽略上文” | 作为 trusted=false 内容处理，未知工具/控制字段不执行 |
| connector 或服务账号运行中撤销 | authorization version 变化，后续动作被拒绝 |

## 六、风险优先级

| 风险 | 优先级 | 处理 |
|---|---|---|
| 数据串段 | P0 | 唯一约束和快照边界测试 |
| 隐私泄露 | P0 | 业务工具过滤、脱敏、日志清理 |
| Agent 越权调用工具 | P0 | tool allowlist、签名、权限校验 |
| Agent 无限循环或过度执行 | P0 | Planner stop condition、PolicyEngine 硬限制 |
| callback 乱序导致状态倒退 | P0 | event_seq/status_version 版本比对 |
| 跨库状态不一致 | P0 | pending_start、幂等补偿、对账任务 |
| 幂等冲突未处理 | P0 | Idempotency-Key + request hash + TTL |
| callback 被伪造 | P0 | callback HMAC-SHA256 签名和业务侧验签 |
| 情绪伤害 | P0 | 回忆录业务 guardrails |
| Runtime 无法恢复 | P1 | checkpoint、节点级重试 |
| AI 不稳定 | P1 | 模板兜底和结构化 parser |
| 模型策略配置发散 | P1 | 固定 model_policy.yaml 最小映射 |
| 媒体成本高 | P1 | 视频默认二期后，按需生成 |
| 观测不足 | P1 | 第一版保留 trace、step、token、cost |
| 前端性能 | P1 | 低配模式和媒体懒加载 |
| 分享外泄 | P1 | 默认脱敏、过期、撤销 |
| 第一版只有 MemoirAgent 验证抽象不足 | P2 | 二期接入 CustomerSupportAgent 前预留破坏性重构窗口 |
| worker 重复执行或旧结果回写 | P0 | lease/heartbeat + 数据库 fencing token + 稳定幂等键 |
| 契约随实现漂移 | P0 | 独立 Runtime Contract、schema version、package digest、兼容性测试 |
| Scene/Action 分步写入产生半成品 | P0 | MemoryPlaybackDocument + 单事务发布 + published_revision 指针 |
| 旧 run 在删除或重新生成后迟到写回 | P0 | generation_epoch + active_run_id 业务侧 fencing |
| Runtime、callback、媒体 worker 状态双写 | P0 | content/enhancement/run 状态分离，generation_status 只做派生 |
| Runtime 早于业务 run 映射开始执行 | P0 | start_mode=held，绑定 active_run_id 后显式 start |
| 旧媒体任务污染新作品状态 | P0 | MediaTask 绑定 document_id/epoch，只聚合当前 published document |
| 小程序请求层无流式适配 | P1 | HTTP 轮询为 MVP 基线，SSE 按平台能力启用并可回退 |
| 多业务接入形成无界队列 | P0 | AdmissionController、并发配额、429/Retry-After、provider 共享限流 |
| AgentPackage 形成任意代码执行入口 | P0 | 仅加载 CI 构建并由管理员注册的受信任 package，首期禁止在线上传 workflow |
| Tool/Callback/Provider 形成 SSRF | P0 | connector/target 注册表、出站 allowlist、DNS/IP 与重定向逐跳校验 |
| Runtime 重复保存亲密关系正文 | P0 | Checkpoint 加密和 TTL、Artifact 仅保留摘要/hash/业务引用、删除联动 |
| dispatch 与业务状态混为一张状态机 | P0 | dispatch_state 只属于 AgentRun，并与 status 分列、分转换表维护 |
| 重试成本和副作用无法归因 | P0 | Step/ToolCall/ModelUsage 记录 execution/step/tool attempt，逻辑幂等键保持稳定 |
| 临时磁盘或进程内状态承载长任务 | P0 | API/worker 共享权威数据库和 outbox；serverless 仅承载无状态短请求 |
| 排队或人工等待误耗执行预算 | P1 | 活跃执行、held、queued、waiting_human 和最终 deadline 使用独立时钟 |
| purge 后迟到结果复活私密数据 | P0 | privacy tombstone/version、所有私密 payload 条件写、purge 后禁止 retry/resume |
| 风险 AgentPackage 继续执行 | P0 | active/deprecated/revoked 生命周期，worker 每个 attempt 重新校验 |
| callback 无限重试或重放制造新事件 | P1 | 持久 outbox、dead letter、原事件身份重放和主动查询兜底 |
| dispatch dead letter 让 run 永久排队 | P0 | 按事件类型对账；同事件重放失败后置为 DISPATCH_FAILED |
| 日记/RAG/工具结果发生间接提示注入 | P0 | trust label、数据槽隔离、静态 allowlist、语义校验和业务二次鉴权 |
| 运行中权限撤销不生效 | P0 | AgentRun authorization_version、动作前复核和 AUTHORIZATION_REVOKED 终止 |

## 七、第一版最小闭环

1. Runtime 建立 `AgentPackage`、`AgentRun`、`AgentPlan`、`AgentStep`、`AgentToolCall`、`AgentEvaluation`、`AgentCheckpoint`。
2. Runtime 支持 LangGraph workflow。
3. Runtime 支持静态 Planner、轻量 Evaluator 和 PolicyEngine。
4. Runtime 支持 LiteLLM / Provider Adapter ModelGateway 和 LangChain prompt/parser。
5. 情侣日记后端完成 archive/snapshot/tool API。
6. `MemoirAgent` 生成 3 到 8 张卡片。
7. 后端保存 scenes/actions。
8. 前端完成列表和播放器。
9. 跑通失败兜底、重试、删除、密码解锁。
10. 跑通 worker 失联接管、取消传播、旧 worker fencing 和契约兼容测试。
11. 跑通 baseline、原子发布、删除/重生成竞态和媒体状态独立更新。
12. 跑通健康检查、能力发现、共享持久化、优雅停机和 attempt 级审计。
13. 跑通 privacy purge 写屏障、package 安全撤销和 outbox dead letter 恢复。
14. 跑通不可信内容隔离、dispatch dead letter 终止和运行中授权撤销。
